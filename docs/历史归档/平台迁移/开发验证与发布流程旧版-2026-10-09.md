## 1. 四条执行路径

| 路径 | 用途 | 是否访问真实 AgentBridge/OA | 是否重启服务 |
|---|---|---:|---:|
| 定向验证 | 修改后快速反馈 | 否 | 否 |
| 全量验证 | 提交或发布前回归 | 否 | 否 |
| MCP 冒烟 | 验证中心服务、TLS、身份和 OA 会话 | 是 | 否 |
| wheel 部署 | 发布中心 Python 包并自动冒烟 | 是 | AgentBridge；OpenClaw 默认不重启 |

这四条路径不能相互替代。单元测试证明代码契约，MCP 冒烟证明当前部署可用，wheel 部署证明发布链路可重复。

## 2. 持久测试环境

统一入口为 `scripts/Invoke-AgentBridgeValidation.ps1`。默认环境位于：

```text
%LOCALAPPDATA%\AgentBridge\test-venv-py312
```

脚本根据 Python 版本和 `pyproject.toml` SHA-256 生成依赖指纹。指纹不变时直接复用环境；指纹变化时才重新安装项目、pytest、pytest-xdist 和 wheel 构建后端。可以通过 `AGENTBRIDGE_TEST_PYTHON`、`-BootstrapPython` 或 `-VenvPath` 显式覆盖。

首次初始化需要安装依赖，可能耗时数分钟。不要因为首次慢而删除环境，否则每次都会重新付出同样成本。

## 3. 日常定向验证

Python 改动优先选择直接相关的测试文件：

```powershell
.\scripts\Invoke-AgentBridgeValidation.ps1 `
  -Mode Targeted `
  -PythonTests @('tests/test_auth_challenges.py', 'tests/test_central_service.py')
```

OpenClaw 插件改动：

```powershell
.\scripts\Invoke-AgentBridgeValidation.ps1 -Mode Targeted -OpenClaw
```

只有修改包清单或准备发布插件时才增加打包检查：

```powershell
.\scripts\Invoke-AgentBridgeValidation.ps1 -Mode Targeted -OpenClaw -PackCheck
```

MCP App 改动：

```powershell
.\scripts\Invoke-AgentBridgeValidation.ps1 -Mode Targeted -McpApp
```

`Targeted` 至少要求一个测试路径或组件开关，避免看似成功但实际没有执行任何检查。

## 4. 发布前全量验证

```powershell
.\scripts\Invoke-AgentBridgeValidation.ps1 -Mode Full
```

全量模式执行：

- 浏览器测试运行时准备、公开内容检查、当前代码事实核对；
- Python 全量 pytest，默认 4 个 worker，按测试作用域分发；
- `compileall`；
- `pip check`；
- Workspace Node 测试，含查询分组；
- OpenClaw 插件测试；
- OpenClaw `npm pack --dry-run` 包清单检查。

- 固定提交的 wheel 构建、包内资源与源码核对，以及空环境中从源码目录外加载两个 OA 页面脚本。

Full 要求跟踪文件已提交且干净；含无关本地修改时使用隔离提交目录，不能删除用户文件。
定向测试仍支持未提交的开发改动。Full 不允许 `-SkipOpenClaw`，部分检查使用 Targeted。
开始验证即将候选回执标为 running，所有检查成功后才写 succeeded。回执绑定提交、
实际跟踪文件内容、Python 依赖版本、Node/npm 版本、已安装 Node 锁清单、制品哈希和测试范围。
正式部署必须校验这份回执，并复用已验证的同一个 wheel。

首次大规模重构第一批将原生 Full 与 CI 共用的验证计划集中到 `scripts/validation_plan.py`；旧 PowerShell 委托入口保留历史兼容。
阶段清单、测试分类和实际命令只在共享计划中维护；新增 Node 测试未分类会拒绝验证。
每次运行保存独立的阶段证据，包括命令、退出码、报告摘要、用例文件集合和输出摘要。
Python、Workspace Node 和 OpenClaw 测试报告共同参与核验，缺失、失败、陈旧或被修改的证据不能形成成功回执。
旧回执没有完整阶段证据时须重新执行 Full；Targeted 不能升级为 Full。
浏览器专项仍按既有开关执行，平台条件跳过在测试报告中明确记录。
设计、兼容边界和实际验证见[第一批记录](../../首次大规模重构/第一批实施与测试记录-2026-10-04.md)。

Workspace 持久投递的终态与终态事件由同一数据库事务提交。流读取端看到终态后仍须做一次无等待的
剩余事件排空，防止“先读旧事件页、后读新终态”时遗漏最终消息；这不是业务轮询，也不得重新投递请求。

只有存在匹配完整候选的验证回执时才能使用 `-SkipValidation` 复用结果；无回执、输入变化、跳过项或哈希不符都会拒绝。该参数省略重复全量测试，不省略制品校验、治理检查和线上验收。`-ResumeAcceptance` 隐含同样的收据复用：恢复验收不会调用 `begin`，因此不会把已经成功的收据覆盖为 running。

## 5. 真实 MCP 冒烟

会话状态探针：

```powershell
.\scripts\Test-AgentBridgeMcp.ps1 -Check SessionStatus
```

它通过正式内网 HTTPS MCP 调用 `oa_session_status`，不会创建认证卡，也不会执行 OA 业务写入。

发布运行时联合探针：

```powershell
.\scripts\Test-AgentBridgeMcp.ps1 -Check Release
```

它先要求公开 MCP 工具目录包含当前业务工具，以及
`agentbridge_host_task_ensure/observe/recovery_list/list` 四个宿主私有任务协调工具，
再调用 `oa_session_status`。工具目录缺失时以 `MCP_TOOL_CATALOG_INCOMPLETE`
失败，防止“新 wheel 已安装、systemd 仍从旧源码启动”被普通会话探针掩盖。

登录复用探针：

```powershell
.\scripts\Test-AgentBridgeMcp.ps1 -Check LoginReuse
```

它调用 `oa_session_login`。会话有效时应返回 `reused=true`、`hasInteraction=false`；会话已过期时可能创建或复用安全登录卡，但仍不会执行 OA 业务写入。

冒烟脚本直接读取 `%USERPROFILE%\.openclaw\openclaw.json`，并从进程、用户、机器环境或 `%USERPROFILE%\.openclaw\.env` 解析 `${VAR}` 引用，不再为每次探针调用多个 `openclaw config get`。Bearer 只通过子进程标准输入传给本地 Node 客户端，不进入命令行、JSON 摘要或日志；输出仅包含白名单状态字段。

## 6. wheel 一键部署

先看计划，不访问服务器：

```powershell
.\scripts\Deploy-AgentBridge.ps1 -PlanOnly
```

正式执行：

```powershell
.\scripts\Deploy-AgentBridge.ps1
```

目标机首次启用语雀完整 Chromium 交互登录时执行一次：

```powershell
.\scripts\Deploy-AgentBridge.ps1 -InstallSystemDependencies
```

它会额外安装 `xvfb`、`x11vnc`、`novnc`、`websockify` 和 `xauth`。正式运行
仍只有一个 `agentbridge.service`：语雀登录挑战按需创建独立 Xvfb、Chromium、
回环 RFB/CDP 和临时路由，完成或超时后清理。8781 是固定内网 IP 上由内部 CA
保护的 noVNC HTTPS 网关；RFB/CDP 不对内网监听。旧的共享
`agentbridge-xvfb.service` 已退役，部署脚本会停止并删除遗留 unit。

脚本会：

1. 默认拒绝存在已跟踪未提交修改的工作区；
2. 运行发布验证；
3. 复核完整候选回执，复用固定提交隔离构建并通过空环境验证的 wheel；
4. 单次 SCP 上传；
5. 单次 SSH 完成版本化留存、安装、`compileall`、`pip check`，安装受版本控制的 AgentBridge systemd unit，并清理已退役的共享 Xvfb unit；
6. 校验服务工作目录、Python `-P` 安全路径和 `bscli` 的 site-packages 来源后重启；
7. 通过正式 HTTPS MCP 自动执行 `Release` 工具目录与会话联合冒烟；
   服务重启后若首次探针抢在 Uvicorn 就绪前失败，会以 5 秒间隔最多重试 6 次，仍失败才终止发布。

需要同时验证登录复用时：

```powershell
.\scripts\Deploy-AgentBridge.ps1 -IncludeLoginReuseSmoke
```

已完成同一候选的全量验证时：

```powershell
.\scripts\Deploy-AgentBridge.ps1 `
  -SkipValidation `
  -IncludeLoginReuseSmoke
```

`-AllowDirty` 保留参数兼容，但不能再绕过制品校验；真实部署遇到跟踪文件修改会拒绝。需先在隔离目录提交并验证候选。

只有 OpenClaw 插件或其持久运行配置变化时才使用：

```powershell
.\scripts\Deploy-AgentBridge.ps1 -RestartOpenClaw
```

Windows 托管 Gateway 重启实测可能超过两分钟。重启统一使用可见前台生命周期控制器，完成后
桌面必须保留标题为 `AgentBridge OpenClaw Gateway` 的 Windows Terminal。中央 Python 包、
systemd 配置或 OA 适配代码变化，不应顺带重启 Gateway。生命周期控制器在整个启动期间维护带
心跳的共享租约；Guard 识别租约后不再依据 180 秒旧快照重复重启。发布进程异常退出时，租约因
所有者消失或 45 秒未续期自动失效，不会阻止后续自愈。Guard 的恢复调用使用 `StartOnly`，在
生命周期互斥锁后重新检查一次健康状态，覆盖租约写入前的极窄竞态窗口。
刷新 Guard 计划任务时，安装器还会清理计划任务停止后遗留的旧 Guard 子进程，并以新格式状态心跳
作为安装完成条件，不能只依据 `Start-ScheduledTask` 已返回。
生命周期控制器首次看到 `/readyz` 成功后，运行时验收还会在 45 秒稳定窗口内重试健康端点并等待
当前 Gateway 的插件注册证据，覆盖插件初始化期间端点短暂忙碌的情况；超过窗口仍失败关闭，不触发重启。

统一发布验收中的 OpenClaw 控制面检查由受控子进程执行，默认最多等待 180 秒。
控制面无响应时验收会明确超时，不再无限挂住，也不会自动重启 Gateway。若本次发布完全
不涉及 OpenClaw，且完整插件测试已经通过，可以显式使用：

```powershell
.\scripts\Publish-AgentBridge.ps1 -SkipOpenClawAcceptance
```

该选项不能作为日常默认值；跳过的实时 OpenClaw 验收必须在发布结果中说明，并在控制面
恢复后补测。

当 `%USERPROFILE%\.openclaw\.env`、`openclaw.json` 中 MCP Header 引用或其他
Gateway 进程环境发生变化时，必须完整重启 Gateway；`openclaw mcp reload` 只清理
MCP 工具运行时缓存，不能替换长驻进程已经读取的环境变量。Bearer Token 的安全轮换
顺序固定为：

1. 服务端签发新 Token，但暂不撤销旧 Token；
2. 原子更新本机 `.openclaw\.env`，用 `Test-AgentBridgeMcp.ps1 -Check Release`
   直接验证新 Token；
3. 只执行一次 `.\scripts\Restart-AgentBridgeOpenClawGateway.ps1`，等待可见前台重启完成；
4. 通过 Gateway `/readyz`、本次插件注册日志和真实宿主 MCP 调用确认新 Token 已生效；
5. 最后撤销旧 Token，再执行一次 Release 冒烟和活动 Token 核账。

不得把独立冒烟成功等同于 Gateway 已换用新凭据；前者直接读取当前 `.env`，后者
可能仍持有启动时的旧环境值。

## 7. 安全边界

- 自动冒烟只读取 MCP 工具目录并调用 `oa_session_status`；可选登录复用只调用
  `oa_session_login`。
- 脚本不包含待办审批、草稿保存、会议预订或任何 OA 业务写工具。
- 真实 OA 写操作仍必须走 prepare、可信字段卡、执行授权、commit、回读验证，并由用户针对具体事项确认。
- OpenClaw Bearer、Cookie、密码、卡片 URL 和业务字段不得写入仓库、命令行或普通日志。
- `output/release` 是本地临时构建目录并被 Git 忽略；Linux 版本化 wheel 位于 `/home/guomao/agentbridge/releases/<release-id>/`。

## 9. 推荐节奏

1. 修改代码后跑最小相关定向验证。
2. 涉及远程发布或工具契约时补一次 `Release`；纯会话逻辑可用 `SessionStatus`，登录逻辑变化时再补 `LoginReuse`。
3. 准备提交时跑全量验证。
4. 先 `-PlanOnly`，再执行 wheel 部署。
5. 发布入口按已验证的插件/配置指纹决定是否重启 Gateway；中央代码、Workspace、文档和测试变化复用现有进程。必要重启只执行一次并等待完全收敛；宿主维护可用 `-ForceRestartOpenClaw`。首次缺少基线须通过一次受控启动建立证据，详见[发布操作手册](../../部署运维/发布操作手册.md)。
6. 部署成功后以自动 MCP 冒烟结果为准，不再手工重复同一批检查。

## 10. 慢启动与发布恢复

启动包装器、部署入口及 guard 的默认 Gateway 启动预算统一为 600 秒。此时间是进程启动
保护上限，不是期望每次等待十分钟；就绪后立即结束。包装器每 30 秒记录阶段、耗时、进程数
与监听数，区分进程尚未出现、尚未监听和就绪检查未通过，不输出 Token 或业务内容。

`Restart-AgentBridgeOpenClawGateway.ps1 -StartOnly` 遇到唯一、前台可见且仍在预算内的启动
进程时接续等待，不杀掉重建；截止时间按原进程创建时间计算，不因接管而无限延长。
普通重启仍替换旧实例，重复进程、错误监听归属和失效启动继续走受控恢复。

如果服务器已完成同一提交的部署，但后续宿主检查或推送被中断，使用：

```powershell
.\scripts\Publish-AgentBridge.ps1 -ResumeAcceptance
```

恢复入口自动要求并核验该提交已完成本地验证。它仍要求干净工作树、既定远端和
分支；重新核对服务器 Release 与当前提交、MCP/页面健康、备份和 OpenClaw 验收，然后推送并
核对远端哈希。版本不一致停止，不重新安装，不重启 Gateway，不重放任何业务任务。
不能与 `-RestartOpenClaw` 或 `-IncludeLoginReuseSmoke` 混用。代码改变后必须按新提交正常发布。
