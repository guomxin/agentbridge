# 本机宿主自愈与可靠性演练

> 历史快照：保存平台收敛前的流程，不作为当前操作入口。现行流程见[原生维护](../../部署运维/苹果系统原生维护.md)。

> 适用环境：Windows OpenClaw 工作站与 `10.10.50.213` 中央 AgentBridge
>
> 更新日期：2026-09-02
>
> 安全边界：本手册中的检查、故障注入、恢复演练和影子观察均不得调用业务列表或执行业务写入。

## 1. 目标

本可靠性包同时收口三件事：

1. **本机宿主自愈**：Windows 用户登录后自动启动 OpenClaw Gateway 和 Workspace 反向隧道；
   进程异常退出后由任务计划自动拉起，不再因 72 小时执行上限被停止，也不产生重复实例。
2. **备份恢复演练**：选取服务器最新一致性备份，复制到独立目录，只读打开并证明写入被拒绝；
   不替换线上数据库、不启动第二套 AgentBridge、不访问任何下游业务系统。
3. **影子观察**：中央治理线程每小时采集一次运行摘要、24 小时 SLO 和事件数量，按 UTC 日期形成
   日汇总，七天后自动结束；不自动恢复业务写入，也不向业务用户发送告警。

三者的职责边界如下：

```text
Windows 任务计划              中央备份目录                 中央运行治理库
  OpenClaw Gateway              最新 manifest + db          Observation
  Workspace SSH 隧道       ->   隔离只读恢复副本       ->   小时快照 / 日汇总
       |                              |                         |
       +-- 保证宿主能回来              +-- 证明备份能读且不可写   +-- 观察是否稳定
```

## 2. 本机自愈配置

安装或刷新 Gateway 任务：

```powershell
.\scripts\Install-AgentBridgeOpenClawSelfHeal.ps1
```

安装或刷新 Workspace 隧道任务：

```powershell
.\scripts\Install-AgentBridgeWorkspaceTunnelServer.ps1
.\scripts\Install-AgentBridgeWorkspaceTunnel.ps1
```

第一条命令在 213 上安装并验证 SSH 服务端空闲探测，第二条命令安装本机任务。服务端配置用于
回收盒盖断网后没有正常关闭的旧 `sshd` 和反向监听；本机脚本用于识别唤醒、切网并重连。

安装器保留 OpenClaw 原始 Gateway 启动命令到
`%LOCALAPPDATA%\AgentBridge\openclaw-gateway-runtime.cmd`，并把旧任务入口改成幂等兼容垫片。
日常启动、发布重启和故障自愈统一调用
`scripts/Restart-AgentBridgeOpenClawGateway.ps1`。控制器定向停止旧 Gateway、等待端口释放、
清理仅属于失效 PID 的锁文件，再在标题为 `AgentBridge OpenClaw Gateway` 的 Windows Terminal
前台窗口中启动。关闭这个窗口等同于停止 Gateway，守护器会重新创建一个可见窗口。

后台计划任务 `AgentBridge OpenClaw Guard` 每 15 秒检查 Gateway、可见前台父窗口和 Workspace
隧道任务、包装器进程及状态心跳。它不会把“任务仍是 Running”或“端口仍监听”单独当成健康；
隧道心跳超过 60 秒或包装器消失时，只精确恢复隧道，不触碰正常 Gateway。Guard 通过 `wscript.exe` 无控制台
包装器运行，不占用命令窗口；Gateway 退出后的旧 Windows Terminal 标签页也会正常关闭，避免
多次重启后累积空白或失效窗口。守护状态写入
`%LOCALAPPDATA%\AgentBridge\openclaw-guard-status.json`，不保存业务数据。
重新安装 Guard 时，安装器会精确停止旧计划任务及其可能遗留的 Guard PowerShell 子进程，删除旧状态，
并等到新实例写出带生命周期租约字段的心跳后才返回成功，避免“任务显示安装成功、实际仍是旧 Guard”。

生命周期控制器与 Guard 通过
`%LOCALAPPDATA%\AgentBridge\openclaw-lifecycle-operation.json` 共享启动租约。控制器取得生命周期
互斥锁后写入操作标识、阶段、所有者进程、心跳和到期时间，并在停止旧进程、创建前台窗口和等待
`/readyz` 期间持续续租。Guard 看到有效租约时把状态记为 `lifecycle_in_progress`，只观察 Gateway，
不清理进程、不调用第二次启动。控制器正常结束后把租约标为 `completed`；进程异常退出或心跳到期
时租约自动失效，Guard 下一轮恢复。启动总时长不会单独触发接管，因此发布脚本等待较慢的模型或
插件初始化时，不会再被 180 秒旧快照误杀。Guard 发起的恢复统一采用 `StartOnly`：即使它恰好在
租约写入前取得了旧快照，也会在等待生命周期互斥锁后重新检查 Gateway；前一个操作已经启动成功时
只返回 `already_running`，不会再无条件重启一次。
生命周期结束后的运行时验收另有 45 秒稳定窗口：允许 `/readyz` 在插件初始化期间短暂超时，并等待
当前 Gateway 的插件注册日志；稳定窗口只做本地只读复核，不会重启 Gateway 或调用业务工具。

原生任务配置采用：

- 当前 Windows 用户登录时启动；
- `StartWhenAvailable`，错过登录触发时尽快补启动；
- 允许使用电池，不因切换供电终止；
- `ExecutionTimeLimit=PT0S`，不设置运行时长上限；
- 异常退出后每分钟重启，最多 999 次；
- `MultipleInstances=IgnoreNew`，同一任务只保留一个实例；
- 没有有效生命周期租约时，Gateway 冷启动仍有 180 秒本地宽限；有租约时以持续心跳和 45 秒
  租约到期为准，不按进程总年龄重复拉起实例。

本机制只恢复宿主进程和 SSH 连接。它不会重放用户请求，也不会调用 AgentBridge 的业务 commit。
等待用户的卡片、任务和业务结果仍由中央 Task Hub、Interaction 和 Operation 状态决定。

Workspace 隧道启动器还使用独立互斥锁，并识别参数完全匹配的既有 `ssh.exe`。任务更新留下旧 SSH
时，新包装器会等待并接管其生命周期，不会不断重试同一个远端端口；安装器先停止旧任务和精确
包装器，再覆盖任务定义并定向清理旧 SSH，避免旧 PowerShell 脱离任务计划程序。隧道状态在线时
每 15 秒刷新；SSH 错误按尝试追加并分类，不再被下一次重试清空。两者分别记录在
`%LOCALAPPDATA%\AgentBridge` 的状态文件和日志中。

本机轮询间隔超过 60 秒时按盒盖唤醒处理，即使网卡和 IP 看起来未变，也会主动替换睡眠前 SSH。
213 同时对当前隧道账户使用 `ClientAliveInterval 5` 和 `ClientAliveCountMax 2`，因此本机没有机会
发送关闭报文时，服务器也会在短时间内释放旧 `127.0.0.1:18789`。两层机制共同覆盖“回家睡眠、
回公司唤醒”和 VPN 恢复场景，不修改防火墙、代理或 Gateway 监听地址。

兼容任务、当前用户守护任务和人工操作使用同一生命周期控制器，不需要修改防火墙、代理、
Gateway 监听或管理员 ACL。不要再直接执行 `openclaw gateway restart`；原生命令可能在外层任务
结束后遗留 Node 子进程或失效锁，也不能保证用户看得见前台窗口。

人工重启统一使用：

```powershell
.\scripts\Restart-AgentBridgeOpenClawGateway.ps1
```

## 3. 本机故障注入验收

只检查当前状态：

```powershell
.\scripts\Test-AgentBridgeLocalHostRecovery.ps1
```

执行一次重启等价故障注入：

```powershell
.\scripts\Test-AgentBridgeLocalHostRecovery.ps1 `
  -ExerciseLifecycleLease `
  -ExerciseFailureRecovery `
  -ExerciseTunnelRestart `
  -TimeoutSeconds 300
```

生命周期租约注入会把启动时间模拟为十分钟前、保持当前心跳，等待 Guard 明确进入
`lifecycle_in_progress`，并确认 Gateway PID 未变化；它不终止 Gateway。进程故障注入会终止当前
Gateway 监听进程一次，等待任务计划生成新 PID；隧道则执行一次受控停止和启动。
验收必须同时满足：

- Gateway 和隧道任务最终均为 `Running`；
- `18789` 只有一个监听进程；
- `/readyz` 正常；
- Gateway 进程与 `18789` 监听一一对应；
- Gateway 位于可见 Windows Terminal 前台窗口；
- 模拟慢启动期间 Guard 识别有效租约且不替换 Gateway；
- `agentbridge-interactions` 的当前启动日志版本与插件清单一致；
- 报告中的 `businessCalls`、`businessListReads` 和 `businessWrites` 均为 `0`。

Gateway 恢复通常需要一至三分钟，检查脚本使用有界等待，不应同时再开第二个 Gateway 诊断实例。

## 4. 备份恢复演练

从 Windows 执行：

```powershell
.\scripts\Test-AgentBridgeBackupRestore.ps1
```

脚本通过固定 SSH 主机密钥连接服务器，选择
`/home/guomao/agentbridge/backups` 中最新清单，在
`/home/guomao/agentbridge/data/restore-drills/restore-<时间>-<随机标识>` 创建独立副本。

演练依次验证：

1. 原备份清单、SHA-256、SQLite `quick_check`、必要表和用户关联隔离；
2. 恢复副本与源备份哈希一致；
3. 恢复副本能以 SQLite `mode=ro` 和 `query_only` 打开；
4. 对恢复副本执行建表探针必须被 SQLite 拒绝；
5. 恢复目录生成 `restore-report.json`，并明确记录三类业务计数均为 0。

演练不会替换 `/home/guomao/agentbridge/data/agentbridge.db`，不会启动第二个服务，也不会验证下游
Cookie 或 Token 是否仍被目标系统接受。异机灾备、会话密钥迁移、RTO/RPO 和正式切换仍属于后续
生产化工作。

## 5. 七天影子观察

在服务器运行环境中启动：

```bash
sudo -u agentbridge env \
  HOME=/home/guomao/agentbridge \
  AGENTBRIDGE_RELEASE_ID=$(cat /home/guomao/agentbridge/config/release.env | sed -n 's/^AGENTBRIDGE_RELEASE_ID=//p') \
  /home/guomao/agentbridge/venv/bin/python -P -m bscli.cli.main \
  --home /home/guomao/agentbridge/data diagnostics observation-start \
  --name "运行治理二期七天影子观察" --hours 168 --created-by operator
```

查询状态并可立即补采一轮：

```bash
sudo -u agentbridge /home/guomao/agentbridge/venv/bin/python -P \
  -m bscli.cli.main --home /home/guomao/agentbridge/data \
  diagnostics observation-status --state active --capture
```

行为约束：

- 同名活动观察重复启动时返回原批次，不创建重复观察；
- 中央治理线程每分钟运行，但同一观察默认每小时最多持久化一个快照；
- 达到结束时间时再采最后一轮并自动变为 `completed`；
- 状态输出包含逐小时快照和按 UTC 日期聚合的 `dailySummaries`；
- 管理控制台“事件治理”页面展示活动观察、快照数、计划结束时间和最近采样时间；
- 影子观察只读取中央 SQLite 运行账本，不调用 OA、泰华、语雀或照明系统；
- 不根据 SLO 自动暂停能力，不自动重投业务操作，不处理 `RESULT_UNKNOWN`。

## 6. 重启后的检查顺序

Windows 工作站重启或重新登录后，无需操作中央 AgentBridge。等待约三分钟，然后：

1. 确认桌面存在标题为 `AgentBridge OpenClaw Gateway` 的窗口；
2. 运行 `Test-AgentBridgeLocalHostRecovery.ps1`；
3. 打开 Workspace，确认可以新建一条普通对话；
4. 管理端查看影子观察最近采样是否继续更新；
5. 如果 Workspace 能看历史但不能发起任务，先查隧道，再查 Gateway `/readyz`；
6. 不通过重复发送业务写请求来测试宿主恢复。

## 7. 未覆盖边界

- Windows 尚不是无人值守服务账号，任务依赖当前用户登录；
- 本机硬盘损坏、Windows 无法启动时，OpenClaw 宿主仍不可用；
- 当前中央 AgentBridge 为单机 systemd 部署，没有热备节点；
- 隔离恢复演练证明备份可读，不等同于异机完整业务恢复；
- 正式告警通知、生产 SLO、异机灾备和自动故障转移仍待建设。
