# 工作台同步第二批公共层定向验证（2026-11-27）

## 范围与约束

本记录对应[四批实施方案](../后续规划/工作台与电报同步分批实施方案-2026-11-27.md)的第二批公共层子项。第一批解决 OA 查询双端闭环；本子项核对通用文字分片恢复、老卡只读状态、诊断可观测及长文本边界，不代表第二批整体完成。

- 起点：`f69552cac0c5258d87dee86ef6624d4f35707dfe`；独立分支 `codex/workspace-sync-batch2-common`，不修改第一批主工作树。
- 用户问题：Workspace 与 Telegram 的同步语义和恢复能力不一致，需要在首批可靠出站基础上补齐公共能力。
- 待验证假设：分片未知回执恢复可能阻塞后续消息；旧卡状态需要始终依权威任务/操作显示；同步漏入队、未发送及回执未知需要区分；超过 50,000 字符的公开答复应完整、有界交付。
- 预期行为：逐片保存确定的交付回执；已发送或结果未知的分片不自动重发；迟到的同次有效回执仅补账并恢复尚未尝试的后续分片；旧卡不可触发过期或已消费动作；诊断不包含正文或可信链接；达到上限时行为明确且不静默截断。
- 涉及模块：公共 Workspace 文字/查询投递账本、结果卡只读状态、相应诊断与定向测试；不编辑 OpenClaw 入口或 NanoBot/Pi 适配器，不重构模型上下文。
- 安全边界：保留原提问、宿主、用户及配对固定关联；发送前复核；撤配后只允许原次回执补账；未知结果不重放；所有业务写操作仍须 `prepare -> authorize -> commit -> verify`；不创建真实任务，不访问真实 OA/TG 或生产配置。
- 验收场景：中间分片确定拒绝/未知/迟到确认、重启后恢复、错误或重复回执、来源变更/撤配；49,999/50,000/50,001 字符及总上限的中文/emoji/Markdown；旧卡刷新、终态/过期和跨用户拒绝；诊断区分未入队、待发送、平台回执与中央账本确认。
