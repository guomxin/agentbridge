用户已授权连续完成四批、每批 Chrome 扩展与 Telegram 桌面自动验收、本任务三宿主必要维护和固定候选渠道交接，以及通过正式门禁后的发布与最终部署。相同范围不逐批重复请求许可。每次维护仍须核对实际宿主、原配置、在途更新、唯一消费者、固定候选和恢复材料；用户授权不代替这些检查。配对挑战仍需账号本人证明；真实提交、审批、撤销等仍需对应业务事项授权及 `prepare → authorize → commit → verify`，测试或部署授权不能代替业务授权。

用户进一步明确本轮真实账号范围：**只有第一账号使用真实 Telegram，第二账号仅使用 Workspace**。文中“另一账号／第二账号隔离”均指在 Workspace 选择同一宿主后看不到第一账号的问题、答复、卡、附件或确认入口；没有第二个真实 Telegram 客户端。Pi 的第二 sender 拒绝测试使用注入更新，不能写成第二账号真实 TG 验收。正式资格中的两个网页主体与一个真实私聊分别记证。

只向同一主体、同一实例、当前获准的对应端点交付，不跨三个 Bot 广播。保留材料期限、可信内容隔离、权威业务核验、未知不重放、Pi 首账号私聊开放范围及技能试用隔离。生产只读验收不选办待办、不 prepare、不提交；明确刷新产生的新读取与自动补投分开计数。故障注入、撤权和进程崩溃验证使用隔离环境。密码、Token、Cookie、字段/授权材料及短期可信链接不进入本记录、普通历史或模型上下文。
