# 工作台同步第二批 OpenClaw 持久镜像验证

本记录对应独立分支 `codex/openclaw-durable-ingress-s2`，从首批候选 `f69552ca` 建立。开发时仅合入公共文字分段及中央投影回执依赖；没有修改首批冻结工作区、真实 Telegram 收件游标、运行中的 Gateway 或 SDK 安装。

## 范围与预期

原问题包括同文不同 Telegram `message_id` 被短时正文指纹合并，以及公开历史仅排入内存队列，中央应答丢失或宿主退出后不能恢复。

本次修改 OpenClaw 的公开文字镜像、插件启动恢复和独立存储；不执行模型、业务能力或 Telegram 发送。真实平台消息 ID 优先于正文指纹；固定原中央、Bot、账号、私聊和消息 ID，保存原身份凭据命名空间与内容摘要。中央只接受 `projection_v2: true` 对已经登记的原私聊端点补账，不从历史注册或迁移端点。

## 已实现的边界

- 仅使用第三方插件可用的 `runtime.state.resolveStateDir`。插件在自己的私有目录建立 SQLite，文件为 `0600`，目录为 `0700`；完整同步只作用于该库，不修改 SDK 共享库、信任或全局配置。
- 公开原文按 JSON 转义后的 UTF-8 字节预算分块。全部块写入后才发布可投递记录；未完成组装、缺块及摘要不符均不发送。凭据和可信卡地址在落盘前拒绝，中央再次执行权威公开内容检查。
- 每个原身份串行补投镜像。中央已提交但应答未知时，使用原消息键重试。成功必须取得匹配消息键、角色、正文摘要、条目及端点的投影回执；不能把普通成功响应当作持久回执。
- 确认回执后删除本地原文；清理失败不把已确认项变回待投，重启只继续清理。身份或原收件路由变化时不把旧记录投向新身份。
- Unicode 总限按码点计数，50,001 字及 200,000 个 emoji 不截断。超过上限保存明确的同步说明，指向本人 Telegram 原会话，不编造工作台链接。
- 容量满时拒绝新增，不驱逐未确认记录或历史回执。容量处置和确认记录保留策略仍需在正式交付前确定。

## 验证与返工

本次新增 25 项 Node 专项，全部 445 项插件测试及 `pack:check` 通过。文档和中央回执/公共文字边界专项通过现行 `agentbridge-native validate` 入口；最后一轮定向验证完成于 2026-11-27 12:16:11（UTC+8）。`validate --changed` 判定 `full_required`；这些结果是开发证据，正式 Full 留给合并后的固定候选。

新增专项覆盖同文不同 ID、同键异载荷、丢失中央应答、重启、原身份变化、先后顺序、缺失或错配回执、写盘及清理失败、长文、秘密筛除、私有权限、SQLite 独立连接及进程退出后重开。

开发中的真实 SDK 试验发现两个限制，不能把底层工厂试验当作插件资格：SDK 同步状态库单值限 64 KiB；注册代理仅允许内置或官方可信插件调用该状态 API。因此最终产品实现没有使用该受限接口，也没有修改 SDK。早期 SDK 工厂的三进程试验仅证明其存储行为，不能作为最终插件可用性证明。

最终存储与中央服务在隔离 HTTP 回环中验证：两条同文、不同平台消息 ID 的 51,000 码点中文与 emoji，第一次中央提交后故意丢应答；最终恰有两个中央条目和两个回执，原键重试复用原条目，没有业务 operation 或模型 dispatch。此试验调用真实中央服务与最终插件存储，但不经过 MCP HTTP 传输，不是 Telegram 真机证据。

阶段从 2026-11-27 首批真实验收期间并行开展。具体工具输出及起止信息保存在本轮私有执行证据，未写入业务正文、凭据或短期卡链接。

## 尚未闭合的原生入站边界

安装的 OpenClaw 2026.7.1 在原生 Telegram 队列中持久保存 update，但插件的 `message_received` 是观察钩子，默认异步且失败放行。插件回调开始后的本地提交可恢复，并不等于平台确认前一定已调用并完成该回调。`inbound_claim` 只针对插件拥有的会话，其失败可被原生流程记为已处理；`before_dispatch` 也不是通用接纳屏障。

没有找到允许第三方在原生 Telegram spool 完成前注册、失败能保留原事件的稳定 API。不能通过直接读取未完成队列、另起消费者或修改 SDK 私有文件假称解决。切换官方 webhook 模式仍需独占交接、原会话绑定、入口许可及真实失败恢复证据；仅切换传输不会自动补上该观察钩子的失败屏障。本分支因此交付的是可恢复的公开历史镜像，不能宣称端到端原生入站持久接纳或 exactly-once 已实现。

真实 Telegram 双向客户端验收、候选资格、Full、发布与上线验证由主流程执行；本记录不替代这些门禁。
