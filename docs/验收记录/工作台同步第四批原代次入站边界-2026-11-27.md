# 工作台同步第四批原代次入站边界

## 范围与原因

对应[第四批计划](../后续规划/工作台与电报同步分批实施方案-2026-11-27.md#第-4-批独立配对迁移明确接续与总体复核)。根任务已授权在 `d7cf0dfc` 独立配对迁移上补齐 NanoBot/Pi 入站时间与本地代次边界。仅在独立第四批工作树实现，没有操作生产、真实 Telegram 或浏览器。

代码确认 Telegram 的旧 backlog 可在首次读取时落到新配对：第二批普通文字只记录当前绑定，未核对原平台时间。NanoBot 原本地 `credential_ref` 还来自固定 Web 绑定，相同 sender 撤销后重新配对不能改变其本地 digest。中央查询/原件账本虽有配对证明，普通入站、旧 working 回复与历史首次登记仍需明确同一代次。

预期行为：显式配对的当前 Telegram 路由携原配对证明；首次接收必须来自原私聊并携有效平台秒级时间，严格晚于当前配对/个人身份生效整秒。与迁移同一秒的消息不可证明先后，拒绝新模型接纳和首次历史登记。旧继承配对保留原兼容路径；已冻结同代次的原回执可补账，未知请求不重做。

涉及中央配对 endpoint 的只读边界元数据、来源事实及协议门禁、共享接收/历史/媒体 helper、NanoBot TelegramRoutes 与 accept、Pi accept 和专项测试。Pi `execute` 的跨端明确引用逻辑由另一子项维护，双方在独立工作树修改不同片段。

## 必须保留的安全边界

- 不根据客户端当前时间替换 Telegram 原时间，不从 caption/文本猜身份或授权。
- private source 在模型接纳和历史首次登记之前固定原 message、endpoint、配对证明和平台时间；同 message 不可换主体、代次或时间。
- 当前绑定异常不等同于已撤配；不在不确定时预约发送或重做模型请求。
- 撤配后的原件、文字与卡片只可补原回执，不经新配对重放。继承记录不回填虚假的独立代次。
- 新协议缺失、凭据回退、旧宿主与旧令牌都不能重新开启已迁移的授权。

## 验收计划

覆盖迁移前、同一秒、后一秒、未来/缺失/非法时间、错私聊、重复 update、同 message 改时间/载荷、来源回执丢失、同 sender 重新配对、旧 working/终答、原精确 ACK、旧继承路径和实际 Nano/Pi 私有 handler。真实 Chrome/TG、固定候选 Full 与发布由根流程串行组织，隔离测试不得冒充真实业务证据。

## 实现与兼容

中央 endpoint 返回显式代次和接收时间下界；继承路径不生成虚假的独立代次。共享接收器先冻结原私聊、原 message 与平台秒，才允许 caption、历史首次写入或模型接纳。NanoBot 的显式 `credential_ref` 绑定当前配对证明，使重配后的本地摘要同步变化。Pi 复用相同接收校验，保留其独立名单。

显式配对的中央历史首次登记要求原来源证明；私有适配器同时冻结公开角色、原 run、内容摘要及终态。新增 `projection_receipt_only` 只能读取已落回执，完整原凭据与内容一致时在撤配后返回原 entryId 和摘要，正文不重建。新中央行冻结原身份范围，旧行保持空值，原私有记录没有完整来源和 token 摘要时不会补授撤配后的读取权限。

恢复器先以原本地绑定查询上述回执，再决定当前队列能否继续；未知网络结果有界重试补账，不重新发 Telegram、不重新接纳模型。首次接收时间严格晚于有效边界整秒，原来在确认配对的同一秒制造消息的隔离夹具改为后一秒，增加专门的同秒拒收测试，生产判断没有放宽。

本子项只修改反向来源与历史门禁。通用通知、出站媒体及跨端引用的协议门禁由总体集成子项维护。

## 实际归档模型进程补充

第四批 SDK 离线场景在 `df6cd449b65f` 上已完成真实宿主的迁移双端证明，但随后普通消息与明确引用均返回未知，模型端点未被调用。隔离复现确认 NanoBot 的二级模型进程只添加了适配器目录，没有添加主进程已经使用的同档 `agentbridge.whl`；新引用 helper 引入共享公开文本过滤器后，子进程报 `ModuleNotFoundError: agentbridge`。原 SDK Python 有 NanoBot 与 MCP，没有独立安装中央包。

修复只调整二级进程的启动库路径：要求当前发布目录同档 wheel 为安全的普通文件，把它与当前适配器目录一同加入隔离进程，并复核导入来源确实在此 wheel。缺失、符号链接、可被其他身份写入或缺少中央包时拒绝启动，不回退工作区或另一个安装。新增实际隔离子进程测试，并在同一归档 SDK 场景验证全新普通消息和双方向明确引用。当前仍是开发候选，不构成部署证据。
