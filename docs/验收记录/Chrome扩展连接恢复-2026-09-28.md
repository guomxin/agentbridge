# Chrome 扩展连接恢复记录

日期：2026-09-28。Codex 桌面版本：26.924.2738.0。

## 现象与证据

全局浏览器发现连续失败，提示无法加载浏览器请求头策略。重置当前控制会话后仍然失败。桌面日志同期反复出现当前任务没有可用的 ChatGPT 浏览器路由。Chrome Native Messaging 注册项、清单及桥接可执行文件均存在。

上述证据不能证明扩展未安装，也不能将以往所有断连归为同一原因。

## 本次恢复方法

使用已知 Chrome 扩展浏览器身份直接连接，跳过全局应用与浏览器联合发现；从用户标签清单领取原工作台页面，保留原登录。浏览器身份和标签编号来自本次发现，不能硬编码为长期配置。

恢复后成功执行工作台页面读取、刷新、输入、发送及结果读取。“看看我的OA待办”查询完成；“于克磊上周都做了什么”加载日志总结 Skill 1.1.0，卡片显示两份文件。随后完成进展与案例查询。

继续操作时出现一次发送按钮点击超时。通过同一连接读取页面，确认消息未发送且文本仍在输入框；刷新可访问性状态并重新定位按钮后发送成功，没有重置会话或重启应用。单次动作截止与整条连接失效应分别处理，点击失败不能直接推定请求未执行，也不能盲目重复发送。

未重启 Codex 或 Chrome，未清除 Cookie、修改扩展源码、注册表、安全策略或站点权限。未使用 Playwright。

## 结论与后续恢复顺序

本次不需要重启 Codex。全局发现路径失败而直接 Chrome 连接成功，将本次阻塞缩小到发现或路由路径；属于已验证的恢复方法，不代表产品内部缺陷已修复。

后续优先复用已连接的 Chrome。单页失效时先在同一浏览器重新获取对应页面；全局发现报错时不要据此认定 Chrome 不可用。直接连接也失败时，再按官方故障排查检查连接、应用更新与重启；重启不是每次验收的前置步骤。

官方参考：[Chrome 扩展故障排查](https://learn.chatgpt.com/docs/chrome-extension)。
