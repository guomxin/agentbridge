# 工作台同步第四批插件显式引用验证

## 范围与边界

本轮在独立 OpenClaw 工作区实现显式跨端公开引用。已确认旧入口先注入业务规划，再读取最近历史并可能选择任务；该行为不能证明用户引用了哪一条已投递消息。新入口复用中央 `projection_reference`，只接受当前本人配对中可核对的公开投影，唯一目标展示摘要，多项要求指定原消息，失效明确说明。

涉及插件提示入口、原生消息引用元数据和工具执行门禁。Telegram 与 Workspace 的新引用回合不加载业务规划、不创建或续办任务，不从历史获得执行权。原生 Telegram 回执只取正式 SDK 事件字段并核对原私聊路由；不解析正文伪造平台引用。其他渠道原路径保留。

定向覆盖唯一、多项、无权或过期、协议不符、原生引用与伪造正文、跨 Bot/端点拒绝、并行回合及直接代理工具拦截。使用合成素材和实际 SDK 消息映射回环；不操作真实 Telegram polling、用户文件或生产配置。真实 Chrome/TG 验收与最终发布由集成候选串行完成，离线结果不冒充平台验收。

## 实施与验证

开始时间：2026-11-27，基线为第三批文件确认修复提交 `3cbf0ae3`。在独立树实施；与三批候选 Full 并行，不更改该固定输入。


[显式引用解析器](../../integrations/openclaw-agentbridge/lib/cross-endpoint-reference.js) 支持统一继续指令、原消息/任务标识和正式 SDK 的原生回复字段。Telegram/Workspace 的旧宽泛跨端措辞也进入受控解析；无确定来源、畸形标识及超长引用明确拒绝，不回退到历史任务猜测。中央卡摘要的公开 `status` 角色与 user/assistant 一并受控核验。独立配对版本标记仅适用 NanoBot，本插件维持原身份元数据。

[插件](../../integrations/openclaw-agentbridge/lib/plugin.js) 在业务规划之前处理引用，固定系统说明与不可信摘要分离；本轮在网络调用前进入只读状态，SDK 原生工具钩子和[代理工具执行入口](../../integrations/openclaw-agentbridge/lib/proxy-tools.js) 均拒绝业务调用。原 run 与回合共享只读标记；下一条普通请求可独立执行，旧 run 或旧工具对象不能借用新请求解除限制。超时、旧协议响应或中途身份变化不解除限制。

开发定向覆盖见[专项](../../integrations/openclaw-agentbridge/test/cross-endpoint-reference.test.js)和[插件回归](../../integrations/openclaw-agentbridge/test/plugin.test.js)。隔离的正式 SDK 2026.7.1 `hook-runtime` 映射器 → 注册候选插件 → 真实中央解析器回环已通过：两条已确认的同文原问句，原生回执精确选中、多项要求具体选择、未知回执拒绝、两层工具拦截、下一轮独立及旧回合继续受限。共三次只读解析（未知平台回执在本地提前拒绝），零新业务操作、零续办记录、零新业务任务。

## 同端回复范围修正

收口自审发现首次版本会将所有原生 Telegram 回复归为跨端引用，导致普通同端回复被拒绝。入口现限定为明确跨端文字，或本地账本能识别为 Workspace 原发送的回执；普通 Telegram 回复不导入跨端历史，也不施加新的只读限制。已识别但缺少 Bot 证明的旧 Workspace 回执继续明确拒绝；明确跨端文字引用未知消息号不能回退到最近消息。专项与正式 SDK 双向回环补测该差异。
