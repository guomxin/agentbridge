# 系统响应五批实施与性能验收

按[系统响应耗时方案](../后续规划/系统响应耗时分析与分批优化方案-2026-10-16.md)实施。原始生产版本为 `1acae4c34a71`，开发基线为 `c781ddf`；五批完成及固定发布验收前，不将本记录视为生产改进已上线。

## 测量分层

- 历史生产基线来自当前用户近期元数据，包含不同版本和验收活动；用于定位问题，不直接与合成负载计算生产提升比例。
- 自动 HTTP 基准使用固定旧源码和独立候选环境，各场景 30 次，相同材料、下游读取延迟 20 毫秒和 worker 启动延迟 10 毫秒。固定浏览器等待默认不执行；第四批另用实际等待版本对照。
- Chrome 扩展每批独立进入真实 Workspace 和可信办理页。工具调用的墙钟测量包含扩展往返开销，少量页面样本不当作生产 P95。
- 宿主协调器基准运行真实 JavaScript coordinator 与真实 MCP HTTP 传输，只有远端通知、租约和续跑响应为合成边界；与 Python 每 300 毫秒续办的 UI 夹具分开。

所有隔离业务写入仅作用于合成下游。授权消费、提交及权威核验仍走原中央账本。材料变化必须零写入，unknown 只发生一次提交且不重放；确认之后的同一幂等请求不得产生第二次业务写入。
