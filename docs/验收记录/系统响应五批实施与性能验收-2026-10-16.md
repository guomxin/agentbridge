# 系统响应五批实施与性能验收

按[系统响应耗时方案](../后续规划/系统响应耗时分析与分批优化方案-2026-10-16.md)实施。原始生产版本为 `1acae4c34a71`，开发基线为 `c781ddf`；五批完成及固定发布验收前，不将本记录视为生产改进已上线。

## 测量分层

- 历史生产基线来自当前用户近期元数据，包含不同版本和验收活动；用于定位问题，不直接与合成负载计算生产提升比例。
- 自动 HTTP 基准使用固定旧源码和独立候选环境，各场景 30 次，相同材料、下游读取延迟 20 毫秒和 worker 启动延迟 10 毫秒。固定浏览器等待默认不执行；第四批另用实际等待版本对照。
- Chrome 扩展每批独立进入真实 Workspace 和可信办理页。工具调用的墙钟测量包含扩展往返开销，少量页面样本不当作生产 P95。
- 宿主协调器基准运行真实 JavaScript coordinator 与真实 MCP HTTP 传输，只有远端通知、租约和续跑响应为合成边界；与 Python 每 300 毫秒续办的 UI 夹具分开。

所有隔离业务写入仅作用于合成下游。授权消费、提交及权威核验仍走原中央账本。材料变化必须零写入，unknown 只发生一次提交且不重放；确认之后的同一幂等请求不得产生第二次业务写入。

## 第三批：缩短业务编排（待独立验收）

已实现从已完成、覆盖完整的 OA 待办查询卡选择一项或多项，进入对应的单项专门界面或原持久批次。客户端只传原操作 ID、不可猜测目标键及请求键；中央核对原查询所有权、十分钟新鲜度、完整来源、精确事项身份、当前权限、已审查助手内容及固定绑定后，将准备意图与新任务在原数据库同一事务保存。Workspace 仅唤醒原宿主；宿主私有入口仍逐次检查 L3、原端点、原会话和协调租约，再走原真实 prepare。准备不签发决定、不消费授权、不提交业务。未知类型禁止直接进入，必须回到原受治理流程。

单项选择适配全部 14 类 OA 材料准备，多项沿用逐项核对和决定。请求丢回复、双页面重复选择及宿主重启恢复均定位同一持久任务和幂等操作；已有失败或 unknown 只回读，不重新调用。页面保留原请求键的恢复入口，即使查询过期或目标当前不可新选，也由服务端复核旧请求。当前原批次尚未结束时，再建批次继续受原互斥规则约束。

助手目录、权限和依赖均有中央生成的内容版本戳，按身份缓存并合并同轮读取，绑定和执行权限实时核对。任务确认与协调租约改为原子入口，业务返回携带精确任务观察回执，仅回执完整匹配时省去额外观察调用。新增工具依旧宿主私有，生产模型工具覆盖及模型选择保留。

OpenClaw 固定版本 2026.7.1 不能在同一轮加载助手后重新生成模型工具 schema，因此本批采用独立运行的静态范围工具对照；专用 OA 助手可选绑定后的封闭执行检查，通用助手默认关闭，保留原跨系统独立任务和计划恢复。不声称动态 schema 裁剪已上线。真实模型对照采用原生产模型、隔离凭据副本及合成业务系统，比较完整工具面和受限 OA 工具面；质量不足的配置不切换生产。
