## 同条件性能对照

归档基线 `1e3874c` 与当前实现采用同一个最终 harness（SHA256 `f01b9b8daa42c55d20590f271b143dad85310e24229243fa8605e0a78cd59e76`），五场景各 3 次；双方运行期间源码未变化，comparison 等价性检查通过。数据保存于 `benchmark-before-final-harness.json` / `benchmark-after-final-harness.json`。

| 场景 | 基线总耗时中位 | 本轮总耗时中位 |
| --- | ---: | ---: |
| 待办查询 | 102.4 ms | 117.7 ms |
| 单项办理 | 881.3 ms | 927.9 ms |
| 混合批次 | 1870.1 ms | 1982.4 ms |
| 材料变化 | 421.6 ms | 451.4 ms |
| 结果未知 | 672.7 ms | 716.3 ms |

15/15 样本均无错误、下游调用次数一致；双方账本均为 12 次明确决定、12 个 consumed 授权、9 次成功及 3 次 unknown、12 次合成写入，协调错误为零。实际受控 sleep 等待也同向增加，不能把小样本归因为界面本身变慢，也不能宣称全链路提速。快捷入口绕过模型理解是结构变化；生产端到端耗时须另以真实查询记录为准。未知停止及材料变化在写入前拦截的边界没有退化。
