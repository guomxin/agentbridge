## 一、提交前业务加载竞态（优先修复）

生产相同路径 `resolve_workflow_detail → _validate_target` 已完成时，`document.readyState=complete`，但 OA `_hasExecuteContentLoad=false`；约 1 秒后才变成 true。两次只读采样均复现。现网原提交函数 `submitClickFunc` 第一段在该标志为 false 时直接 return。

当前 `seeyon_pending_execution.py` 先调用 `enter_commit_boundary()` 消耗授权，再通过 `setTimeout(..., 0)` 调用提交入口，仅以 `scheduled=true` 作为排队确认，没有等待 OA 业务正文加载完成。因此存在“已消耗授权，但原函数静默返回，随后空等 60 秒并停为 unknown”的真实代码路径。

将现网原样提交函数放入本地 Node VM，DOM、密级检查和最终提交分支均为 stub：bodyLoaded=false 时提交分支调用 0 次，true 时 1 次。该隔离复现没有向 OA 发起写入。

这是已确认的代码缺陷和现网前置状态，极可能解释本次异常；原尝试没有记录当时瞬时加载标志、选中的函数和办理 RPC 方法，不能把该推断写成已百分之百还原历史根因。

修复要求：在消耗授权前，有界等待 OA 自己的业务加载条件，再核对原事项、节点及材料；未就绪时明确“尚未提交”。必须继续调用原始完整提交入口，保留正文、密级、必填等 OA 自身检查，不能直接绕过到下层提交函数。补充明确的入口执行/请求证据，不能把 scheduled 当作业务请求已经发出。

代码：`agentbridge/adapters/seeyon_pending_execution.py`、`agentbridge/adapters/seeyon_pending_verification.py`。

## 四、重新查询会重新开放已有办理事项

隔离 fixture 对同一精确效能数据 affair 做两次独立查询：第一次已排队准备，第二次仍为 preparation=null、enabled=true；再次选择产生另一个不同的办理任务。9 项检查通过，决定、授权、合成写入均为 0，没有执行两次 prepare。

根因：`actionable_results.py` 按 sourceTaskId 和查询 operationId 查找已有准备，targetKey 也包含查询操作，因而只能在原来源内排重。它不能在新查询中可靠呈现已有未决或 unknown 办理。该缺陷不代表本次用户已经重复提交，真实记录仍只有一次。

修复要求：按同一用户、同一 OA 主体、精确事项及业务能力关联已有未决/未知任务，保留原请求与授权边界；unknown 只能核验，禁止新建同一事项的第二次提交路径。不能按标题合并，也不能跨主体或错误归并不同业务意图。

复现脚本：`output/efficiency-audit-20261023/reproduce_cross_query_preparation.py`；证据：同目录 `cross-query-preparation-evidence.json`。

## 五、单次确认逻辑与旧两步文案冲突

后台实际只记录一次最终决定，并在同一事务完成字段和批准授权，未发现要求用户再点第二次授权的实现。但真实完成记录仍显示“字段核对已完成……请查看后续授权卡和任务进度”，并在另一子卡显示“已授权”。主动卡的旧 schema notice 也仍写“提交意见后还需在独立授权卡中核对”。

修复要求：按可信 businessView 和持久决定显示“一次确认已记录，业务结果核验中”等一致状态，收敛字段/授权内部步骤。保留历史原合同，不重写 immutable schema；不把授权完成显示成业务完成。

代码：`agentbridge/workspace/static/workspace_results.mjs`、`agentbridge/workspace/static/workspace_cards.mjs`、`agentbridge/adapters/seeyon_pending_actions.py`、`agentbridge/core/central_service.py`。

次要问题：附件区仍无条件提示“附件内容未在本页读取”，可能与下方已经打开的材料预览矛盾；多项任务标题均为“核对并办理OA待办”，不利于区分具体周次。应分别明确尚未预览的范围和真实事项标题，不把打开材料当作已理解或已核对。

## 修复与验收顺序

1. 业务就绪等待和真实提交阶段证据：覆盖正文延迟、永不就绪、身份/材料变化、原函数返回和真实请求发出；就绪前零授权消费、零提交，进入边界后最多一次。
2. 跨查询、跨端点的同主体精确事项未决/unknown 识别：隔离验证新旧查询、批次和不同主体，unknown 禁止重提。
3. 合并确认文案、未知结果详情、只读核验主操作与事项标题：独立 Workspace 验证待确认、提交中、核验中、成功、未提交和未知。
4. 自然语言闭集查询与分段性能：缩短本次 39.4 秒查询中的工具调用前等待，再优化重复草稿读取。独立测量工具前、OA 读取和结果投影，不删材料复核或以 AJAX HTTP 200 代替业务核验；同时统一材料预览范围文案。
