# 纳米机器人发布请求候选绑定修复

## 范围与原因

2026-11-27 正式发布的只读在线计划在 NanoBot 相邻版本迁移检查处失败，尚未切换线上版本。前端 `remote` 传入了已审核的 `routeTransition`，但公共 `remote_request` 没有附加当前发布的 `candidate`；远端在所有迁移动作之前读取该字段，因此计划的 `observe` 就抛出异常。原有相邻升级测试直接构造远端请求并手工填入候选，未覆盖实际前端序列化入口。

本次在独立分支基于 `f6ec4ec1e17c` 修复请求边界，覆盖在线观察、暂存、绑定、激活、恢复、探测及回退相关请求。含迁移时，目标必须等于本次发布候选，前端统一传入候选，拒绝调用者替换候选、审核配置或远端根目录。没有迁移的请求保持既有行为。共用该请求编码器的 Pi 路径一并回归，但不修改 Pi 的迁移策略。

保留相邻版本白名单、原目录修订、完整路由摘要、L3、原 Bot、原两主体和个人身份；不跳过 Full、制品、线上前驱或发布审核。所有测试只在隔离临时目录中运行，SSH、进程管理及系统隧道均由测试替身承接，不接触线上数据、真实 Telegram 或浏览器。

## 验收计划

- 真实前端 `observability`、`remote` 与公共请求编码器连接到隔离中央处理器，验证 0.3.0 → 0.3.1 的暂存、激活、原身份复用与恢复。
- 各发布动作携带相同候选，错误目标及调用者覆盖在发送前拒绝；无迁移的原请求保持不变。
- 运行 NanoBot 与 Pi 原生发布专项及本次差异对应的官方开发检查；固定新候选的正式 Full 与真实发布由主任务单独执行。

各发布动作的传输覆盖另验证恢复证明及其他既有参数不丢失，包括回退、恢复核验、隧道启停。此类编码测试不等同于真实 SSH、服务启动或业务动作验收。补充探测测试时曾因替身覆盖了原路由身份元数据而失败；已改为保留真实路由解析，只替换隔离 readiness 客户端，未放宽产品检查。
