# 协同办公意见确认时核对优化

日期：2026-11-03。用户要求取消填写意见时反复检查，改为点击确认时核对，并在上线后完成 Chrome 验证。

## 范围与行为

仅对具备完整可信材料基线、字段为单一 `opinion` 的 OA 办理页启用，覆盖审批、阅办知会、考勤确认及对应批次。编辑继续自动保存并校验文字，不访问 OA；普通轮询、刷新和恢复页面也不自动预检。其他业务表单及旧客户端继续沿用原流程。

点击确认携带草稿修订号、所见材料凭证与请求标识。服务端仅执行一次真实 prepare，核对当前账号、权限、任务、事项身份和材料；材料相同才以本次真实结果冻结意见并在原事务中记录决定和授权。材料变化只更新展示内容，保留意见并要求再次明确确认；更新的材料凭证独立于意见版本，后续编辑不会退回最初材料。账号或目标变化、撤权、过期及并发冲突均拒绝授权。

新增的 `business_draft_material_reviews` 仅记录已展示材料，不含授权计划，不延长原页面有效期。最终执行仍保留原单次授权消费、防重、提交边界检查及权威业务核验；未知结果不自动重放。代码与私有证据不保存凭据或可信卡片链接。

## 开发验证

- 定向回归覆盖新确认路径、原 preview/approve 兼容、批次、保留内容、警告接续及可信卡片；前端覆盖自动保存、刷新与恢复零预检、变化后再次确认及未知回执恢复。
- 独立审查发现源账号换绑后应在网络读取前拒绝，已增加初始、排队及最终事务的主体绑定检查，并通过回归。
- Chrome 扩展连接的隔离 Workspace 使用真实中心、OA 适配器、解析、授权事务及协调器，只有下游 HTTP/DOM 为合成。连续编辑期间下游调用保持 7 次；变化后的第一次确认增至 9 次，但决定、授权和写入均为 0；第二次明确确认才创建 1 个决定和授权。两次确认各仅一次 `draft.confirm`，没有 `draft.preview` 或 `draft.recheck`。
- 另一条材料不变的效能流程一次确认完成。长正文、空意见、更新提示、保存后刷新及合成完成页已检查；长历史工作台与输入框另存页面证据。

完整回归首个候选 `20592c3` 的 Python 阶段为 3565 通过、4 失败、3 个 opt-in 跳过；未作为通过收据。三项失败指向初始材料的来源标签被改为 confirmation，一项是新增伴随表尚未加入冻结存储合同的增量清单。已保留初始材料的 source 标签，并显式列出新增结构，原有结构及 SQL 断言保持不变。定向样本此前没有覆盖补签材料来源标签和存储总清单，已纳入修正验证；返工原因是兼容合同漏检。
