# 小改动验证范围与重复检查

用户要求本地与 GitHub 按实际影响验证。已有基线从纯文档、发布策略直接跳到完整 CI，单改测试也会运行所有业务测试、Node 套件和 wheel 构建；文档检查还会准备只供广覆盖回归使用的依赖。调查本地验证和已有收据复用入口，优先选择能界定影响范围的重复工作。

本次范围为开发和 CI 验证流程。验收覆盖纯文档、仅改测试、混合改动、未知或丢失的比较依据，以及失败如何传递。保持正式发布收据绑定、正式制品校验、独立 Linux 验证和生产身份边界。在独立工作树实现并验证，不带入主工作区的草稿。

此前实测中，本机固定 Full 共 225 秒，Python 阶段约 216 秒、Workspace Node 约 5 秒、wheel 约 3 秒。GitHub 纯文档运行共 33 秒，其中 Node 准备 6 秒、Python 环境准备 11 秒、实际检查 5 秒。历史提交 `628faf4` 仅改工作台历史测试和文档，旧分类仍会选广覆盖 CI。发布时漏加复用选项也会再次执行 Full。此次优先缩小这些可验证的重复成本。

开发入口与 GitHub 共用分类规则。新入口比较祖先提交、暂存区、工作区与未跟踪文件；无改动直接结束。暂存和工作树同一路径冲突时要求先对齐，未提交的 UI 改动先执行源代码专项，wheel 明确留到干净候选。开发结果写入与正式收据分离的目录。生产发布中的在线治理、备份、制品校验及发布后复验仍按正式流程执行。

本机独立 Node 检查用时 5.56 秒，运行 Workspace、OpenClaw、MCP App 及公开内容扫描。全新 Python 3.12 环境实测，无数据库扩展或 xdist，文档与发布策略两档通过，执行分别为 1.05 秒和 4.53 秒（不含 GitHub 启动与依赖安装）。

以相同项目规则回放基线最近 100 个普通提交的实际文件差异，原来 67 笔选广覆盖，现在 63 笔，具体新增定向为 `628faf4`（Node 与文档）、`3b4c0b5`（Node）、`b31c757` 和 `785e57f`（独立 Python 测试与文档）。另外 32 笔纯文档、1 笔发布策略继续走原有范围。此回放衡量分类机会，不假设历次 GitHub 比较基线都有成功证据。独立 Python 档在本机实跑 35 项，耗时 5.40 秒；既有共享夹具、核心运行代码及混入策略的前端改动仍选广覆盖。
