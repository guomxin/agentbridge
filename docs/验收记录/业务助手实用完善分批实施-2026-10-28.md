# 业务助手实用完善分批实施

## 范围与验收计划

开始日期：2026-10-28。基线：`35aed79`。当前状态：实施中，未发布。

用户要求按顺序分批落实，每批用 Chrome 扩展验收，使用通俗简短提示词，根据结果调整后续实现。主工作区已有规范、文档和测试修改，本次使用独立工作区，不纳入原有修改。

第一批：普通样例的原生工具边界、目录并发失效、待运行验收样例防丢、固定任务报告和对照版本展示、管理页已有检查信息展示。已确认原因分别为原生 hook 未检查样例状态、目录读取期间版本变化未阻止旧响应返回、离开守卫仅覆盖方法字段、任务按钮跳到当前草稿且报告未带基线身份。验收包含下一回合恢复、冷启动/已缓存并发失效、保存新修订保留题目、切换和刷新提示、旧修订报告可查、旧报告版本未知时不猜测。

第二批：准确关联原版本的文字使用反馈、真实反馈整理为脱敏样例、固定常用回归题。复用现有绑定、反馈和评测任务，不引入自动训练或模型裁判。历史归属不明确时不猜测；固定题目不继承通过结论。

涉及模块：OpenClaw 工具 hook/目录缓存；Skill 工作台和质量报告；Workspace/Admin 展示；现有 Skill 反馈及任务存储。

安全边界：保持用户/回合/版本隔离、模式发布和冻结审批证据；不增加业务权限、不复制真实业务原文、不自动审批或执行业务；未知结果不重放。隔离验收使用专用 home、端口、账号和合成文本，区分合成回归与真实模型/业务证据。

每批先定向验证及独立 Chrome Workspace 验收，覆盖长文本、空状态、多结果、提示生命周期、失败/恢复、刷新与账号隔离，再继续下一批。最后固定干净候选执行项目 Full 和制品检查；记录具体回执、耗时和未测边界。

### 第二批（约 12:16—12:27，北京时间）

- 在可核实原绑定的使用记录卡上增加“评价这次使用”；后端从事件和原绑定推导版本、模式和归属，客户端不能指定这些字段。同一使用记录重复提交返回原回执，冲突不覆盖。撤销后的历史评价不恢复执行权限。无绑定或不一致的旧记录不开放评价。
- 根据实际数据边界调整：现有记录能确认助手加载版本，但不能可靠关联每条回答；本次不伪造逐条回复归属、不增加消息追踪系统。该入口评价一次使用，不证明每条回答确实应用了规则。
- 反馈可整理为脱敏验收样例：保留来源反馈 ID，但问题和断言由用户填写，不自动拷贝原业务文本或把纠错说明当作断言。ID 在后端按用户及助手校验，并随评测保存。
- 每个草稿可固定一个已完成评测的题组，只保存现有任务引用，不复制成绩或增加样例管理页。临时测试不覆盖固定题组；按题目、模式、断言和重复次数判断是否同题同条件，条件变化时提示分数不能直接比较。
- Chrome 实测：“不要补原文没说的效果。”保存为原 1.0.0 使用反馈；转换后问题、断言为空。补入“整理成周报：登录问题还没定位，明天继续查。”，包含“还没定位”“明天”，排除“已解决”“提升稳定性”，实际通过本地合成评测。该临时题未替换固定周报题；点击使用常用回归题取回原问题、断言和重复 2 次，重测后显示“同题同条件”。
- 刷新/退出再登录后反馈回执与固定题组仍在；切换草稿的未保存提示可继续编辑或明确放弃；无评测草稿显示空状态；另一账号看不到私有助手、反馈和题组。控制台 error/warn 为空。界面发现使用来源写为“任务使用”不准确，已改为“助手使用记录”并补测试。
