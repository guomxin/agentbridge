# 原生电报可信卡关闭补齐

日期：2026-11-27。基线：`ad73d88ff3c2ce00c20fdd9e9b13db69e4a0bc30`。本记录仅覆盖 NanoBot、Pi 共用原生消费者；不代表部署或真实 Telegram 验收。

## 范围与安全边界

已确认：中央 v2 镜像卡已具原卡正回执关闭协议，原生 Telegram 工具卡仍只保存静态气泡。原生发送已有本地 SQLite 的唯一发送预留和正 `message_id`，可以补独立去重关闭通知。既有旧布尔 ACK、未知发送和未发出的卡不能用于补造原卡事实。

本次在独立工作树修改共享适配器及必要宿主私有呈现钩子。新呈现冻结原绑定、原 run 或原任务、原交互；本地关闭消费者只接纳本轮新发送且已确认送达的原卡。原生与镜像分别持有原卡，不借用对方权限或重复发送。现行 L2 只维持无任务 credential 卡能力，L3 延续现有任务卡；不增加业务能力。

关闭查询只读固定原交互公开状态，当前本人私聊与原配对必须仍有效。不返回可信票、凭证或业务字段，不恢复或继续业务，不改变模型答案。关闭发送前持久预留，未知不重发；终态 run、重启、多卡和其他主体均须覆盖。原卡外观不编辑，明确追加一次固定安全说明，原结果保持独立。

## 验收计划

覆盖两个宿主的原生卡正回执、成功/失败/过期/替换/拒绝、同任务多卡、历史无新来源不认领、未知/崩溃不重发、错 run/原配对撤销、原端点/主体/实例隔离、L2 已有凭证卡限制，以及镜像不重复。运行实际共享私有状态处理与中央 MCP、实际消费者和回环 Bot API；实际 SDK/Chrome/Telegram 由主验收独立记录。

## 实现与验证

共享消费者在 `reconcile()` 中独立观察原卡，不依赖入站轮询或原 run 仍在运行。新卡呈现先保存 `native-card-sources.sqlite3` 的原绑定及原 run/任务；发送预留与本地 watch 同事务。既有 `telegram_card_deliveries` 的确切正回执才允许追加关闭通知，通知回复原卡消息。关闭表保存唯一开始、结果和正回执；明确 429 按原等待时间最多五次，400 拒绝和不明回执均不自动重放。不迁移旧行、布尔确认或中央镜像投递。

状态读取使用新增 `agentbridge_host_interaction_present(state_only=True)`。原接口普通读取及任务快照具有推进任务或签发入口的附带行为，因此关闭观察不调用它们。新模式只返回固定原交互及原任务归属；当前私聊、主体、实例和配对失效时保留原发送事实，不发送新通知。L2 和 L3 独立登录都可以无 task，但必须是凭证卡且有原 run、请求键和本次呈现；无任务填写卡、授权卡不因此获得能力。

已正送达原卡的观察不套用出站领取的二十四小时时限。离线二十五小时后恢复，只要仍为同代本人配对，就可以读取原材料的自然过期状态并追加一次通知；不延长原材料或原发送授权。关闭已结算的 watch 不再扫描。每轮最多八条，已换绑旧记录也推进观察顺序，避免阻塞后来卡。
