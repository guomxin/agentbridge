# 业务助手首批体验改进与扩展验收

日期：2026-10-11。基于重构后的 `972e4cf`，在 `codex/skill-first-batch` 分支实现。本次为本地候选验证，未部署生产、未升级已安装宿主插件。

## 实际改进

| 场景 | 本次行为 |
| --- | --- |
| 改了处理方法，还没保存 | 显示“有未保存修改”，暂停评测和发布；试用按钮变为“保存后试用” |
| 保存后立即试用 | 先确认保存成功，再带入草稿 ID、新修订号和所选模式；保存失败或期间文字继续变化时保留输入，不进入错误修订的试用 |
| 预览已验证，填单尚未验证 | 分别显示每个模式的当前修订证据，只勾选有输出样例的模式提交；旧修订、旧内容哈希及仅触发评测不能充当本次输出证据 |
| 候选准备覆盖已有草稿 | 先显示方法、适用范围、模式依赖、参考资料及必读清单的新增、修改和移除；点击后使用查看差异时的修订号，版本变化会报冲突 |
| 助手超过候选数量上限 | 先排序再截取；完整名称或独立 ID 优先，其他按名称、简介、适用场景、输出描述的文本重合排序；“不适用”文字不增加相关分数 |

服务端额外返回当前修订完整的 `tested_profiles`，避免样例历史只展示最近 30 条时漏掉早期有效模式。后台任务刷新保留按任务 ID 展开的候选；采用中的同一候选跨刷新共用请求锁。候选排序是轻量确定性规则，不决定权限或最终适用性，没有引入向量库、训练服务或新的工作流框架。

## Chrome 扩展验证

开始修改前通过 Chrome 扩展列出标签页，读取已有 Workspace 的实际地址、标题和页面内容，确认扩展可以连接和操作。后续页面验收使用同一扩展连接。

本地临时 Workspace 使用真实 HTTP、数据库和业务助手服务，配独立合成账户、临时密钥与合成草稿。生成及独立评测调用现有宿主的真实无工具模型接口 `agentbridge.skills.complete`，返回模型为 `openai/gpt-5.5`；没有接通本地业务对话网关。页面上的 OpenClaw 未配置提示因此属于该测试环境边界。

| 操作或简短提示 | 观察结果 |
| --- | --- |
| “做个周报助手，分清已完成和计划。” | 真实模型生成“周报整理助手”私有草稿修订 1 |
| 编辑处理方法后查看按钮 | 未保存提示出现；评测、发布不可点击；“保存后试用”可用 |
| 选择预览并点击“保存后试用” | 新修订 3 保存成功，对话输入框包含同一草稿 ID、修订 3、preview；未点击发送，不宣称完成真实宿主对话试用 |
| “整理成周报：完成联调，计划下周上线。” | 候选与不使用助手各完成一次真实模型调用；两者均通过所列文字断言 |
| 查看预览评测并申请发布 | 预览可选，填单不可选；后台确认申请 `profiles` 只有 `preview`，修订为 3。测试申请随后撤回 |
| 查看合成候选替换差异 | 展示 8 项变化，包括移除 fill/preview、加入 use、移除参考文件及必读项 |
| 预览后由服务 API 模拟另一处保存 | 目标从修订 1 变为 2，原页面确认替换被拒绝；提示重新查看差异，不自动重试 |
| 重新查看差异后确认 | 保存修订 3，保留修订 1、2 历史；最终仅 use 模式，移除的参考文件没有残留 |
| 展开候选后刷新任务 | 展开状态及差异入口保留；定时刷新和任务顺序变化另由自动化覆盖 |

人工复核候选实际输出为“已完成：完成联调”“下周计划：计划上线”“日期：未说明”，没有把计划写成完成。无助手对照同样通过，因此不能据此宣称助手提高准确率。候选替换使用明确标注的合成候选，不冒充模型生成质量证据。

尝试第二个扩展标签页时，扩展返回跨浏览器配置窗口移动错误。既有验收标签页仍可使用，未切换浏览器；冲突通过服务 API 修改同一隔离草稿后，再由原标签页点击确认验证，不计为双标签页实测。

本地截图与模型调用元数据位于 `output/skill-first-batch-20261011/`。该目录不纳入 Git，截图分别记录未保存、修订试用、按模式申请、替换差异及冲突。最终页面未记录前端 JavaScript 错误；临时服务及验收标签页已关闭。未提交 OA、日志等真实业务数据，未授予业务权限，未更改生产草稿或发布内容。
