| 本轮项目 | 取证结果 |
| --- | --- |
| 安装 | 在宿主工具目录独立安装官方 `@earendil-works/pi-coding-agent@1.6.0`，保留 npm 锁文件。核对官方包的 SHA-512 与锁文件一致，Node 为 26.5.0，执行 `pi --version` 返回 1.6.0。 |
| SDK | 用临时目录和独立的内存会话管理器创建了两个不同 ID 的会话，两个会话的活动工具数均为零，均正常释放。这一步未调用模型或中央业务。 |
| 渠道范围 | 受管配置有两个不同的 Workspace 主体。在原私聊已确认送达的本机账本中，仅一个主体有对应的数字私聊身份。私有准备文件已写入两个网页主体和一条候选私聊映射，目录权限 0700、文件权限 0600。配置标记为准备状态，正式绑定仍需复核中央当前授权。 |
| Bot 创建 | 用户确认桌面当前登录的是第一账号。在已核验的官方 BotFather 私聊创建了 `AgentBridge Pi`，用户名为 `@AgentBridgePiBot`，随后在该账号的 Telegram 桌面端打开了新 Bot 的私聊。 |
| 密钥与身份 | 密钥保存在受管 Mac 登录钥匙串，仓库外配置保存其引用。另起独立进程按该引用无交互读取，通过官方 `getMe` 比对 Bot 数字 ID、用户名和显示名，并用 `getWebhookInfo` 确认 webhook 为空。复核配置时有两个 Workspace 主体、一个获准的私聊发送者，消费者处于停用状态。 |

软件安装与文档检查并行。上述结果覆盖本机安装、Bot 创建、凭据读取及渠道配置。Pi 的模型登录、宿主适配、中央准入、第一账号的双向收发及第二账号拒绝访问均留待接入验收。
