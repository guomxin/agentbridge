# 业务技能质量与持续沉淀二期验收

日期：2026-10-03。运行版本 `565cbe4ecead9`，OpenClaw 插件 `0.4.109`。通过原生固定发布入口部署并推送 main；健康、TLS、备份、Gateway 实际加载版本、发布冒烟和双身份验收通过。对应[二期设计](../架构设计/业务技能质量与持续沉淀二期设计.md)。

## 交付内容

- 结构化创作字段、方法诊断、草稿与线上差异、修订和发布状态、使用用户选择器。
- 持久生成与评测队列、幂等、取消、失败重试、租约恢复；模型服务复用宿主配置，无工具执行。
- 合成文字独立评测、正负适用场景、重复运行、候选/线上/无 Skill 对照、服务端断言、固定审批快照。
- 自动沉淀总开关和范围开关、完成事件事务发件箱、方法/偏好/事实分类、相似候选与明确采用操作。
- 权限过滤后的候选发现、可选参考文件按固定版本加载、组合前置检查、版本反馈与统计。
- 标准 Skill 文件映射的受限导入导出，不执行脚本，不继承原包权限。

## Chrome 扩展实测

全程使用同一 Chrome 扩展。先检查既有 Workspace 和管理控制台，再用简短人类提示测试。工作台为实际内网部署、真实已配置模型；控制台另有隔离测试，二者证据不混用。

| 场景 | 实际结果 |
| --- | --- |
| “做个计划整理助手，只整理给定文字，不补步骤。” | 后台保存“计划整理助手”私有草稿修订 1；无业务工具依赖，未发布 |
| 生成首次无效 JSON | 任务标记失败，未保存不完整草稿；手动重试成功。补丁增加一次受限格式重生成，取消/失效租约仍阻止保存 |
| “整理一下：计划修复登录问题。” | 候选与无 Skill 均通过包含“计划”“登录”、排除“已修复”“已经完成”的规则；人工复核候选未新增执行步骤 |
| “查一下原始日志。” | 候选判为不适用；规则通过 |
| “整理这段计划：明天检查登录。” | 候选判为适用；规则通过 |
| 评测汇总 | 候选 3/3、无 Skill 2/3。无 Skill 的触发对照定义为无方法可选，因此分差不代表生产路由准确率提高 |
| 仅自己提交发布 | 申请进入待审批；评测、方法、受众和差异固定到申请；审批前不进入已发布目录 |
| lishiyu 工作台 | 无另一用户的私有草稿、后台任务或个人助手；原有空分配状态保留 |
| 同时开启自动总开关和工作台范围后说“整理计划时，先列原文事项，再列原文日期，缺失就写未说明。” | 后台自动提炼为个人偏好，准确保留用户规则，没有新增 Skill、覆盖已有草稿或自动发布 |
| 标准文件包导出 | 浏览器生成 `skill-files.json`，格式为 `agentskills.files.v1`，内含 YAML 头的 `SKILL.md`；无用户身份、任务或审批记录 |

普通对话对最后一条规则曾回复泛化的业务工具策略，没有准确回应当前规则；后台提炼结果正确。该普通对话输出不计为语义质量通过，后续需要更多宿主对话样本确认。文字评测不能替代完整宿主交互评测。

测试后恢复自动总开关和工作台范围开关为关闭。保留新草稿修订 1、其评测与个人待审批申请，以及旧周报草稿修订 2 / 已发布 1.0.0。没有提交 OA、日志等真实业务数据，没有新增业务权限。

## 控制台验收边界

线上原控制台会话已过期，已请求用户重新登录；本轮没有绕过认证，也没有将待审批申请直接改为发布。

为继续完成 UI 检查，在临时目录启动同一提交的隔离控制台，仅使用合成用户、草稿和固定输出桩。通过 Chrome 扩展验证：

1. 审批列表显示方法名称、修订、使用范围和待审批状态。
2. 详情展示固定版本差异、受众变化、独立报告、未验证语义说明。
3. 不勾选复核即批准时，服务端拒绝并提示先检查草稿、样例和使用范围。
4. 完成复核后通过，列表状态变为已发布；前端无 JavaScript 错误。

隔离模型输出为 `fixture/stub`，只证明界面与后端审批流程，不作为真实模型质量依据。测试服务已停止。截至 10 月 3 日，线上新申请的控制台点击批准及批准后真实加载待恢复登录后补验；10 月 4 日已完成，见下文。

## 保留边界

独立评测是合成文字和明确断言；真实业务回放、通用语义自动评分、全量标准脚本执行和跨宿主端到端质量不在当前完成声明内。相似匹配是文本候选，组合功能是执行前检查，偏好/事实分类不是通用个人记忆系统。上述调整已写入设计，避免把未经验证的能力包装为完成。
