# 语雀查询与正文交付修复设计

日期：2026-10-08。本文保留实施前的设计；实际修改、部署及验证结果见[修复与复核记录](./基础读取八项用例修复与复核-2026-10-08.md)。
本文件记录缺陷修改方案，不登记用户手工用例是否通过；照明系统不在范围内。
本方案的五项问题已纳入[B01—B08 统一修复清单](./基础读取八项用例代码侧复核-2026-10-08.md)的 R5—R9，与其他四项缺陷作为同一轮实施范围。

## 目标与已知事实

完成用户授权范围内的文档查找、候选核实和原文入口交付；明确区分工具调用结束、搜索完成和目标找到。
保留现行只读接口和凭据值脱敏约定，不把文档定位误判为必须拒绝的操作。

此次记录中，语雀搜索与正文读取成功；目标地址搜索返回 42 条候选，但仅取得第一页 10 条，随后未读取候选核实。
最后两轮回复未调用工具。全文展示的宿主最终历史正文为 1,699 字符，中央收到并保存的最终流事件为 3,312 字符，包含重复正文。
这已证明两种最终结果不一致，但尚未确定上游具体拼接位置。
语雀读取结果的脱敏计数为零；代码未覆盖“帐密/账密”和带引号的密钥赋值形式。
当前知识库枚举来自组织公共区，不能等同于账号可访问的全部空间。

## 一、查询过程与结果交付

修改 `bscli/mcp/central.py` 的语雀工具说明、`bscli/adapters/yuque.py` 的能力描述，重新生成宿主工具目录，避免只修改生成文件。

- 区分搜索列表与定位目标：前者可按用户要求返回一页；后者应继续分页、筛选并读取相关候选，不把第一批搜索命中当作目标已找到。
- 用户授权的查找目标包含对相关候选文档的只读核实，不要求用户逐篇重复说“打开”。重名或范围歧义影响结果时再澄清。
- 候选核实应确认目标地址和所需信息属于同一段落、章节或表格记录，不能因为地址出现在文档中，就声称该文档包含目标登录资料。
- 返回标题、知识库、原文链接和可核实的非敏感位置说明；区分“已确认”“候选待核实”“已检索范围内未找到”。
- 达到单轮执行预算时报告已查数量、剩余范围和停止原因。不能声称全部查完，也不强制无差别读取全部候选。
- 搜索与读取结果提供一致的原文 URL：相对路径依据配置的语雀 origin 解析，校验目标域名；保留旧字段并新增规范化字段，避免破坏现有调用方。

首批复用现有搜索、目录、读取和分页工具，不新增通用规划框架。工具说明不能保证模型始终按预期行动，因此必须增加真实模型行为验证。
若仍反复提前停止，再设计有界的定位操作，将候选核实流程下沉到服务端；不以简单关键词过滤伪装成可靠定位。

## 二、最终正文的一致性

定位范围为 `bscli/workspace/gateway_client.mjs`、`gateway_events.mjs`、`gateway.py` 和 `application.py` 的宿主终态处理。

1. 用合成内容复现“部分回复中断后重新生成完整正文”的事件序列，比较流事件与同一 run 的最终历史，定位拼接来源。
2. 明确累积快照、增量片段和最终消息的协议语义。最终权威正文替换临时内容，不追加到先前正文后面。
3. 若上游最终流事件本身不可靠，在适配层有界核对同一请求的最终历史：同时匹配会话、请求/run 标识及真正结束的 assistant 消息。
   不可直接拿会话最后一条消息，也不可把工具调用前的说明当作最终答案。
4. 权威终态确认后统一用于实时页面、中央持久历史及刷新恢复。核对超时走既有结果恢复流程，不重新执行用户请求。

不使用按重复标题或相似段落裁剪的办法，避免删掉正常重复内容；不直接修改全局安装的宿主包。
历史中已有的重复消息暂不批量重写，修复先保证新消息正确。

## 三、脱敏规则与可解释性

修改 `bscli/adapters/yuque_content.py`，并检查 `yuque.py` 的所有返回字段。

- 补充“帐密/账密”、带引号的配置赋值、环境变量式密钥名、凭据连接串等已确认缺口。
- 表格按字段和单元格关联识别，正文、结构化表格、OCR、链接及元数据共用一致的处理规则；不要只处理展示正文。
- 保留章节、字段名称、服务器地址及非敏感定位信息，隐藏凭据值。提供脱敏类别和位置，不返回原始值。
- 采用结构化识别加文本规则，明确这是已知模式检测；不得用“未命中规则”证明正文没有敏感信息。
- 测试仅使用合成凭据，不把真实文档内容、密码或密钥复制到仓库、测试夹具或诊断日志。

本设计能完成文档定位，但不增加明文凭据查询能力。若产品目标包含直接交付凭据值，需要另行定义授权主体、用途、展示通道及审计边界；不能通过提示词绕过当前接口约定。

## 四、范围说明和完成语义

- 结果新增明确的搜索范围元数据，表示组织公共区；保留现有分页字段并明确 `hasMore` 的含义。
- 同步更新工具说明、生成目录和语雀适配文档，把“所有可见知识库/组织范围”改为实际覆盖范围。
- 其他团队空间、私人知识库的接入单独评估，不把扩大搜索范围混入本次修复。
- 不改变既有 dispatch 的 `completed` 含义：它表示宿主本轮结束。用户目标是否完成由有证据的结果说明表达，避免牵动通用任务状态机。

## 实施顺序与验证

先补合成回归样本，再分别完成正文一致性修复与语雀查询/脱敏修复，统一验证和发布。

| 场景 | 验证条件 |
| --- | --- |
| 目标只在第二页 | 能继续查找，或准确说明未查范围；不能把第一页当作全部结果 |
| 多文档提到同一地址 | 区分地址提及与目标资料确认，提供正确的文档标题和链接 |
| 用户只要文档位置 | 能完成相关候选核实，不因存在凭据字段而一概拒绝 |
| 合成敏感格式与普通字段 | 凭据值在所有返回表示中被一致处理，普通标题、地址、端口和定位信息保留 |
| 中断重生成、快照修订 | 最终正文只保留权威版本；合法重复段落不被误删 |
| 并发回合与历史晚到 | 不串用其他请求的正文，不自动重发，不误取工具前说明 |
| 持久化与刷新 | 实时最终正文、保存正文和刷新后的正文一致 |
| OA 详情及普通文本回归 | 原有详情、短回复、失败提示和任务恢复行为保持有效 |

执行 Python/Node 定向测试、macOS/Ubuntu Full、Chrome 扩展验证。模型行为验证使用合成知识库样本或现有授权范围内的脱敏只读结果，
不能以工具单测通过代替“查询目标完成”的验证。同步更新语雀适配说明、项目当前状态和本目录实施记录。
