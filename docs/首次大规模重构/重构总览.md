# 首次大规模重构

本目录集中保存 2026-10-04 启动的首次大规模重构的评审、分批设计、实施和测试证据。
目标是在保留现有功能、业务权限和受控写入边界的前提下，降低新增系统、能力、技能和宿主的修改成本。
继续采用模块化单体，按小批次推进，每批独立验证。九月已经完成的职责拆分、发布和恢复治理是本次工作的基础。

2026-10-04 用户确认后续不再使用 Windows。本次及后续重构以 macOS 开发和本机宿主、Linux 中心服务及 CI 为维护目标，
Windows 兼容与实机验收不再作为完成条件。现行验证使用 Python 共享计划；既有 Windows 脚本和迁移证据作为历史兼容材料保留，后续按依赖逐步清理。

## 第二批推进安排（2026-10-04）

用户明确图片验收等回到电脑后再处理；该项单独保留，不作为下一个代码批次的前置条件。
用户已确认以下 2B 范围，并告知照明登录过期。2B 已实现并发布，平台验收结果见本批记录，照明实机验收待用户回来后补做。

本次实施 **2B：照明告警备注修改类型声明与兼容回归**，范围为
`smartlight.alarm.remark.update.prepare` 和 `smartlight.alarm.remark.update` 两项能力。
该流程与现有声明结构相容，同时覆盖泰华试点没有的 `context_fields=(alarm_id,)` 和 `reversible_write`，
可检验类型声明在另一系统、固定目标和可回滚修改中的适用性。继续保留参数、字段卡、scope、权限和动态函数解析合同。

本批交付要求：

1. 固定迁移前的完整能力、字段卡及目录合同，并为照明声明生成原形状投影。
2. 检查泰华与照明的能力、写目录、scope、用户权限及规划描述之间的一致性；外围映射仍按实际来源维护。
3. 验证目标告警不能被字段提交替换，备注留空仍表示清除，并发修改会阻止提交，权威回读、回滚信息、
   单次授权及提交后未知结果不重放保持原行为；取消/撤权测试继续覆盖共享执行器。
4. 完成固定提交 macOS Full、Ubuntu Full、原生发布验收并记录实际证据；无需为静态重构提交真实业务修改。

其他照明动作的旧目录为 `field_schema=None` 且没有 `field_message`，当前类型声明要求非空字段提示，
应另批设计可选字段卡合同后迁移。OA 还包含预检、动态字段与批量反向映射等变体，按形状分别迁移。
之后先对普通调用与计划调用做参数校验差异清单和兼容样本，再统一可共享部分；
随后推进中央服务显式依赖、存储初始化与维护分离、技能动作请求合同。各工作包分别验证，
保留授权消费、计划取消和技能撤销的共享事务及复核时点。
