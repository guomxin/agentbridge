# 图片发送异常修复

本次为重构结项后的缺陷修复，不新增重构阶段。用户手工验收结果不在本文登记；照明系统不在本次验证范围。

## 现象与证据边界

用户反馈 A04 通过“添加图片”选择文件，点击发送后图片消失，未看到智能体开始处理。检查时线上没有对应的新图片受理记录。
本地相同代码通过 Chrome 扩展复现：把 PNG 合成图片命名为 `.jpg`，浏览器能预览，但发送后图片被刷新移除，连接状态悬留。
真实用户图片未提供，因此不能断言其两次失败均由后缀与内容不一致引起。

发送接口在图片校验、持久受理前已经发送 SSE 200 响应；校验异常随后进入通用 JSON 错误处理，产生混入 SSE 的第二段 HTTP 响应。
前端忽略这段无效事件，并把没有最终结果的 EOF 当作正常完成，触发历史刷新和本地消息清理。
旧有正常小图片测试覆盖不到这条路径。

## 修复范围

- 选图按文件头识别 JPEG、PNG、WebP，修正支持格式之间因后缀导致的 MIME 误判；不能识别的内容在发送前明确提示。
  文件内容保持原样，后端仍独立校验，最多 4 张、单张 6 MB、合计 12 MB 的限制保持有效。
- 服务端先执行既有校验和持久受理，再发送 SSE 响应头；受理前的错误走正常 JSON 状态码。
  发送响应头后的非断连异常统一使用 SSE 错误事件，内部异常内容不下发。
- 前端只在收到终态或时间线已经确认完成后判定成功。连接提前结束会显示明确失败，不触发成功刷新，也不自动重新发送。
  本地待确认图片和文字继续可见；用户主动刷新时以后台持久记录为准。

不修改数据库结构、业务授权或持久受理事务；Gateway 与插件版本保持现状。
