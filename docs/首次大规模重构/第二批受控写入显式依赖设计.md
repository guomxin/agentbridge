# 第二批受控写入显式依赖设计

日期：2026-10-04。基线：`65f5442`。状态：2G 设计与实现中。

## 范围与动机

中央服务目前继承 `ControlledWriteExecutor`，执行器直接访问中央服务的存储、注册表、卡片地址和五个回调。
这使执行器无法独立构造，也难以辨认新增写流程真正需要的依赖。本批将继承改为组合，
保留中央服务的公开构造参数、存储属性、能力调用入口和全部业务行为。
中央服务的存储初始化、适配器装配和生命周期仍按原顺序执行，后续独立处理。

新增冻结的 `ControlledWriteDependencies`，明确列出七个存储/注册表对象、可信卡片地址与五个回调。
执行器只接受该依赖对象；卡片生成、待办批量定义、技能检查、计划验证由中央服务提供窄回调。
依赖装配只引用已有对象，不初始化数据库、不创建新连接；执行器不接收或访问中央服务对象。
中央服务在每次进入执行器时装配依赖，保留调用前替换注册表、存储或回调的既有行为，避免构造期缓存旧引用。

## 必须保持的边界

- 字段卡、目标绑定、最新详情提示、冻结授权卡、独立确认、会话绑定复核的顺序与错误保持一致。
- `enter_commit_boundary` 继续先复核用户权限，再调用原授权存储的 `consume`。
  技能检查和计划授权检查继续使用 `consume` 传入的同一 SQLite 连接；不得提前执行或另开事务。
- 授权消费与计划提交标记同时提交/回滚；技能撤销或计划取消仍能阻止正式写入。
- 下游写入后的异常继续归为未知，不能自动重放；OA 可继续提示仍产生新的独立授权。
- 能力 Schema、CLI/MCP/Workspace 合同、权限、持久数据及真实业务配置保持兼容，无数据库迁移。

## 验证与交付

先比对旧执行器与新执行器的语法树，在仅归一化依赖访问与方法名后，所有原方法逻辑必须一致。
核对中央服务原构造器保持不变，原其他方法仅变更四处执行器调用。
增加无需中央服务的执行器测试，验证授权与回调的事务连接、失败回滚、未知结果及不可重复消费；
中央集成测试覆盖调用前替换依赖。既有取消、撤权、重启恢复、批量、字段卡和 OA 继续确认回归共同执行。

完成定向测试、发布预检、干净固定提交 macOS Full、同一 wheel 核验、原生发布与 Ubuntu Full。
本批不为结构重构执行真实 OA/照明写入。图片与照明补验、工区和处置保留事项仍以原独立记录为准。
