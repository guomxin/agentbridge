# 第二批试点设计：泰华日志创建类型化流程描述

日期：2026-10-04。基线：`eb5b8d5`。状态：2A 试点实现及定向离线验证完成；尚未完成本批固定提交 Full 或发布。

本试点对应[架构评审与分批计划](./架构评审与分批计划.md)的第二批，仅统一泰华日志创建的静态流程声明。
保留中央服务公共门面、受控写执行器、MCP 签名、现有参数校验、用户权限目录和持久化结构。

## 现有合同

| 项目 | 保持的值 |
| --- | --- |
| 准备能力 | `taihua.work_log.create.prepare` |
| 提交能力 | `taihua.work_log.create` |
| 能力版本 | 两者均 `0.1.0` |
| effect / adapter | `controlled_write` / `taihua-central` |
| workflow | `taihua-work-log-create-prepare-v1`、`taihua-work-log-create-v1` |
| 输出 Schema | 两者均 `{"type":"object"}` |

| 用户业务权限 | `taihua.work_log.create` |

| 冻结计划版本 | `agentbridge.taihua_work_log_create_plan.v1` |

准备输入保留 `log_date`、`hours`、`project`、`content`、`input_submission_id`；无必填属性，禁止额外属性。
空参数仍进入可信字段卡。提交输入仅允许必填 `authorization_id`。字段卡原有日期、半小时工时、项目与正文长度约束保持原样，
本批不把这些约束额外施加到其他调用入口，也不改变适配器的默认值、归一化或异常分类。

准备函数为 `prepare_taihua_work_log_create`，提交函数为 `commit_taihua_work_log_create`，`context_fields=()`。
契约与未知结果异常分别为 `TaihuaWorkLogContractMismatch`、`TaihuaWorkLogOutcomeUnknown`；
业务拒绝继续使用 `TaihuaBusinessRuleRejected` 和 `TAIHUA_BUSINESS_RULE_REJECTED`。

## 最小改造

1. 新增 `bscli/core/write_workflow.py`，定义不可重新赋值的类型化流程声明、构造校验及兼容投影；仅依赖能力类型与标准库。
2. 在 `bscli/adapters/taihua.py` 声明一个日志创建流程，提供原来的两项 `CapabilitySpec`。
3. `bscli/core/write_catalog.py` 从该声明生成原有业务字典和两项 scope；其他流程继续沿用原定义。
4. 保留旧函数名、模块函数别名、白名单解析与执行器读取的字典形状。既有 `write_catalog` monkeypatch 故障注入仍经过相同执行入口。

类型包含准备/提交 spec、scope、字段 Schema、上下文字段、两个真实 callable、两种异常和两条提示文本。
构造时检查配对系统及适配器、写入 effect、非空权限、可调用绑定及异常类型。字段 Schema 和能力 Schema 的投影复制，
避免一个消费者修改字典污染另一个投影；不将浅层 frozen dataclass 宣称为嵌套对象完全不可变。

MCP 工具、用户权限 JSON、规划元数据仍是外围映射，本批用一致性回归保护，不声称已实现全仓库单一声明。
不改授权消费、取消及技能撤销共用的 SQLite 事务；不改提交边界和权威回读；结果未知不自动重放。

## 验收

- 新旧能力的名称、版本、描述、Schema、workflow、字段卡、写目录及权限相等，其他写流程和工具可见性保持不变。
- 不合法的能力配对、空权限、非 callable、非法异常类型在声明构造时被拒绝；投影中的嵌套 Schema 修改不相互污染。
- 字段预填、重复日志拒绝、同日不同日志允许、项目消歧、提交前复检、单次授权及权威回读保持原行为。
- 既有取消/授权竞态、边界撤权复核、提交后未知不重放、重启恢复及模块函数故障注入测试继续有效。

定向测试涵盖 `test_write_catalog.py`、类型声明新增测试、`test_taihua_adapter.py`、`test_plan_write_boundaries.py`、
`test_central_service.py`、`test_central_mcp.py`、`test_user_grants.py`。测试使用临时会话密钥、临时状态和模拟业务端。
开发结果不代替固定提交 Full、真实业务验收或发布回执；无线上调用、推送或部署。
