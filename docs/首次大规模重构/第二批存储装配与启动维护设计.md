# 第二批存储装配与启动维护设计

日期：2026-10-04。基线：`94f2460`。状态：2H 实施中。

本批一次处理三个相连工作包：中央服务的存储装配、会话/任务历史维护与 Schema 初始化分离、
数据库查询期间的数据源目录重复初始化。公开构造参数、存储属性、业务规则与持久数据继续兼容。

## 装配与生命周期

中央存储采用前置授权/技能、运行存储两个明确的类型化构建结果。中央服务继续显式绑定原属性，
技能创作初始化和能力注册仍在原位置；运行存储保持操作、会话、字段卡、授权、交互、任务、计划、
转换器与治理存储的原有依赖顺序。外部注入的会话密文存储和发布标识继续生效。
构建结果不持有中央服务、不共享不同 home 的对象，也不采用全局服务定位器或隐式属性注入。

会话活动时间回填、任务交互观察回填、历史终态修复、孤立任务过期与拉取式通知对账归入显式启动维护入口。
Schema 建表/加列单独执行；任务四类数据修复仍在同一个连接内按原顺序提交，异常全部回滚。
原存储构造器默认继续执行维护，保证独立 CLI、测试和外部调用兼容；中央装配显式选择 Schema 初始化后维护。
维护只处理既有本地账本，不执行下游写入，也不重放未知任务。任务计划重启恢复继续由原运行时负责。

## 数据源读取

数据源构造目前每次创建目录、密钥保护器并执行两次建表，内容查询每批取数都重复此过程。
按 IndependentDatabase 实例协调首次 Schema 初始化；后续获取不建表的轻量 Sources 句柄。
不缓存授权、配置记录、启停状态、修订号或解密器；每次仍检查密钥文件并在原 snapshot/unchanged 时点读取实际记录。
旧源导入仍在原调用时点发生，已存在的禁用源继续优先；初始化失败可重试，实例间隔离。
这种方式消除重复 DDL，保留运行期密钥与授权检查，不引入需要失效管理的权限缓存。
