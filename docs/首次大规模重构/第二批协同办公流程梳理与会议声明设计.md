## OA 现状与分批边界

OA 注册表包含 67 项能力，其中 19 项只读、48 项写能力（42 项受控写、6 项可逆写）。
写目录有 25 个准备入口、23 个不同的提交能力；准备与提交并非全部一一对应。
按目录的现有行为互斥分类：

| 类型 | 准备入口数 | 现有流程与特殊合同 | 后续安排 |
| --- | ---: | --- | --- |
| 普通静态字段卡 | 8 | 出差草稿/提交、请假草稿/提交、补签草稿/单条审批、会议室申请撤销、流程撤销 | 2D 迁移会议室申请撤销，其余保留 |
| 非批量动态字段卡 | 2 | 会议创建、独立会议室申请，首次展示读取实时房间和可用性 | 2D 迁移 |
| 审批预检 | 13 | 效能、差旅报销、出差、劳动续签、知识产权、加班、请假、离职、交接、机票、考勤确认、周报及标准协同 | 另批设计函数与 profile 配对、审批依据和指纹兼容 |
| 批量共享提交 | 2 | 旧补签批量和通用待办批量，均有动态字段入口；通用批量还按当前事项替换实际定义 | 另批设计别名和多准备入口共享提交的投影 |

所有 OA 写目录均有字段卡。13 个预检项在基础目录之后追加 `preflight_function` 与 `preflight_profile`。
旧补签单条、旧批量和通用批量的静态目录共享 `oa.missed_punch.approve`；
反向目录必须显式指向单条准备入口，不能用“提交能力必须唯一”校验拒绝现状，也不能依赖最后插入项取代显式覆盖。
通用批量运行时按当前事项选择准备定义、注入 `batch_id`、`affair_id` 等上下文，逐项独立授权。

编排目前位于 `central_service.py`：先解析批量上下文，再在无 `input_submission_id` 的初次请求中执行预检和动态字段生成，
把审批依据及其指纹注入字段卡，最后加批次提示。字段恢复复用已存字段卡和用户提交值；
随后准备业务计划、生成独立授权，提交前仍按既有规则复核业务状态。
`controlled_write_executor.py` 继续拥有字段/授权绑定及提交边界；取消、技能撤权和授权消费保持原共享事务。
本批不搬动上述编排，也不统一普通调用与计划调用的参数校验。

## 2D 范围

| 声明 | 准备 / 提交能力 | 字段行为 |
| --- | --- | --- |
| `MEETING_CREATE_WORKFLOW` | `oa.meeting.create.prepare` / `oa.meeting.create` | 动态会议字段；创建并发送会议，原有意图确认与回读保持 |
| `MEETING_ROOM_APPLICATION_CREATE_WORKFLOW` | `oa.meeting_room.application.prepare` / `oa.meeting_room.application.create` | 动态独立申请字段；不发送会议，继续复核占用并回读“我的申请” |
| `MEETING_ROOM_APPLICATION_CANCEL_WORKFLOW` | `oa.meeting_room.application.cancel.prepare` / `oa.meeting_room.application.cancel` | 静态撤销原因字段，冻结 `application_id`，保持本人申请和终态校验 |

三流程均保持版本 `0.1.0`、adapter `seeyon-central`、effect `controlled_write` 和 scope `oa:write:meeting`。
权限仍分别是会议创建、会议室申请、会议室撤销；不因共用 scope 扩大权限。
六项能力的描述、输入/输出 Schema、workflow 名、字段提示、授权提示和 MCP/规划映射保持原值。

声明分别放在 `seeyon_meeting.py` 与 `seeyon_meeting_room_application.py` 的函数定义之后。
中央 OA 注册表和写目录消费声明投影；业务模块不反向导入注册表获取能力定义，保留已有异常路径的懒导入。
迁移三项目录及六项 scope，保持注册/目录插入顺序、旧常量与导入别名、函数白名单和动态解析桥。

## 最小类型扩展

在 `WriteWorkflowDefinition` 现有 11 个位置参数之后增加仅关键字可选参数
`field_schema_function: Callable[[object, object, dict], dict] | None = None`。
存在时要求可解析名称的函数，投影只保存函数名；声明、注册和投影本身不执行函数。
`legacy_definition()` 在 `field_schema` 后、`context_fields` 前插入旧 `field_schema_function` 键；
缺省完全省略该键，2A/2B/2C 的键集合与顺序保持。能力及静态字段 Schema 继续深复制。
不提前添加尚未迁移的预检参数，不把动态字段转成初始化时的固定快照。

涵盖六项能力、三个目录、scope、权限与规划。另保存全量 106 项能力、30 项目录、28 项反向映射、
58 项 scope、60 项函数白名单及权限/规划快照；预期不从迁移后实现重新生成。

- 静态合同逐项对照，包括动态函数键的有无和顺序、三流程参数、深复制和动态函数替换。
- 动态卡只在首次请求生成；待填和已提交恢复不重新计算房间选项，可信用户字段不被新参数替换。
- 撤销不执行动态字段函数，目标绑定不允许跨申请恢复；字段提交与业务授权保持独立。
- 三条提交链验证单次授权、边界后未知结果持久化及同键/换键不重放。
- 原适配器的实时占用复检、写前拒绝、权威回读和未知结果用例继续执行；审批预检、批量与计划事务回归保护未迁移路径。
