# 第二批共享参数校验设计

日期：2026-10-04。基线：`1ab6ddd`。状态：2F 已发布 `1d298fcceae4`，macOS 与 Ubuntu Full、基础发布验收均通过；证据见[实施记录](./第二批共享参数校验实施与测试记录-2026-10-04.md)。
承接写声明整合，本批统一普通能力、持久计划和确定性转换器的参数校验基础，保留现有入口行为。

## 已确认的差异

| 规则 | 普通能力 | 计划静态参数及绑定解析后 | 转换器输入与输出 |
| --- | --- | --- | --- |
| 对象必填及未知字段 | 必填先于未知字段；必填按声明顺序 | 未知字段先于必填；必填排序；绑定可满足必填 | 每层必填先于未知字段；必填按声明顺序 |
| 类型及联合类型 | 顶层字段；联合类型只处理字符串成员 | 顶层字段 | 递归对象及数组 |
| enum | 不检查 | 顶层检查 | 递归检查 |
| 字符串长度、数字上下限 | 不检查 | 顶层检查 | 不检查 |
| 静态参数与绑定重叠 | 不适用 | 拒绝；仍在必填检查之后 | 不适用 |
| 未识别的 Schema 关键字 | 忽略 | 忽略 | 忽略 |

三处都明确排除把布尔值当作整数/数字。计划的绑定类型兼容、来源完整性和拓扑规则属于独立合同。
普通能力允许交给适配器处理的默认值与归一化，不能因整合而改用计划的严格程度；
转换器现有嵌套校验也不能被浅层普通能力规则削弱。

## 实施合同

新增无存储、无网络、无业务依赖的[校验模块](../../bscli/core/input_validation.py)，共享对象字段检查、类型判断、枚举和既有边界检查。
三个具名兼容配置由调用方固定选择，不增加请求参数或用户开关；不默认启用新的严格校验。
共享层返回结构化首个问题，原入口继续生成原异常类型、错误码、消息、字段路径及 stepKey。
保留原私有函数入口，保证现有导入和调用桥继续可用。

普通能力仍在创建 Operation 前校验；计划仍在编译时以及绑定解析后、调用能力前校验；
转换器仍在调用 handler 前校验输入、handler 后校验输出。授权、幂等、取消、未知结果不重放、
事务和持久结构均不调整；不修改任何能力 Schema、权限或适配器归一化。
本模块实现现有受支持子集，不宣称是完整 JSON Schema 验证器。

## 基线与验证

运行代码编辑前固定三入口的代表样本、接受/拒绝、消息、错误码和优先级；
另对所有现有能力及转换器 Schema 生成边界差分样本，保存旧实现结果，不能从新实现反生成预期。
覆盖缺省、空串、空备注、nullable 联合、布尔/数字、额外字段、枚举、上下限、嵌套对象、数组项和绑定延后。
整合后逐项比较，新旧输入/Schema 不得被修改。

集成验证包括无效输入不创建操作、相同幂等请求只执行一次、绑定解析后的无效输入阻止下游调用、
转换器嵌套错误阻止 handler 及无效输出保留错误路径。原计划恢复与受控写回归继续执行。
定向与发布预检后固定提交，完成 macOS Full、同一 wheel 制品校验、原生发布和 Ubuntu Full。
持久数据兼容为 `no-migration`；不为本批执行真实 OA/照明写入。

中央服务依赖、存储职责和技能请求合同保留后续批次，避免同时移动校验与执行事务。
