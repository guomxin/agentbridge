# 第二批技能请求与后台执行设计

日期：2026-10-04。基线：`8dca9e0`。状态：2I 实现与定向回归完成，正式全量与发布待执行，实际进展见[实施记录](./第二批技能请求与后台执行实施与测试记录-2026-10-04.md)。

本批一起处理技能请求合同、动作分发、持久任务队列和模型执行。新增动作时有明确的参数与处理入口，
调整生成或评测时无需同时理解队列事务；公开工具、用户权限、审批发布与已有任务继续兼容。

## 请求与分发边界

将现有七个 Pydantic 类型移至 `skill_contracts.py`，`skill_quality.py` 保留原名重导出。
旧 MCP envelope 的 33 个可选字段、strict/extra 规则、默认值、嵌套 Schema 和字段顺序完整保留。
`skill_actions.py` 明确声明 28 个公开动作的必需/可选字段及固定处理目标，并提供独立形状解析。
声明选择处理方法，用户不能直接指定方法名；`decide` 和内部 `_job` 继续不在公开入口内。
同合同的方法替换在实际调用时解析；声明与方法签名由冻结合同及回归核对。

本批只提取形状检查，不在分发前新增值校验、默认值填充或内容归一化。
MCP 先使用严格 envelope，再以 `exclude_unset=True, exclude_none=True` 输出参数；Workspace 继续接受原始 JSON。
例如顶层 `null` 在两入口已有不同处理，不能为了共用解析而抹平差异。
字段类型、身份归属、修订冲突、额度和幂等判断仍在原领域方法按原顺序执行。

## 队列与模型执行

`SkillJobQueue` 只接收数据库连接、事件、唤醒、校验与时钟回调，负责排队、查阅、取消、重试、认领、续租、完成。
保留原 SQL、事务边界、同键冲突、每日/活动额度、五分钟租约、三次尝试上限和按创建时间取任务。
事件与入队/取消同事务，唤醒发生在提交后；失效 claim 不能完成任务，关闭自动范围后不能继续执行。
范围判断和最新评测报告查询允许复用调用方连接，不另开事务读取旧快照。

`SkillJobExecutor` 只依赖显式回调，处理生成、评测和进度接续，不持有工作台、数据库或线程。
保留原提示词、输出限制、一次格式重试、评测变体、错误脱敏与历史任务 kind 回退。
回调在使用时解析，避免捕获过期模型或业务服务。
生成成功仍调用 `SkillAuthoring.save(_job=...)`，草稿、修订、回执、事件和任务成功状态在原同一事务中提交；
不能把保存与队列完成拆成两笔事务。

`SkillWorkbench` 保留原方法签名作为兼容门面，仍负责领域操作、Schema 初始化、线程启动/关闭和自动素材捕获。
当前单活运行方式、审批发布权限、自动提炼双开关和无工具模型执行范围保持原状。
不新增 Schema、数据库迁移、任务并行、调度公平性或外部业务调用。
