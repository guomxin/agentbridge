## 声明结构

新增 `seeyon_write_workflows.py` 聚合剩余 OA 声明，依赖叶业务模块与核心声明类型；
不导入中央注册表或写目录，不执行页面读取、预检或业务提交。原业务函数、异常类和 Schema 常量保留。
13 类审批能力继续从原 `PENDING_ACTION_CAPABILITY_DEFINITIONS` 元数据构建，不另造一份业务 profile。
普通流程的能力版本并不一致，例如出差准备和提交版本不同，保持旧值，不加版本相等限制。

聚合模块暴露 `OA_WRITE_DECLARATIONS`（22 项）及 `oa_write_capability_specs_by_name()`（42 项独立能力副本）。
中央注册表在原有位置取投影，保留只读能力的穿插位置。写目录保持全量插入顺序；scope 同样保持原顺序，
不以类型声明遍历顺序替代原消费者顺序。旧导入名称和函数字符串解析桥保留，故障注入仍能替换目录模块中的函数。

### 审批预检

`WriteWorkflowDefinition` 追加仅关键字参数 `preflight_function=None` 和 `preflight_profile=None`。
两者必须同时缺省，或为具名可调用函数与非空 profile；构造、能力注册和投影都不执行预检。
兼容目录仅在存在时，于 `authorization_message` 之后追加原 `preflight_function`、`preflight_profile` 两键。
保持旧 11 个位置参数和 2D 动态字段参数，已有声明缺键语义不变。

运行时继续首次请求预检，再生成可信字段卡并注入审批依据/指纹。带字段提交标识的恢复复用已存卡片，
字段提交后准备计划时重新获取依据，发生变化仍在授权卡中提示重新核对。
不支持的业务契约在字段卡创建前拒绝；不能为声明迁移跳过预检或缩小拒绝范围。

### 批量与共享提交

新增 `WritePrepareAliasDefinition`，显式引用一个规范的成对声明，另持自己的准备能力、上下文、提示和可选动态字段函数。
别名只投影自己的准备能力与 scope，不重复注册提交能力；兼容目录复用规范提交的函数、异常及字段合同。
不能串联别名作为规范来源。源数据和投影保持副本隔离，声明不执行回调。

单条补签、旧补签批量和通用待办批量的静态兼容目录共享 `oa.missed_punch.approve`，
提交反向目录继续明确指向单条补签准备入口。两个批量的能力 Schema 不同，不能因旧目录值相同而合并。
通用批量实际仍由 `_pending_batch_definition` 按冻结的当前条目选择真实流程，复核能力版本、权限和治理规则，
并注入 `batch_id`、`affair_id` 上下文；绝不把静态补签 fallback 当成所有批量条目的固定业务。
通用批量没有独立固定的 `CAPABILITY_PERMISSIONS` 映射，保留现有动态逐项权限规则。

## 不变的执行边界

- 用户字段和目标绑定、初次预检/动态字段与恢复时点保持。
- 字段提交、独立授权、业务复核及权威回读保持；不增加业务权限。
- 取消、技能撤权、计划提交标记与授权消费沿用原 SQLite 事务；不移动中央执行编排。
- 批量每项独立授权，拒绝、失败、未知结果停止批次；同授权和同/不同幂等键不能重放业务写。
- 旧授权、旧批量入口及没有准备能力字段的历史恢复保留原反向映射。
