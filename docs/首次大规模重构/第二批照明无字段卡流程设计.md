## 范围与原有合同

| 流程 | 准备 / 提交能力 | effect | 原有行为 |
| --- | --- | --- | --- |
| 提交工区 | `smartlight.alarm.work_area.submit.prepare` / `smartlight.alarm.work_area.submit` | `reversible_write` | 核对等级、工区与可操作状态，冻结目标，授权后提交及回读；撤回须另行授权 |
| 撤回工区 | `smartlight.alarm.work_area.revoke.prepare` / `smartlight.alarm.work_area.revoke` | `reversible_write` | 已提交目标缺少工区名称仍可撤回；重新提交须另行授权和复检 |
| 处置告警 | `smartlight.alarm.dispose.prepare` / `smartlight.alarm.dispose` | `controlled_write` | 明确不可撤销，授权后处置，回读状态 3；无回滚入口 |

六项能力版本均为 `0.1.0`、adapter 为 `smartlight-central`，准备只接收必填 `alarm_id`，
提交只接收必填 `authorization_id`，禁止额外属性，输出保持对象 Schema。
三个写目录均为 `field_schema=None`、`context_fields=(alarm_id,)`，并且没有 `field_message` 键。
流程读取并冻结目标后直接生成授权卡，不新增填写步骤。原 workflow、提示原文、scope、用户权限、MCP 可见性和规划映射保持原值。

保留全部准备与提交函数及共享 action helper，权限复核、会话绑定、授权消费、取消/撤权事务和执行边界不移动。
保留 RTU 绑定与前置状态复检；目标已达到预期状态时仍消费授权、返回 `already_completed`，不重复下游写入。
修改后无法确认结果时仍记录未知，不自动重放。

## 类型声明最小扩展

`WriteWorkflowDefinition.field_message` 接受 `str | None`，保持字段和构造参数顺序，不新增默认值。
只有无字段卡时才允许显式 `field_message=None`；有字段卡时仍要求非空文本，授权提示始终为非空文本。
原来可接受的 `field_schema=None` 与非空字段提示组合继续兼容，避免引入无关构造限制。

`legacy_definition()` 在字段提示为 None 时完全省略 `field_message`，仍保留 `field_schema=None`。
其他声明保留原字段及顺序；不把缺键变成空字符串或值为 None 的键。能力和字段投影继续深复制，
不把 frozen dataclass 误写成嵌套字典完全不可变。

照明适配器新增三项声明：`SMARTLIGHT_ALARM_WORK_AREA_SUBMIT_WORKFLOW`、
`SMARTLIGHT_ALARM_WORK_AREA_REVOKE_WORKFLOW`、`SMARTLIGHT_RTU_ALARM_DISPOSE_WORKFLOW`。
能力注册表和写目录由声明生成原形式，保留旧常量、函数别名、动态函数解析、目录顺序和白名单。
本批完成后照明现有四个写流程的静态声明均迁移；MCP、权限及规划仍使用原来源，继续以一致性回归保护。
