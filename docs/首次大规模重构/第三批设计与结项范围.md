# 第三批设计与结项范围

开始日期：2026-10-04。基线：`3aaa88d`。用户要求一次完成剩余工程，按已确定的两个开发包和一个结项包推进。
本文件记录实现约束，实际结果见[实施与结项记录](./第三批实施与结项记录-2026-10-04.md)。

## 任务状态与宿主契约

从 TaskHubStore 提取纯任务状态决策与公开结果投影，覆盖 Operation、Interaction、Plan、批次、终态命令及完成时间。
状态决定与 SQLite 写入分开组织，原事务、身份检查、取消锁、通知去重、历史修复和重启流程保留在存储层。
原规则可能包含特定兼容行为，例如新操作对旧终态的影响、登录交互与普通交互的映射，必须先固定旧样本再迁移。
通过旧实现差分和实库乱序序列验证取消、重复通知、重启、批次和计划状态，不把重构变成重新定义状态政策。

中央发布的传输恢复策略提取为显式合同，OpenClaw 与 Reference Host 各自实现并接入实际请求/续办调用点。
扩展现有跨语言向量，覆盖只读恢复、准备重试、提交不重放、续办就绪、已发 claim、取消和预算耗尽。
保留两宿主既有预算及相邻事务观察差异，向量明确各自策略；Reference Host 不导入中央业务实现。
中央只声明它实际拥有的协议策略，不新增仅供测试使用的宿主状态副本。

## 前端模块

Workspace 保留页面和业务编排入口，将请求/流式解析、生命周期、可信字段表单、卡片、结果及进度投影迁入 ES modules。
原有从 workspace.js 截取源码执行的 Node 测试改为直接导入实际模块；补充取消、身份切换、旧响应和计时器清理回归。
管理控制台同样拆出展示、请求、表单和生命周期模块，保持现有页面与权限规则。
管理端 GET 在切换视图后中止或拒绝过期结果；已提交写请求不重发，失效账户或表单不能接收其后续 UI 更新。
替换表单后旧提交不能清除错误或重置新表单按钮，重复提交由当前表单状态抑制。

静态模块纳入 wheel 与 Workspace 资源版本摘要。`.mjs` 明确返回 JavaScript MIME，未带版本的模块使用 no-store，
避免入口版本更新后仍载入浏览器长期缓存的旧依赖；已有其他版本化资源保持原缓存方式。
管理控制台继续使用 no-store。模块只依赖现有浏览器能力，不引入前端框架或外部 CDN。

生成的代码事实区块保持由现有脚本维护，代码功能、实际部署、自动化结果与真实业务验收分开表述。
结项记录逐项对应最初九项发现，给出交付及延期理由，不以文件变短或测试数量增加替代正确性证据。
