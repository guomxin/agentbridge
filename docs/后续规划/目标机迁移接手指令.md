# 目标机迁移接手指令

把下面整段交给 Mac 上、已打开 CLIExp 仓库的 Codex。先取得 Windows 提供的代码 commit 与私有包，不要求把本聊天完整复制过去。

> 请读取 `docs/后续规划/开发机与智能体宿主完全迁移方案.md`，接手 Windows 开发环境和 OpenClaw 宿主完全迁移。
> 已确定：OpenClaw 固定 2026.7.1；服务器不迁；代码从 GitHub 拉取；最终 Windows 关机后可独立开发、发布、运行宿主及签发证书。
> 先核对当前 commit 与 Windows 交接收据，检查 Mac 架构、依赖、内网连通性及迁移工具，再按 M0–M4 执行。
> Windows 导出的 plan、inventory、加密包、portable-ca 和私有交接收据放在仓库外。不要读取口令到聊天，不上传秘密，不覆盖现有本机配置。
> 如尚无最终包，可继续安装依赖、实现 Mac 发布/生命周期适配和非正式身份检查；不可启动正式渠道或占用生产反向转发。
> `scripts/migration/prepare.py stage` 只负责暂存，预检查通过不代表迁移完成。根据暂存配置生成 Mac 配置，重建插件依赖和源码链接。
> 源端 DPAPI 导出必须由原 Windows 用户执行；根 CA 在 Mac 使用加密 PKCS#8，禁止重新生成根 CA 冒充迁移。
> 在开始接管前核对 Windows 已停用 Gateway 自愈、Gateway 和反向隧道，并取得停机后最终状态包。同一正式渠道只运行一个宿主。
> 在现有用户授权的迁移范围内持续完成适配、测试和修复；系统登录、密钥口令、macOS 权限及缺失连接信息由用户在本机处理。
> 不创建业务记录作为默认测试，不重复提交未知结果的业务操作，不改用户权限；先验证只读、卡片和取消边界。
> 把阶段状态、实际命令、退出码和脱敏证据持续写入仓库外 `AgentBridgeMigration` 目录。失败从检查点继续，禁止用“已安装”替代真实验收。
> 完成后在 Windows 关机条件下验证版本、Workspace、Telegram、微信、多用户隔离、发布维护、CA 签发及重启/断网恢复。
> 保留未完成项目和阻塞原因，不宣称所有聊天/浏览器登录态已经自动恢复。完成迁移后再安排旧机退役。
