## Windows 清理清单

### PowerShell 和运维能力

基线的 PowerShell 文件全部位于 `scripts/`。实施时用 `git ls-files '*.ps1' '*.psm1' '*.cmd' '*.bat'` 重新核验清单，当前总数为 25，不能只删主发布脚本。

| 编号 | 待退出对象 | 承接或删除要求 |
| --- | --- | --- |
| W01 | `Publish-AgentBridge.ps1`、`Deploy-AgentBridge.ps1`、`Invoke-AgentBridgeValidation.ps1`；Environment、ReleasePreflight 模块 | 由 `scripts/agentbridge-native`、原生发布器和 Linux 事务承接；保留前驱兼容、验证收据、unit 哈希、固定候选与验收后推送顺序 |
| W02 | OpenClaw SelfHeal 安装、Guard、GatewayForeground、Restart；RestartPolicy 和 LifecycleLease 模块 | 保留 launchd 唯一管理、内容指纹、pending/baseline、预热和端口所有权；不能通过移除旧测试丢掉这些合同 |
| W03 | WorkspaceTunnel 安装、服务器安装和启动脚本 | 核验 Mac launchd 与 Linux SSH 配置覆盖客户端及服务器侧要求；严格 host key 和回环绑定保留 |
| W04 | 所有 `Test-AgentBridge*.ps1`、`Test-AgentHostCompatibility.ps1`、`Test-OpenClawGatewayWarmup.ps1` | 将仍有价值的业务中立断言对照到原生 acceptance、smoke 和 conformance；删除重复入口 |

原生脚本已有相应能力，不代表与每个 PowerShell 检查完全等价。删除前按实际断言逐项核对 TLS/readiness、备份恢复、版本、身份路由、双用户隔离、只读 smoke、宿主恢复与预热；缺失项先补原生实现。

## 执行和证据要求

定向验证先覆盖制品、发布事务、原生维护、PKI、会话、浏览器锁、报告恢复和文档；随后固定候选提交执行完整共享验证计划。迁移 Vite 输出目录时必须显式包含 MCP App 的 check/build，不能因默认 Full 未启用该选项而遗漏。

现有 Full 要求干净的已提交候选，收据绑定提交、输入哈希和制品；实现过程中可以先跑定向检查，不能把局部测试结果伪装成 Full 收据。完整运行可能包含浏览器依赖准备和前端构建，应在隔离验证环境完成。

每一批实施记录至少包括：候选 commit、改动范围、定向测试、Full 结果、wheel SHA256、外置配置审核状态、实际部署状态、回滚目标和未通过项。真实证据生成后另建带日期的验收记录，不在本清单预填“通过”。
