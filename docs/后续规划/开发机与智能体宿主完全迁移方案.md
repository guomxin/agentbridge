状态：2026-09-30 二次检查并补强源端覆盖、正式包门禁、收据、Mac 路径冲突保护和 GitHub 固定提交拉取；尚未执行目标机安装、正式导出或切换。

## 1. 已确定的目标

- Windows 开发机上的 CLIExp 开发、OpenClaw 宿主、发布维护和证书签发全部转到 Mac mini。
- 最终 Windows 关机后独立运行；Windows 只在迁移期间提供源数据及临时回退。
- Linux AgentBridge、业务数据、用户权限、账本、业务浏览器会话、服务器证书及服务器备份不搬迁。
- OpenClaw 固定 `2026.7.1`，本次不升级宿主。GitHub 提供代码，私有配置和宿主状态另行加密迁移。
- Windows 负责盘点、源端导出与传输；Mac 上的 Codex 负责目标机适配、执行与最终验收。
- 本方案覆盖 CLIExp 和相关开发/智能体环境，不等同于整台个人电脑的所有文件和软件搬家。其他项目、文档及个人资料必须另列清单，不能据此声称整机迁移完成。

盘点默认不递归跟随符号链接/Windows 目录联接，排除 node_modules、__pycache__、.git、.gitrepo、.venv，
每一遗漏都进入 inventory 或 manifest，链接记录真实目标。Git 元数据标记为历史未收录，不能当作可重装依赖；默认另收录 `.openclaw/workspace/.git`，其他必要仓库历史单独 add-source。
先检查原因再补计划；“排除”不等于“已经迁移”。
日志、历史备份、旧 token 配置可能仍在源目录，迁移包整体视为敏感文件，不上传 GitHub、不粘贴聊天。

9 月 30 日只读检查发现的插件项目依赖为 `@openclaw/codex@2026.7.1-1`、`@openclaw/perplexity-plugin@2026.7.1`、`@tencent-weixin/openclaw-weixin@2.4.6`。
以最终包 `source-evidence/runtime-paths.json` 和对应 package-lock.json 为准重新安装，不默认 latest。
`plugin-skills/browser-automation`、`plugin-skills/canvas` 是指向 Windows OpenClaw 安装目录的联接，应由同版本 Mac 安装重新建立。
盘点遵循 OPENCLAW_STATE_DIR、OPENCLAW_CONFIG_PATH、CODEX_HOME；环境仅记录变量名，缺失变量值由原启动器/私有配置或本机受控配置补齐，不输出到聊天。

## 5. Windows 端准备及最终导出

在原 Windows 用户的 PowerShell 中执行。所有输出放仓库外，不允许覆盖已有导出目录。

```powershell
$migrationPython = "$env:LOCALAPPDATA\AgentBridge\test-venv-py312\Scripts\python.exe"
$migrationRoot = "$env:LOCALAPPDATA\AgentBridge\migration\2026-09-30-snapshot"
& $migrationPython scripts/migration/prepare.py inventory --output $migrationRoot
if ($LASTEXITCODE -ne 0) { throw '盘点失败，停止后续步骤' }
```

先复核 `inventory.json` 和 `plan.json`：补充必要的外部插件、工作目录、未提交文件及本机环境设置。
plan 的每个 source 由唯一英文小写 label 和源目录/文件绝对路径组成；它是私有清单，不能提交公开仓库。
当前仓库外生产 profile 已在默认候选内，不能用仓库通用 systemd 模板覆盖。

CA 导出在本机交互终端进行；工具提示输入口令，使用密码管理器产生并保存高强度口令，不能把口令放在命令参数、环境变量、聊天或日志。

```powershell
& $migrationPython scripts/migration/portable_ca.py export-windows `
  --source "$env:USERPROFILE\.agentbridge\pki" `
  --destination "$migrationRoot\portable-ca"
```

这一步只读取原 DPAPI 根状态，校验公私钥匹配后输出加密 PKCS#8；不会修改原根 CA 或部署服务器证书。
把新目录注册到 plan，无需手改 JSON（工具也兼容 PowerShell 写出的 UTF-8 BOM）：

```powershell
& $migrationPython scripts/migration/prepare.py add-source `
  --plan "$migrationRoot\plan.json" --label portable-ca --path "$migrationRoot\portable-ca"
if ($LASTEXITCODE -ne 0) { throw 'CA 加入计划失败' }
& $migrationPython scripts/migration/prepare.py check-plan `
  --plan "$migrationRoot\plan.json" --report "$migrationRoot\plan-check.json"
if ($LASTEXITCODE -ne 0) { throw '计划核验失败' }
```

其他文件也用唯一 label 执行 add-source。逐项复核报告中的 omitted 和 missingFinalLabels；不能只看退出码。
DPAPI 密文可作原机回退存档，但不能作为 Mac 的可用根私钥。CA 口令和迁移包口令是两个独立提示，应分别保存；即使使用同一高强度口令，也必须明确知道两处用途。

导出准备快照可在不停宿主时进行，但不得当作切换用一致性快照。**最终包必须在确认任务收敛、停止旧 Gateway 及可能写源状态的进程后生成**；
SQLite/WAL、会话文件及渠道状态不能从持续写入的目录拼成所谓完整备份。只校验单文件稳定不能证明跨文件事务一致。

```powershell
& $migrationPython scripts/migration/prepare.py export `
  --plan "$migrationRoot\plan.json" `
  --kind snapshot --output "$migrationRoot\host-snapshot.abmac"
if ($LASTEXITCODE -ne 0) { throw '准备快照导出失败' }
```

准备包自动标记 snapshot，不允许用 `--require-final` 暂存为正式切换包。每个包自动生成同名 `.receipt.json`，记录 SHA256、源 commit、计划哈希和时间。
加密包先写 `.partial` 再以不覆盖方式发布，使用本机 NTFS/APFS 等支持硬链接的目录生成，再复制到移动盘；中断的 partial 不能当成正式包。

完成 Mac M0–M2 后才进入停机窗口。保存旧任务启用状态作为回退依据，禁用并停止 `AgentBridge OpenClaw Guard`、`AgentBridge Workspace Tunnel`、`OpenClaw Gateway` 三个现有任务；
使用现有 `scripts/Restart-AgentBridgeOpenClawGateway.ps1 -StopOnly` 停宿主，检查是否仍有旧隧道子进程，不能批量杀掉所有 node/ssh。
停止后运行只读检查：

```powershell
& $migrationPython scripts/migration/prepare.py check-quiesced
if ($LASTEXITCODE -ne 0) { throw '旧机未完全停止，不能导出正式包' }
```

将 `$migrationRoot` 改为新的 `2026-09-30-final` 目录，重新 inventory；重新加入已导出的 portable-ca 目录和审核过的补充 source，运行 check-plan。
最终盘点的代码 commit 必须与最终运行代码一致；如果后续有新提交，重新盘点，不能复用旧 source-evidence。

```powershell
& $migrationPython scripts/migration/prepare.py export `
  --plan "$migrationRoot\plan.json" --kind final --writers-stopped `
  --output "$migrationRoot\host-final.abmac"
if ($LASTEXITCODE -ne 0) { throw '正式包导出失败，不得接管' }
$bundleSha = (Get-FileHash "$migrationRoot\host-final.abmac" -Algorithm SHA256).Hash.ToLower()
& $migrationPython scripts/migration/prepare.py verify `
  --bundle "$migrationRoot\host-final.abmac" --expected-sha256 $bundleSha --require-final
if ($LASTEXITCODE -ne 0) { throw '正式包解密验证失败，不得接管' }
```

正式导出强制检查必需目录、CA 与原根及导出收据一致、源证据 commit 一致，并在读取前后检查旧任务、Gateway/隧道进程和监听，以及整个文件树是否变化。
`--writers-stopped` 表示操作者还核对了其他写入方，不能代替真实停机；比如 Codex 正在编辑源配置/Skills 时仍需协调停止这些写入。

工具使用 Scrypt 派生密钥和 AES-256-GCM，先在内存组成归档，再写加密文件；无明文临时 ZIP。
上限为源文件总计 1 GiB，超过则失败，需拆成分别审核的计划；内存需求高于包大小，不承诺内存绝对清零或操作系统交换区无副本。
文件在读取期间变化则失败；失败不要自动停止业务，先查原因、在正确时点重做。
记录包 SHA256、源 commit、导出时间及 Windows 停机时间，私下传递给 Mac。跨机再次核对收据的哈希，不仅依赖同一下载目录内的文件名。

## 6. Mac 执行顺序与阶段门槛

### M0：建立接手环境

用户完成 Mac 初始设置和 Codex 登录。准备 Git、Python 3.12、匹配的 Node，使用 macOS 自带的 zsh、OpenSSH、launchctl 和 plutil，保持机器可访问原内网服务器。Mac 不安装或依赖 PowerShell；本文 PowerShell 命令只用于原 Windows 源端导出。
GitHub SSH 身份未配置时可用仓库 HTTPS 地址拉取代码，之后再配置正式 SSH 身份。

```bash
set -e
mkdir -p "$HOME/Codes"
git clone https://github.com/guomxin/cli-helper.git "$HOME/Codes/CLIExp"
cd "$HOME/Codes/CLIExp"
# 将下面值替换为本次复核后 Windows 交接收据中的完整 40 位 commit。
MIGRATION_COMMIT='填写本次迁移提交的完整40位哈希'
python3 scripts/migration/fetch_code.py --destination "$HOME/Codes/CLIExp" --commit "$MIGRATION_COMMIT"
# 上一步必须成功；工具会 fetch 并核对准确提交，不覆盖本地修改。
git rev-parse HEAD
python3.12 -m venv .venv
.venv/bin/python -m pip install -e .
```

GitHub 是代码来源，私有包不含整份 CLIExp。已有克隆时跳过 clone，直接运行 fetch_code.py；如果有未提交内容或本地独有提交，先保护已有工作，不 reset/clean。
拉取后处于 detached HEAD 以固定基线。Mac 开始编写适配前建立工作分支；正式发布仍按现有 main 发布策略整合改动，不从错误分支强行跳过门禁。
本次复核提交替代旧的 `5e1e8a9` 准备版本，不能继续使用昨天的工具命令。

Mac 架构、依赖 wheel 和 Node 安装在目标机验证；不得直接复制 Windows venv/node_modules。
按[Mac 接手指令](./目标机迁移接手指令.md)继续，认证与系统权限界面由用户在本机完成。

### M1：恢复到暂存区

先比对加密包 SHA256，再由用户在 Mac 交互终端输入口令：

```bash
set -e
BUNDLE_SHA256='填写Windows收据中的64位SHA256'
.venv/bin/python scripts/migration/prepare.py stage \
  --bundle "$HOME/Downloads/host-snapshot.abmac" --expected-sha256 "$BUNDLE_SHA256" \
  --destination "$HOME/AgentBridgeMigration/staged-snapshot"
```

M0–M2 使用 snapshot；完成适配并收到 final 后，换用正式包的 SHA256 和全新 `staged-final` 目录，并增加 `--require-final`。
不能在旧暂存目录上覆盖恢复。为避免路径变化，Mac 配置生成器应以指定暂存根为参数，在最终包上重新生成 Mac 配置。

暂存工具先认证整个加密包，检查路径、成员列表及每个文件哈希，再写入全新的受限目录；不覆盖 `.openclaw`、`.ssh` 或 Codex 目录，也不启动服务。
暂存文件统一采用受限权限，不保留 Windows ACL 或可执行位；Mac 安装时对已审核启动脚本恢复执行权限，不能对整个私有目录递归开放权限。
检查 manifest 的 omitted 清单。若解密失败不生成目标目录；磁盘写入失败可能留下不完整暂存区，复核后改用新的目录重试。
保留 Windows 原始配置，生成单独 Mac 配置，不对整个会话历史做盲目字符串替换。

### M2：目标机适配

必须逐项完成，不能以预检查通过替代：

1. 显式 `npm install -g openclaw@2026.7.1`，核对 `openclaw --version`。禁止安装 latest 或自动升级；检查现有升级设置。
2. 重装渠道插件和本地插件的相同版本，重建 AgentBridge 插件链接，保持用户绑定、Gateway 鉴权和服务端既有信任关系。
3. 将工作目录、插件路径、SSH 配置、`NODE_EXTRA_CA_CERTS`、模型代理及发布 profile 改为 Mac 路径；核对服务进程真正继承环境。
4. Windows 的 gateway.cmd/vbs、计划任务、CIM 进程检测不能运行在 Mac；按固定 OpenClaw 版本实际 CLI/安装内容适配 launchd。
5. 为 Mac 实现 Python 发布、部署与验收入口，必要的终端入口使用 Shell；宿主与隧道由 launchd 管理。不通过 pwsh 调用旧 `.ps1`，也不以安装 PowerShell 作为兼容方案。Windows 现有脚本保留用于源端运行和迁移回退；Mac 入口必须保留现有提交/远端校验、验证收据、发布门禁、条件重启和恢复验收语义。先实现只读计划模式，再做批准范围内的必要发布验证。原生入口尚未实现、验收前，不宣称发布维护已迁移。
6. 安装根证书信任并配置 Node 的 CA 路径，HTTPS 正常验证；不得关闭证书校验。
7. 使用 portable_ca.py 的 verify、issue 命令测试同一根 CA 在 Mac 签发能力；测试输出保留仓库外，不替换线上证书。
8. Codex 配置按平台适配；插件重新安装/连接。历史聊天单独保留源备份，能否导入以应用验证为准，不能承诺聊天 UI 原样恢复。

```bash
ROOT_CA_SHA256='填写Windows原CA导出收据中的64位根证书指纹'
.venv/bin/python scripts/migration/portable_ca.py verify \
  --root "$HOME/AgentBridgeMigration/staged-snapshot/portable-ca" --expected-sha256 "$ROOT_CA_SHA256"
.venv/bin/python scripts/migration/portable_ca.py issue \
  --root "$HOME/AgentBridgeMigration/staged-snapshot/portable-ca" \
  --server-ip 192.0.2.1 --days 1 --output "$HOME/AgentBridgeMigration/ca-test"
.venv/bin/python scripts/migration/mac_preflight.py \
  --output "$HOME/AgentBridgeMigration/preflight-01.json"
```

CA 每次签发由用户交互解锁，私钥以加密 PKCS#8 保存并配合受限权限；不把根私钥口令交给 Gateway。
这已支持完全脱离 Windows 签发，不要求为了无人值守而把 CA 口令写入脚本。若改用 macOS 钥匙串，另行实现并验证。

### M3：切换

准备阶段不可用正式身份启动第二份 Telegram/微信接收器或抢占服务器回环 18789。
先完成 Mac 环境准备，再安排源端最终停机与导出；若先传了准备快照，必须重新恢复最终包的最新状态。
停用 Windows 自愈任务及隧道，防止旧机自动抢回。核对服务器旧转发已退出，再让 Mac 建立同一个回环反向映射。
新隧道保留 `ExitOnForwardFailure`、BatchMode、host key 验证和 SSH keepalive；不向服务器公网绑定 Gateway。
只启动一套 macOS 进程管理器，避免 launchd 与额外 guard 重复拉起同一 Gateway。

## 7. 回退

若 Mac 接管失败：先停止 Mac 正式渠道和隧道，核对无继续受理/业务提交，再恢复 Windows 原配置、Gateway 和隧道。
旧机只作为迁移期间回退。Mac 已接收新消息后不能盲目覆盖回旧状态；先对账中心任务、渠道进度和新会话，未知提交结果只核查不重放。
最终通过前不清空 Windows，不撤销全部原密钥。通过后再单独处理临时加密包、旧机凭据与退役，保留必要恢复备份。
