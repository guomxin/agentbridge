# AgentBridge 固定发布入口

唯一发布入口为 `scripts/agentbridge-native publish`，完整参数和私有配置要求见[苹果系统原生维护](./苹果系统原生维护.md)。默认生成计划，`--apply` 执行。纯文档修改只做文档检查，不部署或重启服务。

## 发布前

1. 候选整合到本地 main，工作区干净；detached checkout 必须精确指向本地 main。
2. 核验 origin 的 fetch 和 push 地址。目标仓库为 `guomxin/agentbridge`，过渡期精确接受旧名，拒绝其他仓库。
3. 核验 `deploy/release-policy.json` 的线上前驱和数据兼容声明，不放行未知版本。
4. 复核外置 environment profile、unit 哈希、SSH 身份、可信 host key、宿主 profile 及授权。
5. 固定提交完成 Full；wheel 从 Git archive 构建并隔离安装，不能由未提交工作区重建替代。

## 切换与验收

Linux 事务建立独立 Release/venv，验证制品、依赖、包资源和 unit，创建恢复点后切换 `current`，检查服务稳定性，再完成备份 timer 与发布后备份。不要向运行中的 venv 安装新版本。

随后验证 TLS/readiness、MCP、当前 Release、宿主实际加载版本、插件注册、服务器回环转发与双用户隔离。任一步失败不推送。中央 Python 改名不自动要求重启 OpenClaw；宿主按实际内容指纹决定。

`--resume` 使用同一候选、原收据与已保存的事务完成剩余验收。它不能绕过候选校验、重新部署、重放业务操作或恢复旧数据库。失败后先检查事务状态，见[独立版本发布与回退](./独立版本发布与回退.md)。

## 命名迁移注意事项

主服务和备份 unit 必须同步切换到 `python -P -m agentbridge` 或 `agentbridge.cli.main`；回滚需恢复与旧 wheel 匹配的旧 unit。服务器显式 `--home .../data` 保持不变。

修改源码目录、旧默认数据目录和宿主授权分别核验，不将它们混成一次文件替换。历史发布方法见[原流程快照](../历史归档/平台迁移/发布操作手册旧版-2026-10-09.md)。
