# AgentBridge 固定发布入口

唯一发布入口为 `scripts/agentbridge-native publish`，完整参数和私有配置要求见[苹果系统原生维护](./苹果系统原生维护.md)。默认生成计划，`--apply` 执行。纯文档修改只做文档检查，不部署或重启服务。

## 发布前

1. 候选整合到本地 main，工作区干净；detached checkout 必须精确指向本地 main。
2. 核验 origin 的 fetch 和 push 地址。目标仓库为 `guomxin/agentbridge`，过渡期精确接受旧名，拒绝其他仓库。
3. 核验 `deploy/release-policy.json` 的线上前驱和数据兼容声明，不放行未知版本。
4. 复核外置 environment profile、unit 哈希、SSH 身份、可信 host key、宿主 profile 及授权。
5. 发布入口核验本机 `output/release-validation/full.json` 的阶段证据、固定提交与 wheel。默认复用同一候选的有效收据，缺少有效收据时运行 Full 并校验制品。源码、构建输入或工具环境变化时，以正式校验器的结果为准。旧候选收据不能用于新候选。

Full 的 Python 阶段按整份报告判定通过，发布器另行执行运行治理和备份两组测试，以确认这两组用例实际运行。只读预检可与 Full 并行。实际切换前仍须重新核对线上前驱、宿主身份和配置指纹。

## 切换与验收

Linux 事务建立独立 Release/venv，验证制品、依赖、包资源和 unit，创建恢复点后切换 `current`，检查服务稳定性，再完成备份 timer 与发布后备份。不要向运行中的 venv 安装新版本。

随后验证 TLS/readiness、MCP、当前 Release、宿主实际加载版本、插件注册、服务器回环转发与双用户隔离。任一步失败不推送。中央 Python 改名不自动要求重启 OpenClaw；宿主按实际内容指纹决定。

OpenClaw 换插件归档需要先停机时，依[原生维护](./苹果系统原生维护.md#宿主配置)生成本次候选绑定的维护停止收据，备份后原子替换受审配置。正式发布显式传 `--gateway-maintenance-receipt` 才能在中央事务成功后恢复这次已确认未加载的 Gateway；普通人为禁用不会被发布器自动解除。该模式不与 `--resume` 或单宿主回退混用。启动结果未知时保留阶段并核对现场，不能自动重新启用；远端部署尚未发起前可核对备份恢复原配置并用原授权 `host start` 恢复，已发起或未知时先核对中央事务，不自动启动旧插件读取新账本。

事务成功后，从受影响的真实入口做线上只读复验。发现生产回归时按影响修复补发或回退。

`--resume` 使用同一候选、原收据与已保存的事务完成剩余验收。它不能绕过候选校验、重新部署、重放业务操作或恢复旧数据库。失败后先检查事务状态，见[独立版本发布与回退](./独立版本发布与回退.md)。

## Pi 原版本恢复

初装或受管重签撤回后，若中央仍运行同一已发布版本，可用 `scripts/agentbridge-native publish --restore-pi-from <旧版源码目录>` 单独恢复 Pi。先沿用旧部署审核的环境、SSH 身份、可信主机指纹、宿主授权和 Pi profile 执行在线计划；确认计划里的 commit、中央制品、Pi 事务及 GitHub main 后，再对同一组参数追加 `--apply`。旧 clone 应独立、干净，并在原解释器路径上完成自己的正式 Full。该模式与 `--resume`、`--offline`、其他回退标志互斥。

恢复入口依据可信 Git 树逐文件复核旧 checkout，并在线确认 GitHub main 等于该版本或仅追加文档。它用中央 active Release 的完整 commit、manifest 和保留 wheel 的原摘要对照 Mac 原归档与历史资格。若重新构建的 wheel 仅封装时间不同，逐成员比较名称、文件类型、权限及解压内容，包含 `RECORD`。旧版本的归档启动探针重新使用原始 wheel 完成隔离双身份实测。

执行阶段复核原 Pi 的 `rolled_back` 事务、原归档、关闭的作用域和两名主体的原凭据链，再由同版本 Pi 原生接纳逻辑重新签发。已确认的同版本走就绪与双身份复核。恢复仅操作该 Pi 宿主及其已审核作用域，中央版本和 GitHub main 保持当前值。发布处于中断的 `switching` 或 `restoring` 时先核对原事务和回退记录。收据分别保留线上原 wheel 和本次 Full 重建 wheel 的摘要。

## 命名迁移注意事项

主服务和备份 unit 必须同步切换到 `python -P -m agentbridge` 或 `agentbridge.cli.main`；回滚需恢复与旧 wheel 匹配的旧 unit。服务器显式 `--home .../data` 保持不变。

修改源码目录、旧默认数据目录和宿主授权分别核验，不将它们混成一次文件替换。历史发布方法见[原流程快照](../历史归档/平台迁移/发布操作手册旧版-2026-10-09.md)。
