当前开发与本机宿主使用 macOS，中心服务与 CI 使用 Linux；Windows 任务计划和 PowerShell
维护材料保留历史含义，不再作为日常操作入口或后续开发验收条件。

## 1. 运行拓扑

```text
Telegram / 微信 / Agent Workspace
                |
                v
        OpenClaw 2026.7.1（macOS）
                |
                | HTTPS MCP / Task Hub
                v
AgentBridge（Linux 10.10.50.213）
  |- 8780 可信卡片
  |- 8781 noVNC 网关
  |- 8782 管理控制台
  |- 8783 Agent Workspace
  `- 8790 Streamable HTTP MCP
                |
                v
       OA / 泰华 / 语雀 / 照明系统
```

Agent Workspace 需要模型执行时，Linux 服务连接 `ws://127.0.0.1:18789`。该端口由 macOS
工作站主动建立的反向 SSH 隧道映射到本机 OpenClaw Gateway `127.0.0.1:18789`，不要求服务器
访问工作站当前局域网 IP。Gateway 与隧道统一由用户级 launchd 管理，配置、进程核验和恢复边界见
[原生宿主维护](./苹果系统原生维护.md#宿主-profile-与-launchd)。

## 3. 网络入口

| 地址 | 用途 | 调用者 |
| --- | --- | --- |
| `https://10.10.50.213:8780` | 可信登录、字段填写和授权 | 浏览器、Telegram/微信内嵌卡片 |
| `https://10.10.50.213:8781` | 按挑战开放的 noVNC | 可信卡片 |
| `https://10.10.50.213:8782` | 管理控制台 | 管理员浏览器 |
| `https://10.10.50.213:8783` | Agent Workspace | 普通用户浏览器 |
| `https://10.10.50.213:8790/mcp` | MCP | OpenClaw 或其他 MCP 宿主 |

所有固定入口使用内部 CA 签发、包含私网 IP SAN 的证书。客户端只安装根证书；内部 CA 私钥不
部署到 Linux。8781 的 RFB/CDP 后端只监听回环地址，没有活动挑战时不得存在可用浏览器路由。

## 4. 服务安全基线

- systemd 启用 `NoNewPrivileges`、`PrivateTmp`、`ProtectSystem=strict` 和 `UMask=0077`；
- 配置目录只读，数据目录是唯一持久可写区域；
- Linux 会话使用外部 32 字节密钥和 AES-256-GCM，不允许明文 Cookie 回退；
- 每个 MCP Token 服务端绑定 `userSubject`、允许系统、scope 和预期下游身份；
- 凭据、Cookie、Bearer Token、业务字段和卡片控制值不进入模型或普通聊天；
- Smartlight 当前目标地址为 HTTP，只有中心服务到指定目标的适配器被显式允许，不开放通用 HTTP 工具；
- 旧 Chrome 扩展、浏览器桥和 localhost daemon 不得作为故障回退路径。

## 5. 会话与保活

当前启动参数：

```text
--session-keepalive-interval 600
--session-keepalive-lease 604800
```

即每 10 分钟检查仍处于 7 天活动租约内的会话。用户登录和真实请求会更新活动时间，后台探测
本身不会无限延长租约。OA、泰华、语雀和照明系统各自采用适合下游的 Cookie、Token 刷新或
CAS/JWT 再签策略；下游明确注销、身份不匹配或不可恢复的认证失败会使会话过期并重新要求登录。

## 6. OpenClaw 基线

| 项目 | 当前值 |
| --- | --- |
| OpenClaw CLI/Gateway | `2026.7.1` |
| AgentBridge 插件 | 期望版本来自候选仓库 [package.json](../../integrations/openclaw-agentbridge/package.json)；实际加载版本由原生发布验收在线核对 |
| Gateway | macOS 本机 `127.0.0.1:18789` |
| AgentBridge MCP | `https://10.10.50.213:8790/mcp` |
| 可信卡 Origin | `https://10.10.50.213:8780` |

Gateway 与 Workspace 反向隧道使用用户级 LaunchAgent，label 分别为 `ai.agentbridge.gateway`
和 `ai.agentbridge.workspace-tunnel`。Gateway 前台运行且只监听回环地址；隧道使用固定 SSH 身份、
严格 host key 检查、keepalive 和服务器回环绑定。不得并行启动第二套进程管理器或强制抢占监听端口。

原生生命周期入口使用进程锁、输入指纹、PID/启动时间及 readyz 判断是否重启；插件、配置或启动环境
变化需要重新核对，纯文档变化不触发重启。重启保留 pending，冷/热预热通过后才清除。
用户级 launchd 提供登录后的运行恢复，不代表登出、FileVault 解锁前或断电恢复已通过验收。
`host status` 只报告作业状态，不能代替 Gateway RPC、当前进程插件注册与端到端链路检查。
具体命令、私有 profile 和交接证据要求见[原生宿主维护](./苹果系统原生维护.md#宿主-profile-与-launchd)。

Telegram、微信和 Workspace 通过插件的 `identityBindings` 映射到各自的 AgentBridge Token。
不得同时保留一个面向所有用户的共享 Bearer 工具面。详见
[多用户身份路由](../架构设计/智能体宿主多用户身份路由.md)。

## 7. 开发、发布与推送

日常验证使用 Python 3.12 原生入口，不需要 PowerShell：

```sh
scripts/agentbridge-native --help
scripts/agentbridge-native validate --test tests/test_native_maintenance.py --plugin
scripts/agentbridge-native validate --full
```

入口默认使用仓库 `.venv/bin/python`，也可显式设置 `AGENTBRIDGE_TEST_PYTHON`。依赖准备、
完整验证阶段与回执位置见[原生验证说明](./苹果系统原生维护.md#入口与验证)。定向测试不产生正式 Full 成功回执。

正式发布使用 `scripts/agentbridge-native publish`，默认仅生成计划。实际环境 profile、SSH 身份、
known-hosts、宿主 profile 和交接证据必须采用审核后的仓库外文件；身份标签与预期端点逐项指定。完整参数和
`--apply` 执行方式见[原生发布计划和执行](./苹果系统原生维护.md#发布计划和执行)。

发布要求干净固定候选和准确的前序兼容声明；完成或严格复用同一候选 Full 回执及 wheel，执行治理验证，
部署版本化 Release 和受控 systemd unit，再按输入变化决定宿主重启与预热。在线验收通过后才推送
`origin/main` 并回读精确提交。`--resume` 同样核对原候选和回执，不能跳过验收；失败不推送。
GitHub `repository-validation` 在推送后异步运行，不持有生产凭据，也不代替本地发布门禁。

只改文档且不影响运行时、服务 unit、部署脚本或配置时，不需要重启或重新部署 AgentBridge；仍应
运行文档链接检查和相关测试，再提交并推送。

## 8. 健康检查

原生发布执行在线验收，现行 CLI 没有独立的 `acceptance` 子命令。执行方式及恢复限制见
[原生发布手册](./苹果系统原生维护.md#发布计划和执行)，不要用 `host status` 替代完整验收。
验收须核对：

- MCP 必需工具存在；
- 8782、8783 就绪端点返回 `ready`；
- systemd 为 `active` 且 MainPID 有效；
- 每日备份 timer 已启用，最近备份服务成功且清单可校验；
- 线上 Release 与预期提交一致；
- 最近 30 分钟服务错误计数已核对，确认没有新增异常；不能仅凭脚本返回成功推断错误计数为零；
- OpenClaw CLI 与 Gateway 版本一致，插件为 `loaded`、版本匹配仓库且当前 Gateway 有注册证据；
- 服务器回环转发 ready，Gateway 无未完成的预热记录；
- 指定身份隔离时，至少两个真实用户连续两轮 OA 会话 active、身份稳定且不重叠，预期渠道端点及账本隔离检查通过。

带日期的发布与治理结果进入[验收记录](../验收记录/验收记录导航.md)，不在现行运行手册中固定
某次提交。MCP `Release` smoke 仅检查必需工具目录，不调用业务工具，也不验证各下游登录有效性。
身份隔离使用 OA 会话状态实时探测，不发起新的登录卡或业务提交；它可能保存会话状态、更新活动时间
或将失效会话标记过期。OA 验证失败仍须停止发布收尾，不能用其他系统的延期验收代替。
真实业务操作、照明登录与图片上传须分别验收，不能由发布 smoke 成功推断已完成。

## 9. 运行治理与备份

运行 Trace、Span、Signal、Incident、恢复动作和 24 小时试点 SLO 保存在同一运行数据库中。
独立治理周期每 60 秒执行事件评估和汇总，不依赖某个下游系统的会话保活周期。

`agentbridge-backup.timer` 每日使用 SQLite 在线备份 API 生成数据库备份和 SHA-256 清单，默认
保留 30 天。备份校验检查哈希、数据库完整性、必要表和用户主体关联隔离；隔离恢复演练会复制
最新备份、只读打开并证明写入被拒绝。运行治理还支持按小时快照和按日汇总的七天影子观察。详见
[运行治理操作手册](./运行治理操作手册.md)。

## 10. 故障恢复

1. 先分清是 AgentBridge、OpenClaw、SSH 隧道、目标系统还是用户会话故障。
2. AgentBridge 代码或受控参数变化按原生发布流程重新核验候选、配置与兼容声明，再切换并验收。
3. Workspace 能同步历史但不能发起新任务时，优先检查反向 SSH 隧道和 OpenClaw Gateway RPC。
4. 单一用户登录失效时只重建该用户、该系统会话，不清理其他用户会话。
5. 写操作返回 `unknown` 时停止自动重试，先通过权威列表或详情对账。
6. 发布失败时保留上一版本制品与失败证据，先按[原生发布手册](./苹果系统原生维护.md#发布计划和执行)核对可恢复状态；程序回退须遵守[独立版本发布与回退](./独立版本发布与回退.md)的兼容与数据保护要求。
