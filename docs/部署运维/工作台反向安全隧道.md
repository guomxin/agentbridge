# 工作台反向安全隧道

Mac 宿主主动通过 SSH 建立服务器 `127.0.0.1:18789` 到本机 `127.0.0.1:18789` 的反向转发。Linux Workspace 使用服务器回环地址连接 OpenClaw，不依赖工作站局域网地址。Gateway 保持 Token 认证和设备配对。

## 配置与管理

隧道由 `ai.agentbridge.workspace-tunnel` 用户级 launchd 作业管理，Gateway 由独立的 `ai.agentbridge.gateway` 管理。配置来源为私有 mac-host profile，详见[原生维护](./苹果系统原生维护.md)。

SSH 固定 `-F /dev/null`、BatchMode、IdentitiesOnly、StrictHostKeyChecking、ExitOnForwardFailure、10 秒 keepalive 与两次失败阈值。身份和 known_hosts 必须显式提供，不使用隐含 ProxyCommand 或额外转发。

```sh
scripts/agentbridge-native host status --kind tunnel --profile /私有目录/mac-host.json
scripts/agentbridge-native host start --kind tunnel --profile /私有目录/mac-host.json --authorization /私有目录/authorization.json
scripts/agentbridge-native host stop --kind tunnel --profile /私有目录/mac-host.json
```

服务器 SSH 策略参考仓库 `deploy/ssh/agentbridge_workspace_tunnel_sshd.conf`，实际配置须由运维核验。不能为解决冲突扩大监听地址或放宽 host key 校验。

## 验收与恢复

本机检查 launchd、Gateway PID/监听所有权和 `/readyz`；服务器检查回环转发的 `/readyz`；最后从 Workspace 发起只读请求验证真实通路。单独的 `host status` 不证明端到端链路可用。

断线由 launchd 和 SSH 重建连接；服务器端口被其他实例占用时转发失败，不抢占未知监听者。停用作业会 disable 后 bootout，避免下一次登录自动恢复。数据时间线和中央会话不因隧道暂时不可用而删除。

既有 Workspace 设备身份位于服务器持久数据内，正常服务重启不需重新配对。历史工作站实现见[原隧道流程快照](../历史归档/平台迁移/工作台反向安全隧道旧版-2026-10-09.md)。
