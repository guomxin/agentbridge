# 命名迁移与证书维护

AgentBridge 0.2.0 使用 `agentbridge` 分发包、导入包和命令。`bscli` 与 `python -m bscli.cli.main` 仅作为薄转发入口保留到 0.3.0，弃用信息只进入 stderr。任意 `bscli.*` Python API 不再兼容。

## 安装和源码路径

从可信源码或经核验 wheel 在新虚拟环境安装，检查 `importlib.metadata.version('agentbridge')` 与实际模块位置。不要保留旧 `cli-helper` editable 安装来测试新命名，也不要根据产品名从公共索引下载未经核实的同名包。

GitHub 仓库名与本地源码目录互相独立。已有 `CLIExp` 目录可继续使用；移动前核验插件源码链接、IDE 工作区、私有配置和虚拟环境绝对路径。迁移后重建 venv，不直接搬动其中的启动脚本。

## 默认业务数据

新默认目录是 `~/.agentbridge`。如果 `~/.bscli` 存在，新旧命令都会要求显式 `--home`，不会自动创建空环境。继续使用旧目录时：

```sh
python -m agentbridge --home "$HOME/.bscli" capability list
```

生产服务已有显式 `--home .../data`，不需要搬迁数据。对已有本地数据，先停止全部写进程、生成一致备份并验证；识别 SQLite、Profile、会话和附件中的绝对路径，完成必要适配后再切换。`~/.agentbridge/pki` 的存在不表示业务目录已迁移，两边都有数据时不可自动合并或覆盖。

更名只是可选的本地整理，显式指定旧路径可完整保留既有状态。没有完成路径审查和恢复演练时继续使用 `--home`，不要直接对运行目录执行批量替换。迁移后有新写入时，不得用旧快照直接覆盖回滚。

## 既有 CA 验证和签发

正常 PKI 使用既有 `root-ca.crt` 和加密 PKCS#8 `root-ca.encrypted.pem`，与已导出的可移植 CA 格式一致。根密钥仅在受控离线管理环境读取，口令通过本机隐藏输入，不进入参数、环境变量或日志。

```sh
python -m agentbridge --home /已审核业务目录 pki verify-root \
  --state-dir /私有目录/portable-ca --expected-sha256 <已审核根指纹>
python -m agentbridge --home /已审核业务目录 pki issue-server \
  --state-dir /私有目录/portable-ca --expected-sha256 <已审核根指纹> \
  --ip 192.0.2.1 --output-dir /私有目录/新叶证书
```

命令验证根和密钥匹配、自签名、有效期、文件权限与指纹；错口令、缺材料、明文私钥或符号链接均拒绝。签发只输出叶密钥、叶证书、公有根副本及清单。正常续签不会创建新根。只有明确建立新环境时才使用 `pki init-root --state-dir /全新目录`，不能用它修复旧 CA 丢失。

旧平台加密原件只留作历史材料，当前版本没有旧平台解密和导出实现。已有私有原件不随代码清理删除。
