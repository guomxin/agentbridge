# 独立版本发布与回退（M3）


本页适用于 `scripts/agentbridge-native publish`，私有环境 profile 和宿主授权参数见[原生维护](./苹果系统原生维护.md)。默认计划，`--apply` 执行，`--resume` 只续接已确认候选。中央程序采用独立版本环境，纯文档不部署。

## 正常发布

1. 核对目标服务器当前 `config/release.env`；在 `deploy/release-policy.json` 的 `compatibleFrom` 填写本次已审查的前一运行版本。`dataCompatibility=no-migration` 表示没有数据库结构或旧程序不兼容的数据语义变更；不能为了绕过检查而填写。
2. 提交本次改动，运行 原生发布入口（不加 `--apply`，但也不加 `--offline`）。该入口在全量测试前通过 SSH 只读获取线上版本，核对兼容声明；不匹配、无法读取或补验收目标不是当前版本时立即失败。计划输出包含 `releasePreflight` 的线上/候选版本和结果。确认 OpenClaw 是否需要重启及原因，再运行固定发布入口。此预检查不代替部署锁内的最终复核，防止等待测试期间线上版本改变。发布仍必须使用 M1 全量验证对应的同一个 wheel。
3. 新版本安装到 `releases/<commit>/venv`，旧服务继续运行。新环境完成依赖、编译、资源加载、模块来源和 systemd 单元检查，记录实际依赖版本。
4. 暂停备份定时器，等待已启动备份结束，然后停止中央服务。使用旧程序创建并验证 M2 四库恢复点；失败则恢复旧服务，不切换版本。
5. 原子替换 `current` 指针，更新单元和版本标识，启动服务。验证实际进程环境以及 Admin、Workspace 就绪状态，核对四库结构未变后确认中央切换；随后恢复备份定时器并执行一次备份。
6. 原有发布入口继续 MCP、运行治理及 OpenClaw 验收，通过后推送 GitHub。中央切换已确认但后续验收超时时，用 `--resume` 补验收；入口自动复用完整收据，不重新验证或部署。

停服发生在安装和离线检查之后，包含恢复点创建和新服务启动时间；这不是零停机部署。业务数据库不会因为程序回退而自动恢复旧快照。

## 保留的证据和环境

每个版本目录保留 wheel、`artifact.json`、`validation.json`、独立 `venv`、`deployment.json` 阶段记录、`transaction.json` 输入、发布执行器 `release.py`、新单元和 `previous/` 旧单元/版本标识。`deployment.json` 记录前一版本、恢复点路径、结构快照、失败原因与回退结果。

`current` 指向已启用版本。第一次迁移前的根目录 `venv` 保留，它还是原始回退环境和 209 受限备份导出命令所用解释器；不要删除或更新它。中央服务、定时备份和随发布执行的隔离诊断使用 `current/venv`。当前不自动清理历史版本，以免删除唯一可用的旧环境。

## 失败处理

| 发生位置 | 行为 |
|---|---|
| 安装或离线检查失败 | `preparation_failed`，旧服务不停止；修复后用新的已提交版本重试 |
| 恢复点创建失败 | 恢复旧服务和原定时器，标记 `rolled_back` |
| 切换或健康检查失败且结构未变 | 恢复旧指针、单元和版本标识，验证旧服务；标记 `rolled_back` |
| 结构发生变化或旧服务无法恢复 | 标记 `manual_recovery_required`，禁止自动恢复数据库或反复启动 |
| 中央版本确认后备份或外层验收失败 | 保持已确认程序，检查失败项并补验收；不自动回退已接收业务的新服务 |
| SSH 中断、进程被杀或服务器掉电 | 持久阶段记录保留；后续发布拒绝越过未结束事务，须先检查现场 |

程序回退有两个前提：本次已审查的前一版本明确列入兼容契约，且四库 SQL 结构及 `user_version` 未变。结构不变不能证明数据语义兼容，因此契约审查仍是必需项。涉及数据迁移的发布目前会被此流程拒绝，必须另行设计、审查迁移和恢复方案。

## 中断后的受控恢复

管理员先读取对应版本的 `deployment.json`，同时检查 `current`、`config/release.env`、服务 PID/状态和备份恢复点。不要删除阶段记录后强行发布。

确认需要结束该中断事务后，在 213 使用该版本保存的执行器与输入：

```bash
/home/guomao/agentbridge/venv/bin/python -I \
  /home/guomao/agentbridge/releases/<commit>/release.py --recover \
  /home/guomao/agentbridge/releases/<commit>/transaction.json
```

此命令使用同一发布锁。安装准备阶段只关闭记录，不改运行服务；停服或切换阶段尝试上述受兼容边界约束的旧程序恢复。它拒绝对 `confirmed`、`rolled_back`、`manual_recovery_required` 重放恢复。处于需要人工恢复的状态时，应先评估新版本已产生的业务数据，再按 M2 隔离恢复手册制定恢复操作；不能直接把快照覆盖到运行目录。

回退测试采用临时目录、真实 SQLite 和符号链接，注入安装、恢复点、健康检查及结构变化故障；服务管理命令被测试替身替代，不故意破坏生产服务。生产验收验证实际独立环境、真实恢复点、真实服务切换和完整只读验收。
