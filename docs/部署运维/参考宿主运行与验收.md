# Reference Host 运行与验收

## 一、用途和边界

Reference Host 是 AgentBridge 的确定性第二宿主和协议验收器，不是新的聊天产品。它只通过
远程 Streamable HTTP MCP 访问中央服务，不导入 `agentbridge` 业务模块，也不读取服务器数据库。

它用于验证：

- 同一远程 MCP 在非 OpenClaw 宿主中仍能发现并调用受权工具；
- 登录、字段填写和授权卡保持在模型循环之外；
- 一个任务只有一个协调 Lease 持有者；
- 多身份、任务时间线、Artifact、短时传输恢复和重启恢复不会串用户或重复执行；
- Reference Host 与 OpenClaw 使用同一 `agentbridge.host.v1` 契约。

一期的可信页面是受审计私有呈现器，并非官方 MCP Apps AppBridge，因此 Profile 明确声明
`mcpApps=false`。卡片仍由 AgentBridge 中央服务生成，Reference Host 只保存交互引用，不保存
密码、字段值或短期 URL。

## 二、安装

在仓库根目录执行：

```sh
python -m pip install -e ./integrations/reference-host
```

Reference Host 需要 Python 3.12 以上。Token 必须由环境变量、服务凭据或密钥管理器注入，不能
写入 JSON 配置、脚本、日志或命令行参数。

单身份示例：

```sh
export AGENTBRIDGE_REFERENCE_MCP_URL="https://10.10.50.213:8790/mcp"
export AGENTBRIDGE_REFERENCE_IDENTITY_LABEL="测试用户"
export AGENTBRIDGE_REFERENCE_TOKEN_ENV="AGENTBRIDGE_REFERENCE_TOKEN"
export AGENTBRIDGE_REFERENCE_TOKEN="<由安全环境注入>"
export AGENTBRIDGE_REFERENCE_HOST_INSTANCE_ID="reference-host-dev-01"
agentbridge-reference-host
```

多身份使用 `AGENTBRIDGE_REFERENCE_IDENTITIES_JSON`，每项只写 Token 所在的环境变量名：

```json
[
  {
    "label": "用户甲",
    "tokenEnv": "AGENTBRIDGE_REFERENCE_TOKEN_A",
    "endpointKey": "reference-host:user-a",
    "externalSubject": "reference-host:user-a",
    "conversationRef": "reference-host:conversation:user-a"
  },
  {
    "label": "用户乙",
    "tokenEnv": "AGENTBRIDGE_REFERENCE_TOKEN_B",
    "endpointKey": "reference-host:user-b",
    "externalSubject": "reference-host:user-b",
    "conversationRef": "reference-host:conversation:user-b"
  }
]
```

内网 CA 应通过 `AGENTBRIDGE_REFERENCE_CA_BUNDLE` 指向 PEM CA 文件。仅本机开发冒烟可以临时
设置 `AGENTBRIDGE_REFERENCE_ALLOW_INSECURE_TLS=true`，不得作为持久部署配置。

## 三、页面和访问控制

默认监听 `127.0.0.1:8791`。回环监听可以直接打开：

```text
http://127.0.0.1:8791
```

非回环监听必须设置随机 `AGENTBRIDGE_REFERENCE_UI_TOKEN`。首次通过
`/?access_token=<一次性引导值>` 建立 `HttpOnly`、`SameSite=Strict` 浏览器会话，之后地址栏不再
保留引导值。页面启用 CSP、`X-Frame-Options: DENY`、`no-store` 和同源 API。

页面只提供确定性工具调用，不运行模型：选择身份、选择该身份可见工具、填写 JSON 参数、查看
任务有序事件、打开可信卡、下载或重新生成文件。任务更新通过同源 SSE 到达。

## 四、状态和恢复

本地 SQLite 默认位于 `%USERPROFILE%\.agentbridge-reference-host\state.db`，只保存：

- 本地任务与中央 `taskId`、`endpointId`、Lease 版本；
- 脱敏时间线和非敏感结果摘要；
- 允许安全重放的只读参数；
- Artifact 和 Interaction 的不透明引用。

重启后只有相同 `hostInstanceId` 可以自动恢复自己持有的 Lease。另一宿主持有 Lease 时，任务进入
`observe_only`，不会自动接管或 resume。读取和 `prepare` 只在短时传输故障下有界恢复；可能跨过
副作用边界的调用不自动重试。

## 五、自动验收

共享 H01-H29 套件：

```sh
.venv/bin/python scripts/run_agent_host_conformance.py
```

它执行 Python 契约与 Reference Host 测试、OpenClaw 全量插件测试，并检查 Reference Host 源码
没有导入 `agentbridge`。JSON 报告写入 `output/host-compatibility/`。

完整项目回归：

```sh
python -m unittest discover -s tests
```

## 六、真实验收顺序

真实纵切只使用已开通的测试身份，并按风险递进：

1. 打开 Reference Host，确认身份为 `ready`、协商等级为 L3；
2. 执行 `oa_session_status` 或其他会话状态读取；
3. 执行一个有效会话下的只读工具，例如 OA 待办；
4. 查看管理端“运行状态”中的宿主登记、版本、最新健康和活动 Lease；
5. 让会话自然需要登录时，完成认证卡并确认原读取自动继续；
6. 对可重新生成的测试文件验证下载、到期展示和重生；
7. 停止并重启 Reference Host，确认等待任务恢复且未产生第二次业务调用；
8. 真实写入只在用户明确给出目标和授权后执行，另一个宿主不得同时推进同一任务。

## 七、判定和排障

- 协商低于 L3：检查宿主版本是否在中央兼容登记中，禁止手工绕过；
- `HOST_COORDINATOR_LEASE_CONFLICT`：说明任务由另一宿主协调，只观察，不重试 resume；
- 某身份初始化失败：其他身份应继续可用，管理端和 `/api/status` 会显示该身份错误；
- 卡片过期：刷新 Interaction 展示，不重放原写操作；
- Artifact 过期：保留历史条目，只有 `regenerable=true` 时允许重新生成；
- 传输超时：读取或 `prepare` 最多在五秒恢复窗内重试，写后结果未知必须停止对账。
