# 开发验证与发布流程

当前支持 macOS 开发及宿主、Linux 中心服务与 CI。项目安装、宿主登记和发布参数见[原生维护](./苹果系统原生维护.md)。行为变更执行定向测试和完整回归；纯文档变更执行文档检查。

## 定向验证

```sh
scripts/agentbridge-native validate --test tests/test_central_service.py --test tests/test_documentation.py
scripts/agentbridge-native validate --plugin
```

MCP App 修改还须在 `integrations/mcp-app` 执行 `npm run check` 和 `npm run build`，生成资源位于 `agentbridge/mcp/static`。

## 完整验证

```sh
scripts/agentbridge-native validate --full
```

共享计划包含浏览器依赖准备、公开内容和当前事实、全量 Python、编译、依赖检查、Workspace Node、OpenClaw 测试与打包、固定 Git 提交 wheel 和隔离安装。前端修改可通过 `.venv/bin/python scripts/validation_plan.py full --root . --mcp-app` 把前端验证加入正式收据。

Full 要求已提交的干净候选，收据绑定输入、工具版本、执行结果和制品。定向检查不创建 Full 收据。测试使用临时密钥，不继承生产会话密钥。真实浏览器与业务验收单独记录，不能把 opt-in 跳过项写成已验收。

## 发布与线上验证

使用[固定发布入口](./发布操作手册.md)。本地可信 Full 和制品验收是发布门槛；GitHub `repository-validation` 为推送后的独立回归记录。CI 按可信历史选择 docs/release/full，历史身份无法核实时退回完整验证。

发布修改运行代码、unit 或运行行为时，保持前驱兼容、备份、回滚、宿主实际版本和身份隔离门槛。真实业务写入仍遵守[开发安全策略](./开发安全策略.md)，不能因发布回归自动提交、审批或撤销。

历史工作站流程与当时的授权记录保存在[旧流程快照](../历史归档/平台迁移/开发验证与发布流程旧版-2026-10-09.md)，不作为当前命令入口。
