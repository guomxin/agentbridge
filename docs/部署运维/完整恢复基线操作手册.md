# 完整恢复基线操作手册

本手册对应改进计划 M2/F04，定义应用数据恢复点及隔离演练。它不自动覆盖线上目录，不启动恢复出的服务，不重放业务任务；服务器整机丢失时还需要独立保存的密钥、部署配置和固定版本制品。

## 1. 资产与策略

| 资产 | 本阶段策略 | 缺失后的行为 |
| --- | --- | --- |
| agentbridge.db | 必须恢复，整库备份，校验中央必要表及任务主体关系 | 拒绝该批恢复点 |
| database/catalog.sqlite3 | 必须恢复，保留数据源配置、状态与版本 | 拒绝，不创建空目录冒充恢复 |
| database/grants.sqlite3 | 必须恢复，保留权限及版本、审计 | 拒绝，不默认授权 |
| database/reports.sqlite3 | 保留元数据，恢复副本中所有报表变为 expired | 不交付旧载荷，不恢复 running 假象 |
| database/credentials/*.bin | 必须恢复，核对目录引用并实际解密验证 | 缺失、错误密钥均拒绝 |
| systems/*.json | 随同一代备份，按配置模型验证 | 配置错误拒绝；不得用其他环境配置扩大允许来源 |
| session-secrets、profiles | 不备份；恢复副本会话 state 置为 expired | 用户重新登录，不声称旧会话可用 |
| database/reports、document-downloads、timeline-attachments 文件 | 短期交付载荷不备份；对应状态及 task_artifacts 在恢复副本变为 expired | 旧下载不可用，需要重新生成 |
| 解密密钥 | 独立保护，不写入备份包或清单；备份含加密校验标记 | 恢复必须提供匹配密钥；macOS/Linux 使用受控外部密钥 |
| systemd、TLS、环境和宿主机配置 | 固定制品与部署模板重建程序；私密配置须独立受控恢复 | 不能仅恢复应用数据就宣称整机恢复完成 |

备份压缩包本身包含数据库、配置与凭据密文，仍是敏感资产。默认目录 0700、文件 0600；不上传公开 Git，不把密钥和备份包放到同一普通共享目录。Linux 使用现有 `AGENTBRIDGE_SESSION_KEY_FILE`，不轮换或改写该密钥。异机恢复须由运维提供受控保存的同一密钥和必要配置；本机解密演练不证明异地密钥托管已落实。

## 2. 一致性与失败处理

`diagnostics backup-create` 默认创建 v2 恢复点：四库齐备才开始。自 2026-09-28 修订后，用监测连接的 SQLite `data_version` 验证固定四库读取快照期间没有提交，再从固定的只读事务复制。固定快照阶段的提交冲突、复制期间的数据库替换或必要文件变化会作废该轮，最多重试 3 次并短暂退避；全部尝试共用 90 秒预算，systemd 整体预算 360 秒。错误和清单记录冲突资源，不输出源数据值。

各库采用 SQLite 在线备份 API，不直接复制正在写入的 db/WAL 文件。成功代次要求各读取快照在同一个无提交变化的获取区间内固定；WAL 库之后的正常提交不会改变已固定视图，因此不再因整个复制期间有提交就作废。必要文件仍覆盖完整复制阶段校验。这不宣称数据库引擎提供跨库业务原子事务。实现依据：[SQLite data_version](https://www.sqlite.org/pragma.html#pragma_data_version)、[在线备份 API](https://www.sqlite.org/backup.html)。

持续繁忙时可能无法取得恢复点，此时明确失败并保留旧备份，不无限等待、不自动停机、不把不一致备份记为成功。应查看备份服务失败并在低负载时重试；如始终繁忙，再单独安排短暂停写维护，不自行增加线上停机。

一代由一个 zip 和一个 `.manifest.json` 组成；清单最后原子发布，列出成员哈希、大小、Release、恢复点时间、策略、验证结果及密钥校验标记。缺成员、路径越界、摘要不符、目录引用或授权异常均拒绝。清单不是签名证明，依赖受控目录；不防御能同时重写包和清单的管理员。

每日定时器仍为 02:20 加最多 15 分钟随机延迟，保留 30 天。定时配置只代表计划频率，不能承诺 RPO；应检查最新成功代次的 `recoveryPointAt`，失败会扩大数据丢失窗口。另由 209 每 30 分钟主动拉取完整代次、独立保留 90 天且至少 7 代，见[独立备份节点手册](./独立备份节点操作手册.md)。两机是否位于独立故障域及应用密钥独立保管仍待落实，不宣称异地容灾完成。

## 3. 创建、验证和隔离恢复

服务器手工执行时以 agentbridge 身份明确提供密钥路径；备份服务已设置该变量。

```sh
sudo -u agentbridge env AGENTBRIDGE_SESSION_KEY_FILE=/home/guomao/agentbridge/config/session.key \
  /home/guomao/agentbridge/venv/bin/python -P -m agentbridge.cli.main \
  --home /home/guomao/agentbridge/data diagnostics backup-create \
  --output-dir /home/guomao/agentbridge/backups

sudo -u agentbridge env AGENTBRIDGE_SESSION_KEY_FILE=/home/guomao/agentbridge/config/session.key \
  /home/guomao/agentbridge/venv/bin/python -P -m agentbridge.cli.main \
  --home /home/guomao/agentbridge/data diagnostics backup-validate \
  --backup /path/to/agentbridge-GENERATION.manifest.json
```

本地固定只读业务边界的演练入口：

恢复演练使用 `agentbridge diagnostics backup-restore-drill`，需在固定服务身份、已审核密钥环境和显式 `--home` 下运行；完整参数见[运行治理手册](./运行治理操作手册.md)。

演练只在服务器 `data/restore-drills/restore-*` 新建私有目录，解包、复核哈希、验证密钥与凭据、核对任务主体及授权，然后仅修改副本的过期状态。之后四库均以只读连接打开，写入探针必须被拒绝。报告 `sourceHashMatches` 指标准化前的原始成员摘要一致；标准化会改变副本数据库哈希。失败时移除本次新建目录，绝不清理调用者父目录或线上 home。

报告保存验证计数、过期处理数量、实际恢复耗时、恢复点距演练时间及零业务调用结果，不输出解密内容。不连接业务数据库、不访问 OA，也不启动服务。`durationSeconds` 只衡量隔离数据恢复耗时，不是包括服务器重建、密钥取回和用户重登在内的完整 RTO。

旧 v1 中央单库备份仍可验证与演练，但不满足 M2 的四库恢复标准。不得把旧单库的通过结果当作新基线验收。

## 4. 实际故障后的恢复顺序

1. 明确恢复点与对应程序 Release，取回独立保护的密钥和必要机密配置；保存故障现场。
2. 在新目录完成本手册的校验与隔离恢复，核对报告，确认凭据解密成功且授权未扩大。
3. 审查备份之后已发生的写入、结果未知任务、待授权和待投递事项。历史恢复点不代表外部系统被回退，不能启动后自动重放。
4. 在单独的维护操作中停止相关服务、保存现状并切换目录/版本；确认端点、TLS、Token、密钥和允许来源。M2 不提供自动生产切换。
5. 服务就绪与只读检查后恢复入口；通知用户重新登录、重新生成短期报表。业务写入恢复另行确认。

`activationAllowed=false` 是演练报告的明确边界，并非阻止操作系统启动任意目录的强制开关。M3 将另行处理版本环境、恢复点绑定及切换回退。未核实的异地副本、密钥托管和整机演练继续列为外部保障待办。
