# AgentBridge 开发安全策略

## 一、当前架构基线

唯一有效的运行时是中心 AgentBridge：

- 基于 `argparse` 的能力 CLI；
- 使用官方 Python MCP SDK 的 Streamable HTTP 服务；
- CLI 与 MCP 共用 `CentralCapabilityService`；
- 每用户独立 HTTP 会话和受控 Playwright Profile；
- 可信认证卡、业务字段卡和执行授权卡；
- 宿主无关的 `agentbridge.interaction.v1` 轮询与续办协议；
- 持久化的操作、身份、字段提交、授权和任务账本。

禁止重新引入：

- 客户端浏览器扩展；
- localhost daemon 或 daemon 代理命令；
- 对个人浏览器 Profile 的生产依赖；
- 任意 HTTP、JavaScript、DOM 或选择器工具；
- 静默回退到更弱治理路径。

AgentBridge 只返回可信交互信封，不自行假定调用者是 Codex，也不要求中心服务弹出用户本机浏览器。
宿主可以把信封转换成原生按钮或内嵌页面，但不得复制下游业务规则，也不得让凭据和可信字段经过模型。

## 二、身份与会话

同一用户加密会话的凭据代理、能力 Worker 和恢复进程必须运行在固定 OS 安全身份下。
`session login` 是幂等的“确保会话可用”操作：

- 只有实时探测通过后才能复用现有会话；
- 只有下游明确确认登录失效后才能创建新认证卡；
- `SESSION_CHECK_UNAVAILABLE` 只表示暂时无法检查，应有界重试，不能索要密码；
- `SESSION_RUNTIME_MISMATCH` 必须路由到绑定的中心运行时，不能通过删除会话或 Profile 假装修复；
- 实际下游主体与预期身份不一致时立即隔离会话。

macOS 和 Linux 必须通过绝对路径
`AGENTBRIDGE_SESSION_KEY_FILE` 提供恰好 32 字节的外部密钥。会话保护器必须拒绝：

- 符号链接；
- 过宽文件权限；
- 错误密钥；
- 错误用户、系统或会话上下文；
- 被修改的密文。

不得回退到明文 `storage_state.json` 或其他明文 Cookie 文件。

## 三、网络与 TLS

非回环 MCP、可信卡、管理控制台和 Workspace 默认强制 TLS。

仅在受控单机内网概念验证中允许显式私网 HTTP 例外。该例外必须：

- 绑定精确 RFC 1918 私网地址或 IPv6 ULA；
- 发布相同 IP 与端口；
- 输出明文传输警告；
- 不映射到公网；
- 不使用通配监听、公共地址、自动降级或生产环境。

当前正式内网基线已经使用固定私网 IP、HTTPS 和内部 CA。新的远程入口不得以“测试方便”为由
退回明文或扩大监听范围。

## 四、变更门禁

行为变更提交或推送前必须满足：

1. 改动能力、适配器、可信卡或策略的定向测试通过；
2. 完整自动化、编译检查和依赖检查通过；
3. 改动真实下游契约且存在合适测试数据时，完成安全的真实验证；
4. 文档、工具目录、能力注册和部署参数同步更新；
5. 没有把用户原有未跟踪文件或无关改动带入提交。

真实验证失败时先修复或明确记录阻塞，不提交“看起来大概可用”的写操作。纯文档变更不重启或
部署 AgentBridge，但仍需运行文档链接、目录规范和相关回归测试。

## 五、写操作

每个中心写能力必须遵循：

```text
prepare -> authorize -> commit -> verify
```

要求：

- 对外按业务流程组织，不按底层接口组织；
- 敏感业务字段通过可信字段卡收集；
- 授权前冻结不可变计划；
- 授权绑定用户、系统、会话、能力版本、计划哈希、目标和有效期；
- 在 commit 边界一次性消费授权；
- 使用幂等键以及对象/会话锁；
- 核验服务端权威业务状态，不以 HTTP 200 代替成功；
- 越过提交边界但无法核验时返回 `unknown`，绝不盲目重试；
- 可逆动作提供明确补偿，不可逆动作单独标记和授权。

模型只能看到读取工具和受治理准备入口。内部 commit、续办和宿主协调工具不得注册为模型可调用工具。

## 六、真实下游验证

- 只使用中心受控会话和 `CentralBrowserWorker`；
- 不恢复旧扩展，不启动 localhost daemon；
- 登录、字段输入和执行授权使用可信卡；
- 中文和其他非 ASCII 内容使用已验证的 UTF-8 JSON 或目标系统编码路径；
- 通过后端接口或渲染后的权威页面核验精确文本和业务状态；
- 创建草稿、提交、审批、撤销或改变流程状态前取得用户明确授权；
- 可以提交并撤销的测试，也必须分别经过提交授权和撤销授权；
- 第二用户的真实待办不得因隔离测试而被操作。

## 七、常用验证命令

```bash
python -m unittest discover -s tests
python -m pytest -q
python -m compileall -q agentbridge
python -m pip check
python -m agentbridge.cli.main --home .agentbridge capability list
python -m agentbridge.cli.main --home .agentbridge session status --system oa --user-subject <用户主体>
```

原生分层验证：

```sh
scripts/agentbridge-native validate --test tests/test_session_secret_protectors.py
scripts/agentbridge-native validate --full
```

旧运行时防回归测试必须持续证明退役命令、扩展文件和传输路径不会重新出现。

## 八、文档规范

- 文档目录名、领域文件名和正文统一使用中文；
- `README.md` 只作为 GitHub、NPM 等工具约定的入口文件保留；
- 产品名、协议名、命令、接口和代码标识可以保留英文；
- 当前事实、设计、运维、系统适配、验收、规划和历史归档分别维护；
- 新验收文件使用中文主题加 `YYYY-MM-DD` 日期；
- 文档不得保存密码、Token、Cookie、私钥或短期可信卡 URL。
