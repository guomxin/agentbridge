# 苹果系统原生维护入口

适配基线：`a0a687ff10b40ea0bf21fadccdb0e1a9941f4944`。工作分支：`codex/macos-native-migration`。

本入口使用 Python 3.12、POSIX Shell、OpenSSH 和用户级 launchd，不调用 PowerShell。
Windows 脚本保留供原宿主运行与回退。生产身份、正式 SSH 转发和服务器部署必须等正式交接；
本次离线测试通过不能表示 M2/M3/M4 已完成。

## 入口与验证

```sh
scripts/agentbridge-native --help
scripts/agentbridge-native validate --test tests/test_native_maintenance.py --plugin
scripts/agentbridge-native validate --full
```

Shell 默认选取仓库 `.venv/bin/python`，也可显式设置 `AGENTBRIDGE_TEST_PYTHON`。
不能依赖 macOS 默认 `python3`（此机为 3.9.6）。验证环境需要项目 `[database-analysis]` 依赖、
pip、setuptools>=77、pytest、pytest-xdist，以及 Playwright Chromium。

Full 按原门禁执行公开内容检查、current-facts、完整 Python 测试、compileall、pip check、
Workspace Node 测试、插件测试、pack check、固定 Git 提交 wheel 及隔离安装资源检查。
沿用 `scripts/agentbridge_artifact.py` 的 begin/finish/verify 和 `output/release-validation/full.json`，
不把 targeted 或未提交候选的离线回归写成正式发布收据。
POSIX 测试使用自动生成的临时 32 字节会话密钥和规范化临时目录；仅传入测试子进程，结束后删除。
不读取或复用生产会话密钥。

每次入口执行生成仓库外 `~/AgentBridgeMigration/native-run-*.json`，也可在子命令前指定
`--report /绝对路径/report.json`。测试诊断单独写入权限 0600 的 `native-test-*.json`。
子进程失败不会将生产配置、凭据或完整子进程输出打印到终端。

## 发布计划和执行

环境 profile 延续 `agentbridge.environment.v1`：`host`、`root`、三个 `units` 的 `path/sha256`。
profile 与 unit 必须在仓库外；Windows 路径需经人工核对改成 Mac 路径，unit 字节及审核哈希不变。
仓库通用模板不能代替真实生产 unit。

```sh
scripts/agentbridge-native publish \
  --profile "$HOME/AgentBridgeMigration/private/environment.json" \
  --identity "$HOME/.ssh/agentbridge" \
  --known-hosts "$HOME/AgentBridgeMigration/private/known_hosts" \
  --offline
```

默认仅计划。`--offline` 不联网，明确将前序版本标为未核实；移除此选项会只读查询服务器前序版本。
计划显示分支、工作区、远端、unit 哈希及阻塞项。适配分支不能直接发布，必须按原策略整合到 main，
或使用准确指向本地 main 的 detached checkout。origin 只接受本仓库 HTTPS 或 SSH 地址。

正式执行额外提供 `--apply --host-profile ... --cutover ...`。执行顺序为：分支及远端门禁 →
前序版本兼容检查 → 完整验证或 `--reuse-validation` 严格复用收据 → 治理故障注入 →
重新核对候选/profile → 制品上传 → 现有 Linux release transaction → 条件重启 → pending 冷/热预热 →
TLS、MCP Release、备份、宿主实际加载版本、服务器回环转发和可选身份隔离 → GitHub push 与远端 commit 复核。
无任何 dirty、跳过验收、强制升级或自动恢复业务数据的旁路。

`--resume` 只允许当前已确认候选：使用服务器该候选保存的 runner/config 执行 `--complete`，
不上传、不重新安装、不切换服务，也不能重启未验证的 Gateway。验收失败不 push。
指定身份验收时必须提供至少两个不同的 `--identity-label`，并逐项提供
`--expect-endpoint USER_SUBJECT=CLIENT_TYPE`；M4 必须执行两个真实用户的隔离验收。

## 宿主 profile 与 launchd

私有 JSON profile 权限必须为 0600，schema 为 `agentbridge.mac-host.v1`，必需字段：

| 字段 | 内容 |
| --- | --- |
| `node` / `openclaw` | Mac 安装的 Node 可执行文件与 openclaw.mjs 绝对路径 |
| `stateDir` / `configPath` | 审核后的 Mac OpenClaw 状态目录与 JSON 配置 |
| `envFile` | 0600 的 literal dotenv 文件，不以 shell source 执行 |
| `runtimeDir` | 仓库外日志、锁、baseline 与 pending 目录 |
| `caCertificate` | 原根 CA 证书路径，不是私钥 |
| `port` | 默认 18789 |
| `tunnel` | `host`、`user`、`identityFile`、`knownHostsFile`、`remotePort`（默认 18789） |
| `openclawLogDir` | 可选，默认 `/tmp/openclaw`；须与当前安装实际日志位置一致 |

配置必须保留 `diagnostics.stuckSessionWarnMs=30000`、`stuckSessionAbortMs=120000`。
Node CA、状态目录、配置路径和 PATH 显式写入 Gateway 的 launchd 环境。
含凭据的 plist 为 0600；不得公开这些文件。请核对代理、插件链接和插件精确版本，不能只复制 Windows 路径。

```sh
scripts/agentbridge-native host render --profile /私有目录/mac-host.json \
  --destination "$HOME/AgentBridgeMigration/launchd-review-01"
```

render 只生成到一个新目录并运行 plutil，不加载作业、不占用任何端口。
正式 `host start --kind gateway|tunnel --profile ... --cutover ...` 才将审核配置放到
`~/Library/LaunchAgents` 并 bootstrap 到当前 `gui/UID`。这意味着**登录后恢复**，不是 FileVault 解锁前启动。
label 固定为 `ai.agentbridge.gateway`、`ai.agentbridge.workspace-tunnel`，只有 launchd 一套管理器。
Gateway 使用 foreground `gateway run --bind loopback`，不使用 `--force` 抢占监听。
SSH 使用严格 host key 检查、BatchMode、ExitOnForwardFailure、keepalive，并只绑定服务器 127.0.0.1。
不读取用户 SSH config 中隐含的 ProxyCommand 或其他转发设置。

`host restart --kind gateway` 根据内容指纹、进程 PID/启动时间及 readyz 决定是否需要重启；
文档变化不触发，插件 lib/入口/锁文件、配置、dotenv、启动环境、Node/宿主入口及 CA 改变会触发。
重启前保存 pending，输入在启动期间改变则不能签发 baseline；失败保留 pending，预热通过才清除。
如果安装的 plist 内容变化，拒绝覆盖：先停止并检查，再人工归档旧 plist 并重新安装。
`host stop` 先 disable 再 bootout，避免回退 Windows 后 Mac 在下次登录意外恢复正式身份。
`host status` 只报告作业状态，不能代替链路验收。

## 正式切换证据

`--cutover` 是权限 0600 的本机交接记录，schema 为 `agentbridge.mac-cutover.v1`，字段：

- `windowsGatewayStopped`、`windowsGuardDisabled`、`windowsTunnelStopped`、`serverForwardReleased`、`m2Accepted` 均为 true。
- `stagedManifest`：以 `prepare.py stage --require-final --expected-sha256 ...` 恢复的新目录中的 manifest.json。
- `bundleReceipt`、`bundlePath`、`expectedSha256`：最终加密包、源收据和另行核对的 SHA256。

入口复核 final 类型、包哈希、源提交、计划哈希和暂存成员哈希，snapshot 无法激活。
这些布尔字段是操作人员真实完成检查后的本地证据，不是工具能远程证明旧机停机的数字签名。
不得为了通过检查而先填写 true。配置适配应输出到其他目录，保留 staged-final 原始文件用于哈希复核。

## 经授权的 SSH 直传交接

本次用户改为认证 SSH 直传；整包加密不再是必要条件，原 CA 私钥仍保持加密 PKCS#8。
仅 `direct-snapshot-20260930-03` 为已验证准备副本；旧副本不用于恢复。
准备副本的 Codex `.tmp`、`tmp` 已按用户要求排除，不恢复这些目录。

`python scripts/migration/direct_transfer.py --directory ... --receipt ... --expected-sha256 ... --expected-commit ...`
要求源端另行核对的 manifest SHA256 和完整代码提交。校验清单每个成员的大小/哈希、实际文件集合、
重复/大小写碰撞、路径穿越、符号链接、收据及源提交。增加 `--require-final` 后，snapshot 必须失败。
不修改已接收原件。接收收据放在目录同级，不能混进受校验文件树。

`python scripts/migration/adapt_mac.py --help` 可从已验证副本生成全新的仓库外准备目录。
只改已识别的配置路径，保留会话历史，复制 workspace Git，重建同版本 browser/canvas 技能链接，
生成私有 environment/mac-host profile。准备配置禁用全部渠道和微信插件，禁止自动升级；
`preparationOnly=true` 的 profile 无论提供什么切换记录都不能激活宿主或发布。
插件在独立副本按原 lockfile 使用 `npm ci --legacy-peer-deps --ignore-scripts --no-audit --no-fund` 恢复，
防止 npm 自动解析和安装较新的 OpenClaw peer。然后按已安装精确版本重建插件链接/注册表。
不把 Windows Codex 配置或数据库覆盖到正在使用的 Mac Codex。

直传正式 manifest 延续 `agentbridge.mac-migration.direct.v1`，还必须包含：

- `kind=final`、`transport=ssh`、准确 `sourceCommit`、完整 `files`。
- `consistency=quiesced-final`；`quiescence` 中 `gatewayStopped`、`guardDisabled`、`tunnelStopped`、
  `writersStopped`、`sourceTreeStable` 必须是真实检查后的 true。
- `quiescence.stoppedAt/checkedBefore/checkedAfter` 使用含时区的时间且顺序成立；源端应在复制前后执行
  原有 `prepare.py check-quiesced`，并复核源文件清单/内容没有变化，不能根据复制完成自行推断停机。
- 将本次审核的 plan 放入 `source-evidence/plan.json`，以 `planSha256` 绑定；final 接收收据包含相同
  `sourceCommit`、`planSha256`、`manifestSha256`、`files`、`kind=final`、`activated=false`、
  `status=verified-staged-only`。原 CA 与 portable-ca 的根指纹、加密私钥哈希必须一致。

直传切换记录使用 `transferMode=ssh-direct`，提供 `stagedDirectory`、`transferReceipt`、
`expectedManifestSha256`、`expectedSourceCommit`，保留旧的 Windows 停机、Guard 停用、
服务器转发释放及 M2 验收字段；不再要求 `bundlePath`/`bundleReceipt`。
必须在新 final 目录重新适配，复核后才把正式 host profile 标记 `preparationOnly=false`，
并用 `reviewedHostProfileSha256` 绑定其字节；profile 的源 manifest/commit 也必须匹配 final。
这些证据是受控交接记录，不能自动证明远程旧机停机，更不能预先填写 true。

加密 final 包校验路径继续保留；两种方式均不能用准备快照替代最终状态。
