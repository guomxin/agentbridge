# 数据库能力控制台动态授权设计

日期：2026-09-12。先记录设计，再实现，最后以 Workspace 进行验收。此设计补充《数据库一期升级设计》，将原来通过管理员 CLI 配置的能力接入管理控制台。

多数据源上线后的授权以中央账号和数据源为单位。控制台保存和本地 grant 命令均须显式指定来源，只有一个数据源时同样适用。

## 目标

管理员在控制台为中央账号 guomao、lishiyu 等选择数据库能力，保存后下次数据库调用立即按新授权执行。同一账号原有有效 Token 继续使用，不签发或更换 Token，不修改 OpenClaw 配置、不重启 Gateway、不要求重新登录业务系统。中央账号与数据库人员 ID 仍不映射。

数据库能力不是 Token scope 的副本：Token 验证中央身份，database/grants.sqlite3 保存该账号当前能力列表。database_capabilities 每次读取最新列表；database_execute 在执行前及返回前检查授权。撤销后新调用拒绝，读取中发生授权变化则不交付该次读取结果。

## 管理界面

管理控制台“用户与令牌”每个账号行增加“数据库能力”入口，并显示已授权数量。账号列表来自已有中央用户，不要求新建 Token。弹窗展示账号、当前授权和七项能力，管理员勾选后保存；审计员可以查看，不能保存。

六项常规能力为结构、目录、日志查询、日志统计、日志内容分析、日志评论分析。高级自由只读 SQL 独立分组，默认不勾选，不随常规能力自动选中。高级权限包含五个开放视图及评论；正文分析本身不隐式授予评论能力。弹窗明确“保存即生效，无需重启 OpenClaw，不签发新 Token”。空列表表示撤销该账号在所选源的全部数据库能力。

保存需要填写变更原因；成功回显实际保存结果和版本。遇到其他管理员已修改的冲突，提示重新打开获取最新配置，不自动覆盖、不丢失后端状态。

## 管理接口与存储

- GET /api/database-grants?user=<中央账号>&source=<数据源标识>：已登录管理员和审计员可读取。返回 user_subject、source_id、capabilities、revision，以及可选能力的名称、描述、advanced 标记。只接受已存在的中央账号。
- POST /api/database-grants：仅管理员可用，沿用现有 Origin、CSRF、初始密码修改检查。请求体为 user_subject、source_id、capabilities（允许空数组）、expected_revision、reason；缺少来源返回 HTTP 400，不写入授权。仍拒绝未知能力、非字符串列表、无效版本和额外字段。
- revision 使用 SQLite 事务内的比较与更新；旧版本提交返回 409，未修改授权。返回的是本次事务确定的版本，不在提交后另读可能被他人改变的版本。
- 成功授权变更在数据库授权审计中同事务记录操作人、原因、前后能力与版本；同时进入控制台既有管理审计。任何路径都不记录 Token 密钥或数据库凭据。
- 不调用 token.issue/token.revoke，不修改会话绑定、OpenClaw 配置或宿主工具目录。沿用已发布的 database_capabilities/database_execute 工具，因此此轮部署也应保持 Gateway 输入指纹和进程不变。

## 验收步骤

1. 离线验证两个中央账号独立授权：已有 Token 签发完成后，通过管理接口开启/撤销能力；同一 MCP 服务实例、同一 Token 实时允许/拒绝，另一账号不受影响。断言无新签发、撤销和重启动作。
2. 管理接口验证：未登录、审计员写入、错误 CSRF/Origin、未知账号、未知能力、错误参数、过期 revision 均拒绝；空列表可保存；审计包含前后状态。
3. 控制台桌面及窄屏验证：账号对应正确、常规与高级分组清楚、保存回显、冲突提示、审计员只读、无横向溢出和脚本错误。
4. Workspace 实测：复用既有 Chrome 登录态，先核对当前中央账号；管理员在控制台按用户指定范围保存；在 Workspace 发起明确的数据库查询，观察最新能力目录和实际工具结果。然后临时撤销已授权的测试能力，验证同一 Workspace 登录态、同一 Token、同一 Gateway 进程下拒绝；恢复到用户指定的最终范围，并再次查询验证。
5. 保存前后核对现有 Token 元数据和 Gateway PID/输入指纹，证明没有重新签发或重启。若用户选择暂不授权，则只验证未授权路径，不把正向 Workspace 查询列为通过。

用户已确认：guomao、lishiyu 均启用全部七项能力，包括高级自由只读 SQL。实施后从控制台保存；撤销测试结束须恢复到这一范围。所有真实数据库调用仅只读；不调用业务系统 API 或进行业务写入。
