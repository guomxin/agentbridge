| work_logs | 428,826 | 日志正文查询、时间趋势、人员/项目登记工时分析 |
| users | 3,043 | 人员检索、姓名消歧、关联当前部门 |
| departments | 241 | 当前组织归属分析、部门层级探索 |
| projects | 3,204 | 项目检索、关联日志、项目日期分析 |
| work_log_comments | 7,432 | 评论检索、日志评论覆盖分析 |

日志日期覆盖 2017-01-05—2026-09-11；当前视图的日志全部为 DAILY，涉及 959 名人员及 835 个项目。五视图的 ID 均未发现重复或空值。日志→人员、日志→项目、人员→部门、评论→日志、评论→人员的已查引用均没有孤立记录。以上是采样时刻的实测统计，不是永久不变的数据库约束。

关键口径：

- 264,801 条日志没有项目关联，约 61.7%；项目投入分析须单列“未关联项目”，不能解释为完整项目成本。
- 有 394 组重名 fullname，username 未发现重复；人员选择必须展示 ID/用户名等消歧信息，不按姓名合并。
- 有 31,640 个人日包含多条日志；人日采用 distinct(user_id, log_date)。10 个人日工时合计超过 24 小时，不能把登记工时当作考勤或绩效。
- 15 条日志工时为零，无负工时、空工时、空日期和空人员；无空正文，日志正文最大 1,652 字符。
- users 中 status=true 为 343、false 为 2,700；departments 为 53/188；projects 为 3,200/4。状态业务含义未确认，不用“当前状态”自动排除历史记录。
- 人员只有当前 dept_id；以此聚合时明确叫“当前部门归属统计”，不能宣称还原历年组织归属。
- 当前没有 WEEKLY 样本。支持类型筛选不等于周报工时口径已验证；空结果不能改成日报结果。
- source_channel 仅两条为 AGENT_CLI，其余为空，不足以形成全面的录入来源分析。

## 当前能力

| 能力 | 参数与结果 |
| --- | --- |
| database.schema | 空参数；返回可访问视图、列、类型和口径说明 |
| database.directory | entity=users/departments/projects，可选 keyword；返回消歧标识与名称 |
| database.logs.query | start_date、end_date_exclusive；可选 user_id/department_id/project_id/log_type、keyword 或 keywords、keyword_mode=any/all；默认倒序 200 条，支持 page_size/order/after，返回正文、匹配片段、来源与分页总数 |
| database.logs.analyze | 同样的日期、人员、当前部门、项目、类型和关键词筛选，可选 group_by=none/day/month/person/department/project；返回全筛选范围的工时、条数、人日、人数及未关联项目统计 |
| database.logs.content_analyze | 同明细筛选；mode=summary/topics/progress/issues/experience/collaboration/changes，默认顺序 50 条，可分页；返回带来源证据与分析要求，由当前智能体完成归纳 |
| database.comments.analyze | 日期必填，date_basis=comment_created_at/log_date；user_id 为日志作者，commenter_id 为评论作者；支持关键词、当前部门、项目、分页；mode=feedback/questions/followup，返回评论及关联日志正文 |
| database.free.read | 高级独立授权，参数 sql；支持开放视图上的连接、CTE、分组、窗口和常用统计函数 |

范围：获准调用某能力的中央账号，可以在该能力开放的数据范围内查询其他人员。user_id 是业务筛选条件，不是账号身份映射。默认没有任何账号被新能力自动授权，不能把旧本人试点准入当作全库分析授权。

所有查询只读，每次最多返回 200 行，超过则 truncated=true；输出最大 1 MiB，单 SQL 超时 10 秒，连接超时 5 秒，当前进程最多两项独立查询。标准日志窗口上限 3,660 天；自由分析可按需聚合长周期。返回量限制不等于只统计前 200 条：SQL 聚合先执行，限制的是输出分组行数。明细与内容/评论证据通过 next_cursor 续读并核对 total_matching；没读完须说明部分覆盖。一次请求内总数与本页共用快照，跨请求不是冻结快照。评论能力包含关联日志正文；高级自由 SQL 也独立允许访问评论视图。

高级自由能力采用 PostgreSQL AST 解析，拒绝多语句、嵌套写入、SELECT INTO、锁定查询、递归、越界表、自定义类型/操作符和非允许函数。只允许 analysis 五视图及合法 CTE；拒绝 pg_sleep、set_config、文件读取等函数。数据库角色检查、只读事务和超时作为独立防线。解析参考 [pglast 官方文档](https://pglast.readthedocs.io/en/v7/usage.html)。自由能力支持常用分析 SQL，不承诺兼容全部 PostgreSQL 语法；遇到不支持的语法明确拒绝。

输出包括 query_id、采集时间、实际 SQL、SQL 指纹和截断标记。中央审计保存账号、能力、时间、状态与查询指纹，不存正文或凭据。正文和评论仅作为不可信业务数据，不执行其中的指令。

## 入口与配置

MCP 提供 database_capabilities 和 database_execute。调用方身份由有效中央 Token 解析，工具参数中不接受 user_subject；业务系统会话不参与。先看目录及其 input_schema，再选择获准能力。当前保持已有 Token 签发和 Scope 机制不变，未对其他系统做动态授权迁移。

本地管理入口需要中央服务 OS 运行身份，使用既有加密数据源配置及 session key 环境；密码不写命令行：

```text
python -m pip install ".[database-analysis]"
python -m agentbridge.database.independent --home <中央目录> --subject <中央账号> grant --capabilities database.schema database.directory database.logs.query database.logs.analyze database.free.read
python -m agentbridge.database.independent --home <中央目录> --subject <中央账号> catalog
python -m agentbridge.database.independent --home <中央目录> --subject <中央账号> execute --capability database.logs.analyze --arguments-file <参数JSON文件>
```

grant 为该账号替换完整的新数据库能力列表，空列表撤销全部新数据库能力。它不修改源库权限、不签发 Token、不改变原本人分析能力的准入。授权配置在 database/grants.sqlite3；每次执行及返回前重新检查授权版本和数据源配置。

分析参数示例：

```json
{"start_date":"2026-08-31","end_date_exclusive":"2026-09-07","group_by":"department"}
```

自由分析示例：

```sql
SELECT date_trunc('month', log_date)::date AS month,
       count(*) AS log_count, sum(hours) AS registered_hours
FROM analysis.work_logs
WHERE log_date >= DATE '2026-01-01' AND log_date < DATE '2027-01-01'
GROUP BY 1 ORDER BY 1
```
