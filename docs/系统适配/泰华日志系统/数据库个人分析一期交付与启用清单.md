## DBA 核验单与分级说明

2026-09-10 后续变更：DBA 已完成源库收权，账号仅能读取 analysis 下五个脱敏视图。新版固定查询 analysis.work_logs，已发布 007c17004db2 并恢复 strict；预检和两用户样本通过，正式接口结果见最新验收记录。以下清单保留原检查背景，不再表示 TEMP、序列权限仍未处理。

这里需要区分实际影响：TEMP 是创建临时表的权限，不等于可修改正式业务表，属于资源及最小权限加固建议；序列 USAGE 包含 nextval，可以推进序列，属于严格只读账号应收敛的状态修改能力；可读表范围涉及数据保密，尤其应排除认证与令牌表，业务表可以随分析需求逐步增加。参见 [PostgreSQL 16 权限说明](https://www.postgresql.org/docs/16/ddl-priv.html)。

当前生产使用 strict。2026-09-09 首次启用时曾使用 controlled_readonly_pilot 接受 TEMP 和序列 USAGE 提示，该临时配置已退出。以下为持续核验清单，不表示仍待执行；角色默认只读和连接来源等 DBA 配置应保留维护回执，应用预检不代替完整 DBA 审计。

对象为 sisyphus 数据库的 xinguomao 角色。无需提供后端源码，也无需把密码放进工单。请数据库管理员检查**最终有效权限**，包括 PUBLIC 和继承角色：

1. 没有超级用户、BYPASSRLS、建库、建角色权限；无可切换的高权限继承角色。
2. 没有表及列级 INSERT、UPDATE、DELETE、TRUNCATE；无数据库或 schema CREATE。
3. 没有数据库 TEMP；没有 public 序列 USAGE/UPDATE。不能仅撤销角色上的直接授权而遗漏 PUBLIC 授权。
4. 读取范围按一期查询需要收敛，当前通过 analysis.work_logs 视图保障 id、user_id、log_date、hours、type_code、project_id、created_at、updated_at。认证、令牌及密码相关表不应因“全部 public 表可读”继续暴露；同时核查 future/default privileges。
5. 核查角色默认只读设置和连接来源限制。代码强制只读事务不代替角色默认设置或数据库权限收敛。

后续复检不通过 INSERT、nextval 或 DDL 试探生产写入。DBA 变更后运行 `python -m agentbridge.analytics.admin --home <中心目录> check`；该命令只读元数据并以空 ID 数组执行固定查询。只有权限门禁通过后，再安排实际取数验收。
