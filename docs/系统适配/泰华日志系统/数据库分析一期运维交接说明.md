## 日常复检

在中央主机执行以下只读预检；它仅查元数据和空 ID 固定查询，不代替真实用户对账：

```bash
sudo -u agentbridge env \
  AGENTBRIDGE_SESSION_KEY_FILE=/home/guomao/agentbridge/config/session.key \
  /home/guomao/agentbridge/venv/bin/python -m agentbridge.analytics.admin \
  --home /home/guomao/agentbridge/data check
```

预期 status=passed、privilege_policy=strict、privilege_warnings=[]。随后在工作台查询本人已知窗口并核对源系统。检查数据源只有一个启用实例；不得复制同一生产配置到另一个 home 同时运行。

建议在发布、视图变更、凭据或授权变更后复检，并由运维负责人维护周期检查和 Token 到期台账；本说明没有新建自动巡检或到期提醒。

## 常见问题与处理

| 现象 | 处理 |
| --- | --- |
| 需要日志系统登录 | 在该用户可信登录卡完成认证；不要更换数据库密码。登录后观察原任务是否续办 |
| Token 缺 Scope 或到期 | 在管理台核对并重新签发正确权限；同步可信客户端后验证，再撤销旧 Token。管理台目前提供签发/撤销，不假定可原地编辑权限 |
| 数据库凭据无效 | 由运维检查数据库凭据；不能要求用户反复登录日志系统来解决 |
| DATA_CONTRACT_CHANGED | 核查 analysis.work_logs 的八列名称/类型、analysis USAGE、视图及来源主键；禁止为绕过错误恢复 public 底表读取或放宽 strict |
| SOURCE_CHANGED／RESULT_ACCESS_REVOKED | 当前数据或权限已变化，先核对来源；历史快照不能强行返回，可在当前授权下重新查询 |
| REPORT_DOWNLOAD_EXPIRED（下载入口过期） | 来源结果仍有效时重新导出，使用新的导出请求；不要重复旧幂等请求来延长链接。来源过期时重新查询 |
| DATA_ACCESS_DENIED | 核对当前身份、操作权限及结果／报告归属；不能直接认定本人分析权限整体失效 |
| QUERY_FILTER_UNVERIFIED | 普通团队接口未能核验筛选生效，任务以失败结束；不要求用户登录或确认，不绕过保护返回全量日志 |
| 弹出保存对话框 | 选择文件夹并保存，再打开 CSV 核对；仅出现文件卡不等于文件已落盘 |
| 正在恢复结果 | 等待原请求，必要时刷新页面；不要重复发送业务请求。30 分钟仍无证据显示结果未确认，应核对任务和宿主历史 |

lishiyu 当前客户端 Token 引用位于 Windows `C:\Users\xingm\.openclaw\.env` 的 `AGENTBRIDGE_MCP_TOKEN_WECHAT_LISHIYU`，身份绑定位于同目录 `openclaw.json`。这里只记录位置，不记录密钥。更新客户端配置后按既有 Gateway 生命周期脚本处理；仅更新中央 Python 或工作台静态资源不要求重启 Gateway。运维不能直接编辑其他身份的 Token 来“临时试一下”。

数据库密码只有实际轮换时才运行上述相同 OS 环境下的 `configure`（将 check 替换为 configure）；它隐藏交互读取密码、提升凭据版本并关闭数据源。先备份当前配置，配置完成后检查权限、重新确认准入和真实取数，再按变更流程启用。日常检查不要运行 configure。

## 停用、恢复和变更回退

source.json 在分析调用开始和交付前读取，enabled、准入和策略修改无需重启中央服务或 Gateway。管理员采用同目录临时文件及原子替换，保持原文件属主和受限权限；不要原地写入半截 JSON。修改后先重新读取文件核对，再用目标身份的新请求和已有引用验证生效，不能仅凭“文件已保存”判定权限已撤销。

check 不调用用户准入检查，可以在 enabled=false 时执行，但仍校验数据源配置、凭据和严格查询契约。停用时预检通过只表示数据库可用，不表示业务已启用；恢复必须确认原值已生效且新用户查询成功。

1. 由有权运维人在维护窗口备份 source.json、记录启停和准入原值，再只将 enabled 改为 false；保留权限策略、账号和凭据版本，记录审计。
2. 用一个已授权用户验证新汇总、旧结果读取和报告下载均被拒绝。已下载副本不会自动删除，已经看到的内容也无法收回。
3. 恢复时先运行只读预检，核对两用户准入、strict 和单实例，再恢复原 enabled 值；重新查询验证。不要盲目覆盖历史备份，避免回到旧试点策略。
4. 软件回退必须保留 analysis.work_logs 适配；早于 007c17004db2 的底表查询版本不兼容当前 DBA 授权。若无兼容回退包，先停用分析并排查，不要求 DBA 重新开放底表。

保留变更前后配置摘要、操作人、时间、预检和真实复验结果。源库备份由 DBA 管理，中央备份沿用既有发布与备份流程；异机恢复不在此次文档更新中宣称已验证。

## 工作台转发连接维护

运行 scripts/Install-AgentBridgeWorkspaceTunnelServer.ps1 后必须看到 effectiveConfigurationVerified=true。服务端对 root 会话启用 5 秒探测、2 次无响应阈值；此设置匹配所有 root SSH 会话，不限某个密钥。重载只影响新连接，已有工作台隧道需要在无执行中任务时重连。不要依据未带用户匹配条件的 sshd -T 输出判断 root 配置，也不要仅凭配置文件存在判断生效。
