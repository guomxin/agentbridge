# 数据库组织范围与分析契约

## 适用边界

这是 `taihua_logs` 数据模板的通用部门查询能力，没有公司名称、部门 ID 或特定日期的匹配规则。不修改业务记录、数据源凭据或中央账号授权；标准查询仍使用对应 `database.*` 能力授权。

## 目录与范围

- `database.directory` 的 `entity` 支持人员、部门、项目；关键词是字面子串，空候选可缩短关键词重查，不等于实体不存在。
- 部门目录在来源存在 `parent_id` 时返回父级 ID；`parent_id` 参数筛直接子级。缺少层级且请求父级筛选时返回 `DATABASE_HIERARCHY_UNAVAILABLE`。同名实体需通过父级与 ID 消歧，不能套用其他系统 ID。
- 目录每页最多 200 项；`has_more=true` 时保持实体、关键词和父级筛选，用 `next_after_id` 作为 `after_id`。目录 ID 返回字符串；超过 JavaScript 安全整数的输入 ID 必须使用字符串，避免静默舍入。
- 标准日志查询、统计、内容分析和评论分析支持 `department_id` 或 `department_ids`（互斥，集合最多 200 项）。`include_descendants=true` 包括当前组织树全部可达下级。
- 使用固定的参数化递归查询，按部门 ID 去重并终止环；重叠根节点不重复日志。不开放自由 SQL 的递归执行限制。
- 在同一次只读事务内核实全部根节点、组织集合、匹配数量与正文。根节点缺失、层级不可用或超过 1000 部门直接拒绝，不能静默扩大/缩小范围。
- 返回 `resolved_department_scope`，说明根节点、实际部门集合、是否包含下级、当前人员归属口径和未按状态过滤。`status` 含义未确认，不能据此排除历史/停用部门。
- 下级范围分页游标包含组织集合指纹；集合变化返回 `DATABASE_SCOPE_CHANGED`，须从第一页重查。不同请求仍不是冻结快照；人员归属与内容变化不能因此被称为历史一致性。

## 分析要求

已获得 `database.logs.analyze` 的账号可比较两个完整周的总量。以“11 月 2 至 8 日比 10 月 26 日至 11 月 1 日多登记了多少工时”为例，在同一源调用 `database.logs.analyze`，传 `{"start_date":"2026-11-02","end_date_exclusive":"2026-11-09","baseline_start_date":"2026-10-26","log_type":"DAILY"}`。基期从给定日期起算七天，须在本期前结束；两期可以不相邻。比较使用相同筛选，按总量计算，`group_by` 省略或传 `none`。

每项返回基期值、本期值和本期减基期的差值。基期为零时百分比为空。同一人员同日多篇日志按多条日志、一个登记人日计算。比较沿用当前部门归属，两期取数使用同一次只读快照。CSV 仍需额外导出权限，会按相同参数重新查询，读取时间可能不同。

范围确认、记录读取、事项覆盖分别检查。`has_more=false` 只表示当前分页结束，不表示用户范围完整或事项已全部总结。

智能体应先形成事项清单：来源、明确进展、进行中、计划、问题、未知。根据用户要求归纳时保留独立交付、安全、验收、阻塞事项；检查每个结论与引用是否一致。讨论剩余工作不是实施成果；优先级与严重程度属于分析，须给依据。

此部分是智能体执行契约，不是确定性的自然语言正确性证明。自动化测试不能宣称任意总结都不遗漏；端到端回答仍需检查事项覆盖与证据支持。

## 错误与兼容

数据库拒绝保留旧 `code`，同时增加 `message` 与结构化 `error.code/error.message`。宿主也识别旧的顶层拒绝码，避免把 SQL/参数/权限错误变成缺少引用。成功响应中的业务 `code` 不被当成错误。

不存在的单部门过去可能得到空结果，现在明确拒绝；安全范围以外的数字 ID 现在要求字符串。未指定部门时保持原查询行为；缺少 `parent_id` 的来源仍可查询本级和明确部门集合。
