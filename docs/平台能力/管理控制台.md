# AgentBridge 管理控制台

> 适用范围：当前内网中心部署 `10.10.50.213`
>
> 管理入口：`https://10.10.50.213:8782`

## 1. 定位

管理控制台是 AgentBridge 的独立运行治理面，用于查看多用户、多系统的运行状态，并在异常或维护期间控制写能力。它不代替 OpenClaw，不直接操作 OA、泰华、语雀或照明系统业务，也不展示登录凭据、Cookie、可信卡片 URL、业务字段值或 MCP Token 密钥。

普通用户使用的 Agent Workspace 是与 Telegram、微信同层的独立智能体客户端，
不复用管理端账户、页面或会话。其目标边界见
[多端智能体任务延续设计](../架构设计/多端智能体任务接续设计.md)。

管理端与 MCP、可信卡片共用一个 AgentBridge 进程和 SQLite 状态库，但使用独立的 HTTPS 监听端口、管理员账户、会话 Cookie、CSRF 校验和追加式管理审计。

运行治理二期已经进入影子观察期。详细的数据模型、副作用边界和完成范围见
[运行治理与可靠性二期详细设计](../架构设计/运行治理与可靠性二期详细设计.md)，日常处置步骤见
[运行治理操作手册](../部署运维/运行治理操作手册.md)。

## 2. 角色

| 角色 | 能力 |
| --- | --- |
| `admin` | 查看全部治理信息；管理 Token、会话和写策略；处置运行事件；重投或归档通知；创建管理员或审计员账户 |
| `auditor` | 只读查看总览、身份、会话、能力、操作、可信交互、链路、事件、多端任务、运行信息和管理审计 |

管理账户与智能体用户身份分离。管理员登录管理台不会获得任何下游系统业务身份，也不能通过管理台代替用户提交业务流程。

## 3. 页面

- **运行总览**：接入用户、活动会话、活动任务、端点、待投递、写暂停、最近 24 小时异常和隔离完整性。
- **用户与令牌**：按 `userSubject` 汇总各系统下游主体、系统会话和 MCP Token；权限按系统分组显示，令牌密钥只在签发时显示一次。
- **系统会话**：分别显示每个系统的预期主体和已验证主体，并区分最后确认的登录状态、用户活动、当前保活资格和最近保活；可查看不会被后续登录覆盖的状态历史、执行实时检查、使会话失效，或在清除该系统登录态后重新绑定主体。
- **能力与策略**：查看能力目录，按全局、系统、用户或具体能力版本暂停和恢复写入；读取能力不受影响。
- **操作记录**：保留原始 Operation 审计节点，并结合关联可信交互显示“当前等待用户、用户已处理、已续办、已过期、已拒绝或已替换”等有效状态；不展示调用参数和结果正文。
- **可信交互**：查看认证卡、字段卡和授权卡的状态与有效期，不展示卡片 URL、字段值和执行计划。
- **链路追踪**：按用户、宿主、任务、系统、能力和状态搜索端到端 Trace，查看从宿主受理到投递回执的阶段时间线、耗时、错误和最远副作用边界。
- **事件治理**：查看 P0 至 P3 运行事件、24 小时试点 SLO、最近运行信号和恢复账本；管理员可以确认、调查、解决或抑制事件，并立即触发一次运行评估。
- **多端任务**：按任务、计划、端点、接续、投递、文件和隔离七个视图检查 Task Hub。计划视图显示计划状态、版本、涉及系统、步骤进度、当前步骤和单写终点数量。网页端显示为拉取投递，Telegram、微信等消息端显示为直推投递；微信旧消息令牌无法直推时显示“等待微信活动”，不误报为业务失败。文件视图显示所属用户、任务、类型、大小、状态和到期时间，不显示下载地址。
- **系统运行**：查看 Release ID、启动时间、数据库、保活租约、已配置系统、协调调用耗时、Workspace Gateway 脱敏目标与最近连通/错误时间，以及管理账户。
- **管理审计**：查看追加式审计记录，包括管理员、来源 IP、动作、原因、结果和前后状态。

列表页支持本地搜索和状态筛选。筛选只作用于当前已加载的治理记录，不会触发下游系统调用。

### 3.0 控制平面界面（2026-09-06）

控制台采用石墨色导航、浅色数据区和青色结构标识，导航分为“运行观察、执行协作、访问治理”三组，原有 11 个入口均保留。参考方向见[管理控制台视觉原型](../架构设计/管理控制台视觉原型/设计说明.md)。

- **总览**：活动任务、24 小时操作、待投递、开放事件为首层指标；接入用户、有效令牌、活动端点、写暂停和隔离异常为辅助指标。24 小时操作基于接口最近最多 500 条记录，不冒充全量统计。
- **接入与执行路径**：区分客户端、智能体宿主、AgentBridge 中心与已配置业务系统；该区域是架构说明，不是实时可用性监测。Reference Host 标注为协议验证，业务系统列表来自真实配置。
- **会话和关注入口**：总览会话数来自注册表，明确不代表实时在线。“需关注”按真实计数引导到事件、会话、投递、宿主受理、异常操作和策略页面；不再笼统宣称所有核心服务正常。
- **事件治理**：事件、影子观察、SLO、最近信号、恢复账本分为页签。事件列表与选中事件详情并排，窄屏改为上下排列。详情展示实际事件元数据、建议动作、最远副作用边界和最近最多 12 个已记录阶段，可打开完整链路。没有关联链路时明确提示，不能从事件名称推断已授权或已提交。
- **治理动作**：确认、调查、解决、抑制仍走原有原因填写弹窗、角色检查、CSRF 和审计。解决事件不改变业务结果，不自动重试未知写入。
- **检测语义**：事件默认展示“当前异常”，可切换“历史待核对、已结案、全部”。超过 24 小时的未结案结果未知事项按关联操作发起时间（无关联时间时取首次检测时间）归入历史；这只是展示分类，不会自动降低严重级别或结案。分类计数限于当前加载的最多 500 条，顶部未结案计数仍包含全部当前和历史未结案事件。
- **时间与结案**：分别显示关联操作发起、首次检测、最近检测时间和累计检测次数。检测次数不是业务执行次数。已人工解决或抑制的结果未知事件绑定原始 `operation_id`，后续扫描不会为同一次操作重复建事件；新操作仍正常告警。详情保留结案原因和处置者。
- **交互可靠性**：切页取消旧读取，过期响应不得覆盖新页面；网络失败保留重新读取入口。筛选隐藏当前事件后清空详情。管理员退出或登录失效后，清理选中事件及页签状态。
- **窄屏和键盘**：导航可折叠；宽表格仅在自身区域内横向滚动；事件页签支持方向键和 Home/End；按钮保留焦点轮廓和可读名称。

图标使用本地打包的 Lucide Static 1.41.0，许可证随包保留。无外部 CDN、外部字体请求，也不放宽 CSP。现有 Token、主体绑定、会话时长和业务执行接口不因视觉改造而改变。

`requires_user_action` 是一次 Operation 已经把流程交给可信卡片的终态，不代表该记录会在用户处理后原地改成成功。用户填写或授权后，续办会创建新的 Operation，原节点继续保留用于审计。操作记录页因此按关联卡片计算“有效状态”；只有卡片仍为 `pending`、`claimed` 或 `processing` 时才显示“当前等待用户”。

### 3.1 会话状态与保活资格

“登录状态”和“保活资格”是两个维度：

- **有效 / 保活中**：下游会话最近确认可用，并且用户活动仍在 7 天受控保活租约内；后台每 10 分钟尝试续签。
- **上次确认有效 / 未保活（超期）**：注册表最后一次确认会话可用，但用户已经超过 7 天没有真实使用该系统，后台停止主动续签。这不是实时登录保证；下游会话可能仍可用，也可能已经自然失效。
- **已过期 / 未活动**：实时调用或保活已获得下游明确的登录失效证据，后续业务调用需要可信登录卡。
- **活动未知**：历史会话缺少可用于计算租约的最近用户活动时间，不主动保活。

业务调用或用户主动检查会实时访问下游系统；检查成功后记录新的用户活动并重新取得保活资格。管理台的“实时检查”只用于诊断，不替用户续租，避免管理员查看页面无意中让长期不用的登录态永久存活。

“历史”展示会话创建、登录、明确失效、检查延期和重新登录等事件。当前行的错误字段会在成功登录后清空，但历史事件中的失败来源和原因会保留，便于分析类似“刷新令牌失败”“CAS 应用会话失效”和临时网络故障。

### 3.2 多端任务的安全投影

管理 API `v2` 的 `/api/coordination` 只返回任务治理所需的元数据：

- 任务 ID、用户、可读标题、状态、发起端类型和当前关联的操作/交互 ID；
- 计划 ID、父任务、版本、状态、涉及系统、步骤计数、当前步骤键、写终点数量和脱敏终止原因；
- 端点 ID、客户端类型、拉取/直推模式、能力标签、状态、同步状态和最近活动时间；
- 接续状态、执行模式、候选数量和有效期；
- 投递事件类型、状态、尝试次数、重试时间和确认时间；
- 任务文件 ID、用户、文件名、内容类型、大小、状态、所属任务和到期时间；
- Task Hub 的跨用户隔离检查结果。

接口不返回聊天正文、任务摘要、计划目标、步骤标题、完整能力参数、转换结果、业务字段、卡片 URL、文件下载 URL、OA 文件引用、外部聊天用户标识、会话路由、端点密钥、完整事件载荷或 MCP Token ID。多端任务页用于定位“任务卡在哪一步”“计划推进到哪里”“消息是否送达”和“任务文件是否仍可取用”，不用于读取业务内容。

投递状态 `deferred` 表示消息已安全保存在中心 Outbox，但当前微信端点缺少可用的本次入站消息令牌。系统不会在后台连续消耗重试次数；同一用户从该微信私聊再次发送消息后，中心只恢复该端点的延后投递。该状态不影响原任务结果、网页 SSE 或其他端点。

### 3.3 链路与副作用边界

Trace 不保存聊天正文和业务字段，只保存运行元数据。详情中的副作用边界含义为：

| 边界 | 含义 | 管理原则 |
| --- | --- | --- |
| `B0_NO_EFFECT` | 还没有访问业务系统 | 可以进行有界宿主恢复 |
| `B1_READ_ONLY` | 只发生读取 | 可按原有读取策略重试 |
| `B2_INTERACTION_CREATED` | 已创建可信卡 | 等待用户或使旧卡自然失效，不重复创建 |
| `B3_PREPARED_AUTHORIZED` | 已准备或授权、尚无提交证据 | 必须检查冻结计划与交互状态 |
| `B4_COMMIT_ATTEMPTED` | 已尝试提交，结果可能未知 | 禁止自动重试，进入人工核对 |
| `B5_VERIFIED` | 已由权威业务状态回读确认 | 只处理通知或文件交付，不重做业务 |

### 3.4 事件与恢复动作

运行事件不是普通日志的逐条复制。检测器按规则和对象生成稳定指纹，重复症状增加出现次数而不是
刷出大量新记录；瞬时卡住、投递积压和隔离异常消失后可以自动解决，结果未知写入必须人工结案。

管理端当前只开放三种动作：重新投递已确定通知、归档失败/已确认投递、立即评估运行状态。它们
全部是治理动作，不会重新执行 OA、日志、知识库或照明系统业务。每次动作必须填写原因并生成
幂等恢复账本和追加式管理审计。

## 4. 首次初始化

部署并启动 AgentBridge 后，在服务器的受信终端创建首个管理员。密码只从标准输入读取，不出现在命令参数和程序输出中：

```bash
sudo -u agentbridge /home/guomao/agentbridge/venv/bin/python -P \
  -m agentbridge.cli.main --home /home/guomao/agentbridge/data \
  admin account bootstrap --username admin --password-stdin
```

只有管理账户表为空时才能执行 bootstrap。初始管理员第一次登录后必须立即修改密码。密码至少 12 位，并满足大写、小写、数字、符号中的三类。

后续账户由现有 `admin` 在“系统运行”页面创建。系统生成一次性初始密码，关闭弹窗后不能再次查看。

## 5. 登录安全

- 非回环地址必须使用 HTTPS；当前部署复用内部 CA 签发的 IP-SAN 证书。
- 会话 Cookie 为 `HttpOnly + Secure + SameSite=Strict`，CSRF Token 与会话绑定。
- 管理会话默认最长 7 天、空闲 24 小时；控制台保持打开并正常访问时会刷新空闲时间，退出或会话失效后必须重新登录。
- 登录失败有来源 IP 维度的速率限制。
- 页面启用 CSP、HSTS、禁止被 iframe 嵌入和 MIME 嗅探。
- 管理审计表禁止更新和删除；控制动作必须填写原因。

## 6. 写暂停语义

暂停策略只作用于非只读能力，匹配优先级为：具体能力、用户、系统、全局。策略会在两个位置检查：

1. 准备字段卡或授权卡之前，阻止创建新的写交互；
2. 最终提交边界，再次阻止已经授权但尚未提交的操作。

命中策略时能力返回 `WRITE_PAUSED`，不会调用下游系统。恢复策略不会重放或自动重试之前被阻止的操作，用户需要重新发起。

## 7. MCP Token 管理

管理台签发 Token 时要求填写用户标识、权限范围、有效期和审计原因。首次开通某个系统时，还必须填写该系统的预期下游主体；已有绑定的系统会自动复用现有绑定。同一用户在不同下游系统中可以使用不同的账号或显示名。

Token 只绑定 `userSubject`、客户端标签和 scope，不再以一个全局姓名校验所有系统。旧 Token 中的 `expectedPrincipalRef` 仅作兼容字段；登录校验以 `(userSubject, systemId)` 会话上的系统级绑定为准。

管理员修改某个系统的主体绑定时，服务端会清除该系统会话密文并将状态设为已过期，要求用户重新登录；其他系统会话不受影响。

撤销 Token 立即阻止后续 MCP 调用，但不删除该用户已保存的下游会话。需要同时清除会话时，在“系统会话”页面单独执行失效操作。

## 8. 部署与健康检查

systemd 单元在现有 MCP `8790` 和可信卡片 `8780` 之外启动管理端 `8782`：

```text
--admin-host 10.10.50.213
--admin-port 8782
--admin-public-base-url https://10.10.50.213:8782
--admin-tls-cert /home/guomao/agentbridge/config/tls/server.crt
--admin-tls-key /home/guomao/agentbridge/config/tls/server.key
```

部署脚本把当前 Release ID 写入 `/home/guomao/agentbridge/config/release.env`，管理台“系统运行”页面据此显示实际发布版本。

无需登录的健康检查：

```bash
curl --cacert /path/to/root-ca.crt https://10.10.50.213:8782/healthz
```

预期返回 `status=ok`。健康检查只证明管理 HTTP 服务已监听，不代替登录、权限和治理动作验收。

发布与接流量使用就绪检查：

```bash
curl --cacert /path/to/root-ca.crt https://10.10.50.213:8782/readyz
curl --cacert /path/to/root-ca.crt https://10.10.50.213:8783/readyz
```

预期返回 `status=ready`。管理端会检查数据库和必要治理表；Workspace 还要求 Gateway 已配置。

发布后可从管理员工作站运行统一只读验收：

发布后的自动验收由 `scripts/agentbridge-native publish` 完成，完整参数见[原生维护](../部署运维/苹果系统原生维护.md)。

脚本检查 MCP Release、管理端与 Workspace 就绪端点、远端 systemd/Release、每日备份 timer 与最近备份结果、最近错误计数、OpenClaw 深度 RPC、CLI/Gateway 版本和插件加载状态。它不读取待办、日志或知识库列表，也不执行业务写入。需要同时复核两个身份和四个端点时，显式传入两个 `-IdentityLabel`；该可选检查只调用会话状态和 Task Hub 隔离诊断。

## 9. 运维边界

当前一期刻意不提供以下功能：

- 在管理台中重启 systemd、执行 SSH 或修改服务器文件；
- 查看或导出凭据、Cookie、业务字段、授权内容和完整业务结果；
- 查看聊天正文、通道路由、外部聊天用户标识或完整 Task Hub 事件载荷；
- 以管理员身份代替业务用户调用下游系统；
- 自动清理、撤销或重放业务写操作；
- 声称单进程内逻辑隔离等同于独立 OS 或容器 Worker 的物理隔离。

涉及真实业务写入仍必须由对应智能体用户走字段卡、独立授权、提交和权威回读流程。
