# 业务事项持续跟踪

首版关注本人 OA 已办、已发中的一个精确流程，记录节点、处理人变化和流程结束。历史结果行选择“关注后续”，在“任务 → 我关注的事项”查看、核验、设置、暂停或停止。流程结束不代表付款完成。

列表默认显示“关注中”。可用“关注状态”筛选查看已暂停、已停止、已结束、已到期或全部记录。暂停后在“已暂停”中找回并恢复，停止后可在“已停止”中查看最后一次核验结果。

关注需要已有 `oa.workflow.read` 与单独的 `oa.workflow.watch` 权限；旧用户不会自动获得新权限。创建引用来自当前本人有效查询，绑定四项流程身份、下游账号和系统实例，不接受任意链接、标题匹配或旧任务作为身份。详情读取可能将事项标为已读，创建时必须单独明确同意，默认不选。

默认每小时检查、7天到期，仅工作台记录。可设置15分钟至24小时的间隔、1至30天期限和本人已绑定的通知端点；每人最多50项有效关注。设置时期限留空保留原到期时间。恢复不会延长过期来源或自动重新登录。

后台每次仅作有界读取，复用中央受控会话，不运行常驻模型、不更新用户活动、不弹登录卡。前台繁忙时让出会话锁，来源失败有限退避，缺字段保留上次可信状态与原观察时间。权限、账号或实例变化时暂停；暂停、停止和配置版本变化使在途旧结果失效。

变化按单调序号记账，通知引用与变化同事务写入既有 Task Hub/outbox。外部发送前重新核验本人权限、账号、配置和所选端点；重试只处理投递，不重新读取 OA。仅明确选择的个人端点可收到摘要，默认不推送。外部渠道失败可能重试，不承诺严格一次送达。

能力入口为 `oa.workflow.state.get`，关注平台工具为 `agentbridge_business_watch_create/list/get/update`；CLI `watch` 与 Workspace API 共用中央规则。模型不能调用宿主投递校验或运维控制。关注不执行审批、催办、撤销、付款及其他业务提交。

## OA 每日简报

本人开通后，OpenClaw 定时任务汇总当前 OA 待办，以及“我关注的事项”中已核验的节点、处理人和流程结束变化。简报先保存到 Workspace 对话时间线，再向配置的本人 Telegram 私聊排队投递。已打开的工作台通过时间线更新，重新登录也可在对话历史查看。同一北京时间日期的正式简报和试推各自去重。

后台待办查询使用已有 OA 会话和当前读取权限。关注部分读取已保存的变化记录，不额外打开流程详情。首次汇总回看 24 小时，之后从上次完整读取关注记录的截止时点继续。查询失败、结果不全和未核验状态在简报中标明。已有逐事项提醒的设置独立生效。

运行时由已登记的 OpenClaw 宿主使用固定版本的 `scripts/oa-daily-digest.mjs`，配置文件位于仓库外，权限 `0600`。配置包含 `schema=agentbridge.oa-daily-digest-job.v1`、已登记的 `hostProfile` 绝对路径、`identityLabel` 和该 Telegram 身份的 `telegramEndpointKey`。复用宿主凭证和内网 CA，配置中不保存凭证。首次用 `trial` 发送一次，再用 `trial-status` 核对该次 Workspace 记录和 Telegram 回执。正式任务使用 `run`，禁止额外 announce。按 `Asia/Shanghai` 设置固定时间，可以通过 `openclaw cron edit <任务ID> --cron '30 8 * * *' --tz Asia/Shanghai --exact` 修改，示例为每天 08:30。停用使用 `openclaw cron disable <任务ID>`。

## 运维

本机受信任运维身份可执行 `agentbridge --home <数据目录> watch runtime` 查看数量、检查状态和维护暂停；该命令只读现有 SQLite，不启动 worker 或加载会话凭据。`watch control` 支持 global（target为`*`）、system（`oa`）或 user（用户主体）暂停，要求当前版本、原因，记录实际 OS 操作者。例：

```sh
agentbridge --home <数据目录> watch control --scope user --target <用户主体> --expected-version 0 --paused --reason '排查来源读取异常'
```

恢复使用同一命令的 `--resume` 和最新版本。重叠的暂停仍生效，用户自己暂停、停止或已到期的关注不自动恢复。普通 Workspace/MCP 不提供运维控制写入口。管理员 runtime 的 `business_watches` 提供相同只读统计。

新增账本采用加表、索引的兼容性审查迁移，正式发布保留四库备份和精确结构摘要；迁移后失败依发布手册处理，不能擅自恢复数据库覆盖新增业务数据。
