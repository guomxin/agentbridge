>
> 更新日期：2026-08-30

> 适用版本：AgentBridge 当前主线、OpenClaw 2026.7.1、
> `agentbridge-interactions` 0.4.49

## 1. 定位

Agent Workspace 是普通用户使用智能体的独立网页客户端，与 Telegram、微信处于
同一层。它不是 AgentBridge 管理控制台，也不提供 Token 签发、用户主体重绑、全局
写暂停或他人会话检查。

当前二期提供：

- 网页账号首次绑定、登录、退出和持久会话；
- 通过 OpenClaw Gateway 使用智能体对话；
- 在对话框粘贴、选择或拖入 JPEG、PNG、WebP 图片，作为当前消息的多模态输入；
- 查看当前用户的 AgentBridge 任务、事件时间线和关联端点；
- 查看跨系统持久计划的总状态、当前步骤和逐步骤进度；
- 从任务详情选择“继续任务”，在当前网页会话恢复权威任务上下文；
- 打开当前任务的可信登录、字段或授权页面；
- 网页发起与 Telegram、微信相同的 AgentBridge 读取和受治理业务能力；
- 发起 OA 草稿/正式提交、待办处理、已发撤销和会议创建，以及泰华日志填写；
- 最终执行授权同时显示在网页并主动投递到已绑定 Telegram、微信；
- 用户和助手的非敏感文本按中心序号同步到同一用户的已绑定端点；
- 用户在另一端明确引用“刚才网页端”等内容时，当前 OpenClaw Session 可读取同一
  用户其他端点的有界近期文本以解析指代。

当前二期不提供：

- 登录卡、字段卡的多端共同填写；
- 完整 Transcript 共享、任意隐式指代和 OBO 执行宿主切换；
- 企业 OIDC、找回密码和自助解绑。

跨系统计划仍归属于一个普通 `AgentTask`。任务详情额外显示 `planId`、完成步骤数、当前步骤及
每一步的中文状态；页面只接收安全摘要，不展示完整能力参数、业务字段、卡片 URL、授权内容或
转换中间数据。计划等待登录、字段或授权时，沿用原有应用卡片和多端同步；完成交互后由中央计划
运行时续办，Workspace 不通过模型重新拼接剩余步骤。

## 2. 身份绑定

首次绑定不要求用户在网页输入 MCP Token，也不允许用户手工填写
`userSubject`。

```text
网页生成 8 位一次性配对码
  -> 用户在已可信的 Telegram 或微信私聊发送
     /agentbridge link 配对码
  -> OpenClaw 插件使用该聊天身份的独立 MCP Token
  -> AgentBridge 从 Bearer Token 推导 userSubject
  -> 网页设置本地用户名和密码
  -> 创建永久关联的网页 ClientEndpoint
```

配对码有效期 10 分钟，只能确认一次。网页账号与 `userSubject` 建立永久关联后，
普通退出只吊销当前浏览器会话，不删除账号、端点或身份关联。用户下次直接使用网页
用户名和密码登录，不需要重新配对。

浏览器会话默认：

- 绝对有效期 30 天；
- 空闲有效期 7 天；
- 每次有效访问只延长空闲期限，不突破 30 天绝对期限；
- Session Token 使用 `HttpOnly`、`Secure`、`SameSite=Strict` Cookie；
- 修改请求还必须携带独立 CSRF Cookie/请求头。

## 3. OpenClaw 接入

浏览器不直接连接 OpenClaw，也不持有 Gateway Token。Agent Workspace BFF 在每次
发送消息前：

1. 为网页账号生成 90 秒、一次性 Gateway 绑定凭证；
2. 调用插件私有 RPC `agentbridge.workspace.bind`；
3. 插件依次使用已配置的独立 MCP 身份兑换凭证；
4. 只有与网页账号 `userSubject` 一致的身份能够兑换；
5. 插件把该网页 OpenClaw Session 固定到对应身份；
6. BFF 再调用 `chat.send`。

图片附件沿用同一条身份绑定与流式发送连接。浏览器一次最多提交 4 张图片；服务端重新校验 base64、实际文件头、单张 6 MiB 和合计 12 MiB 上限，再使用 OpenClaw 原生 `attachments` 参数传入模型。通过校验的图片同时进入 AgentBridge 中央附件存储，时间线只保存有序附件引用、类型、大小和到期时间，不保存 Base64；默认保留 7 天。网页任务结束、刷新或服务重启后仍可恢复缩略图，同一 `userSubject` 的 Telegram/微信端收到原图；通道不支持图片时降级为受控 HTTPS 链接。写操作仍须经过原有字段卡和授权卡，图片本身不能绕过工具 scope 或可信交互。

进程内绑定只作为缓存。若 OpenClaw 在 Gateway RPC 与 Agent Runtime 工具创建之间
重建插件实例或清空缓存，插件会使用当前候选 Bearer Token 调用宿主私有只读工具
`agentbridge_host_workspace_session_resolve`。中央服务只在该 Token 的
`userSubject` 确实拥有目标网页 Session、且网页端点仍为 active 时恢复绑定。浏览器、
模型参数和聊天文本均不能指定或覆盖身份。

网页 Session Key 使用：

```text
agent:main:agentbridge-workspace:direct:<workspace-account-id>
```

网页、Telegram 和微信会话注册同一份智能体可见目录：

- MCP 目录中 `readOnlyHint=true` 的读取工具；
- OA 发起、待办处理、撤销和会议创建的全部受治理 `prepare` 入口；
- 泰华日志填写的受治理 `prepare` 入口；
- OA、泰华、语雀和照明系统的可信登录入口。

各入口是否能够执行，继续由当前 `userSubject` 对应 MCP Token 的 scopes 在中心端
逐次校验。模型看不到保存草稿、正式提交、审批、撤销、会议创建、日志创建等内部
commit 工具，也看不到 `agentbridge_interaction_resume`。受治理入口先产生字段卡、
冻结计划和执行授权卡；用户在任一可信端确认后，原任务协调器内部调用 resume，中心端
再次校验所需 scope，再执行 commit/verify。这样各渠道业务能力一致，同时不能绕过卡片
直接写入下游系统。

OpenClaw 核心源码没有修改。接入只使用正式插件 API、Gateway WebSocket 协议和
自定义 Gateway Method，因此 OpenClaw 升级后只需执行插件兼容测试。

网页提交消息后，BFF 先把时间线消息、附件引用、幂等键和宿主投递状态写入中央
SQLite，再由独立协调器通过 OpenClaw Gateway 完成身份绑定、`chat.send` 和
`agent` / `chat` 事件接收。浏览器的流式 HTTPS POST 只订阅持久化事件，不再承担
运行生命周期：

- Gateway 握手声明 OpenClaw 官方 `tool-events` 客户端能力，使发起本次运行的同一
  连接能够接收工具开始、进度和结束事件；
- `agent` 事件只显示模型提供的用户可读进度、脱敏后的业务能力名称和执行阶段；
- 工具参数、工具结果、Bearer Token、`userSubject` 和其他会话事件不会进入浏览器；
- `chat` 增量实时更新当前回答，最终事件到达后再读取一次正式聊天历史进行对账；
- 浏览器刷新、断网或关闭页面只结束 SSE 订阅，不中止已经受理的 Gateway Run；
- 宿主尚未受理且链路不可达时，原请求在 60 秒窗口内按同一幂等键自动等待；
- Workspace 与 AgentBridge 重启后从 `agent_host_dispatches` 恢复原请求；
- 请求可能已送达但 accepted 回执丢失时只查同一幂等键，不盲目重发；
- 每条流在 Node 侧同时按网页账号专属 Session Key 和本次 Run ID 过滤，避免其他
  用户或同一用户的并发任务事件进入 Python；
- 发送与监听不能拆成两个 Gateway 连接；OpenClaw 会把完整工具流和回答流优先投递
  给发起 `chat.send` 的连接。

## 4. 网络与部署

当前内网 PoC 地址：

| 组件 | 地址 |
| --- | --- |
| Agent Workspace | `https://10.10.50.213:8783` |
| AgentBridge MCP | `https://10.10.50.213:8790/mcp` |
| 可信卡片 | `https://10.10.50.213:8780` |
| OpenClaw Gateway | `ws://127.0.0.1:18789`（服务器回环，经工作站反向 SSH 隧道） |

OpenClaw Gateway 绑定本机回环，Mac 工作站通过用户级 launchd 管理反向 SSH 隧道，服务器仅监听回环。Gateway Token 认证与设备配对保持启用。配置和故障处理见[反向安全隧道](../部署运维/工作台反向安全隧道.md)。

AgentBridge systemd 参数包括：

```text
--workspace-host 10.10.50.213
--workspace-port 8783
--workspace-public-base-url https://10.10.50.213:8783
--workspace-tls-cert /home/guomao/agentbridge/config/tls/server.crt
--workspace-tls-key /home/guomao/agentbridge/config/tls/server.key
--workspace-gateway-url ws://127.0.0.1:18789
--workspace-gateway-token-file /home/guomao/agentbridge/config/openclaw-gateway.token
```

Gateway Token 文件必须：

- 由部署管理员通过安全管道写入，不进入命令行、仓库、日志或数据库；
- 属于 AgentBridge 服务账号；
- 文件权限为 `0600`，父目录不可被普通用户写入；
- Token 轮换后立即替换服务器文件并重启 AgentBridge。

AgentBridge 第一次从 Linux 连接 OpenClaw 会产生设备配对请求。管理员在 OpenClaw
工作站核对设备名 `AgentBridge Workspace` 后执行：

```sh
openclaw devices list --json
openclaw devices approve <requestId> --json
```

设备私钥只保存在服务器
`data/workspace-gateway/device-identity.json`，权限为 `0600`。正常服务重启不需要
重复配对；删除该文件、清除 OpenClaw 已配对设备或轮换相应设备 Token 后才需要重新
批准。

当前链路不要求服务器入站访问工作站，也不需要为变化的工作站 IP 调整服务参数。
隧道由 `ai.agentbridge.workspace-tunnel` 管理；当前用户登录后恢复，SSH 断开后重连。启动和停止使用原生维护入口，不能再建立第二套任务管理器。停止隧道不删除中央会话或已落库时间线。

## 5. 用户操作

首次使用：

1. 打开 `https://10.10.50.213:8783`；
2. 选择“首次绑定”，生成配对码；
3. 在已经绑定 AgentBridge 的 Telegram 或微信私聊发送页面显示的命令；
4. 网页显示“身份已确认”后设置用户名和至少 12 位密码；
5. 进入工作台。

日常使用：

1. 使用网页用户名和密码登录；
2. 在“对话”中发起读取任务，或请假、出差正式提交任务；
3. 在“任务”中查看 Task Hub 状态、时间线和待处理可信交互；
4. 在“端点”中核对网页、Telegram、微信端点；
5. 退出只影响当前网页会话。

## 6. 安全边界

- 浏览器永远拿不到 MCP Token、Gateway Token、`userSubject` 或下游 Cookie；
- 网页账号不能自行选择或更换 `userSubject`；
- 两个用户的任务、事件、端点和 OpenClaw Session 均按 `userSubject` 隔离；
- Gateway 绑定凭证只能由对应身份兑换一次，错误身份和重放均失败；
- 网页聊天历史只返回用户和助手文本，不返回系统提示或工具内部消息；
- 跨端文本时间线只保存用户和助手的非敏感展示副本，不保存系统提示、工具参数、
  工具结果、凭据、Cookie、卡片字段值或授权决定；
- 可信卡片继续使用独立 HTTPS 页面，敏感字段不进入聊天；
- 同一执行授权为每个 Endpoint 生成独立 URL 和页面会话；
- 任一可信端可确认，但中心事务只接受第一个有效决定并只执行一次；
- 旁端只有确认权，不继承原 OpenClaw 会话的写 scope 或执行上下文；
- CSP 禁止第三方脚本、跨源连接和 iframe 嵌入；
- 登录失败按来源地址限流，密码使用 scrypt 哈希存储。

## 多端任务同步一期

自 `agentbridge-interactions` 0.4.5 起，Workspace、Telegram 和微信不再共享
同一个客户端端点记录。MCP Token 只决定用户身份和调用权限，客户端端点决定任务
来源、会话地址和通知路由。网页发起任务不会再覆盖 Telegram 或微信的会话资料。

任务建立后，已绑定端会订阅同一任务的关键事件，包括任务建立、执行中、等待用户、
完成、失败、取消和结果未知。具备 `trusted_interaction` 能力的端收到可操作卡片；
只具备状态能力的端只收到状态消息。自 `agentbridge-interactions` 0.4.8 起，已绑定
端还共享用户和助手的非敏感文本展示副本；敏感字段值、凭据和工具内部消息不复制。

业务字段填写卡和最终执行授权卡都按端点生成独立展示链接及 CSRF 会话。任意一端
先完成后，其他端再次打开会看到已处理状态，底层业务动作仍只会提交一次。

## 跨端任务接续二期

任务详情中的“继续任务”先在中心 Task Hub 为当前 Workspace Endpoint 选择目标
`taskId`，再向当前 OpenClaw 网页会话发送自然语言接续请求。浏览器不能提交
`userSubject`、Operation ID 或执行权限；中心端只允许选择当前网页登录身份拥有且属于
同一智能体宿主的任务。

Telegram、微信和 Workspace 中明确表达“继续刚才的任务”时，OpenClaw 使用宿主私有
MCP 解析最近任务。候选超过一条时只返回编号、标题、状态、来源端和更新时间，并将候选
顺序短期持久化；用户回复“第二个任务”后由中心按原候选集合选择，模型不能自行替换
`taskId`。选择结果包含由 Task Hub 和 AgentBridge 账本生成的非敏感权威摘要。

接续策略按任务现状收敛：

- 有待处理可信交互时，直接为当前 Endpoint 重显原 Interaction；
- Operation 正在运行时，只报告或观察状态，不发起第二次调用；
- 任务已成功、失败、取消或结果未知时，默认只报告权威终态；
- 用户明确要求查看详情、撤销、下载等新后续动作时，可沿用原 `taskId` 建立新的
  Operation，但仍经过 scope、可信交互、幂等和结果核验；
- 当前消息结束后，本地执行许可即清除，不能泄漏到下一条无关消息。

Task Hub 运行诊断同时统计接续状态，并检查 Endpoint、已选任务、候选任务的
`userSubject + agentHost` 一致性。诊断不返回聊天正文、业务字段或可信卡 URL。

## 网页应用卡与通知降噪

Agent Workspace 的对话区按 `taskId` 归并一次用户任务，但应用卡按 `interactionId`
稳定展示。同一用户指令只调用一个流程时通常只有一张卡；同时处理效能数据、周报等
多个独立流程时，任务列表仍只有一个任务，对话区会分别展示每个流程的字段卡和授权卡，
后一张卡不会覆盖前一张。卡片展示交互状态、影响、最新事件和对应操作入口；字段卡或
授权卡在另一端完成后，网页卡片通过 Task Hub SSE 自动更新到最终状态。刷新网页时，
进行中任务和最近六小时内的终态任务会从 Task Hub 重建，不依赖 OpenClaw 再生成
一条聊天回复。同一可信交互始终复用自己的卡片 DOM 节点和首次位置，后续状态只更新
该卡内容，不会把历史卡片删除后重新追加到对话末尾。

TaskEvent、跨端文本和应用卡更新共用 Task Hub 追加式时间线序号。SSE 首次连接从
当前最新序号建立游标，后续重连显式携带最后序号，不重放历史事件。普通任务进度
只更新应用卡，不再显示临时提示；只有失败和结果未知保留提示，同一异常会合并且
同时最多显示两条。

Telegram、微信等推送端只主动接收可操作的可信卡片、取消、过期以及最终成功、
失败或结果未知。任务创建、操作关联、执行中和交互完成等高频中间事件仍写入
Task Hub，但不再逐条发送聊天消息。Agent Workspace 是拉取式端点，直接读取统一
时间线和任务状态，不建立任务事件 Outbox 订阅。旧版本遗留的网页待投递任务事件
会在初始化时标记为已由时间线承接，避免离线网页形成历史重放积压。

纯读取能力成功后，`task.operation.succeeded` 仍完整写入 Task Hub 和审计记录，但
Telegram、微信不再额外发送一条“操作已完成”的中间状态；用户只看到按序同步的原始
请求和智能体最终业务回答。受控写入、可逆写入、失败、结果未知和应用卡状态不适用该
静默规则，仍按原有治理链路展示。

网页、Telegram 和微信产生的用户/助手文本通过宿主私有
`agentbridge_host_timeline_append` 写入中心时间线。每条消息带稳定幂等键；同一
微信回复即使同时经过两个 OpenClaw 发送 Hook，也只发布一次。中心 Outbox 按时间线
顺序投递到其他消息端，网页通过 SSE 按同一序号读取。来源端不接收自己的镜像消息，
网页历史也不会与中心展示副本重复渲染。

微信直推受通道的“本次入站消息令牌”约束。若端点长时间没有新消息，OpenClaw 只做
一次直投尝试；令牌无效时，中心把消息保存为 `deferred`，不在几十秒内连续重试。
用户下一次从同一微信私聊发消息后，该端点的延后消息恢复为待投递并获得新的尝试
额度。恢复严格限定为同一 `userSubject + endpointId`，不会唤醒另一用户或另一通道。

网页收到 OpenClaw 模型连接错误时会在原消息位置显示失败原因。只有精确中止已经确认，
且事件流或会话历史能够证明尚未调用任何业务工具时，才提供“重新发送”；已经出现工具
调用、无法取得核验证据或无法确认中止的请求不提供安全重试，以免对写操作造成重复执行。

## 宿主受理等待与恢复

Workspace 现在区分两个阶段：

1. `accepted` 之前是“把请求可靠交给宿主”；
2. `accepted(runId)` 之后是“观察同一个宿主运行”。

受理前请求保存在 `agent_host_dispatches`，低敏状态事件保存在
`agent_host_dispatch_events`。协调器按 `userSubject + agentHost + conversationRef`
保序，同一会话最多保留 3 条、同一用户最多保留 10 条未终态请求；不同用户可以并行。
同一幂等键和同一内容返回原 `dispatchId`，同键异参以
`IDEMPOTENCY_PAYLOAD_MISMATCH` 拒绝。

协调器先调用只读 `system.info` 做语义就绪检查。链路不可达时按
`1、2、3、5、8、10...` 秒退避，默认 60 秒；恢复后重新签发一次性 Gateway grant，
并用原幂等键投递。`queued` 和 `waiting_host` 可以由用户取消，进入 `dispatching`、
`reconciling_acceptance` 或 `accepted` 后不能取消。

收到 `accepted(runId)` 后永久关闭该 dispatch 的再投递资格。连接中断时通过
`chat.history` 查找同一 run 的权威结果；请求可能已经发送但 accepted 回执缺失时，
只在原截止窗口内按幂等键核对。查到原 run 后继续观察，无法证明是否受理则进入
`acceptance_unknown`，不会为了追求成功率制造第二个业务运行。

浏览器的 SSE 断开不会关闭后台 Gateway 流。刷新页面后，Workspace 调用
`/api/chat/dispatches` 恢复“请求已保存”“正在恢复连接”“正在确认是否接收”或
“智能体已开始处理”的稳定状态区；最终回答和失败结论仍通过用户时间线跨端同步。
管理控制台显示活动宿主投递、连接恢复等待和受理不确定数量，运行诊断同时检查
dispatch 与 Workspace 账号、发起端点和 `accepted_run_id` 的主体一致性。

OpenClaw 的 15 秒启动看门狗、300 秒运行预算、工具活动证据和发布 Warm-up 仍在宿主
适配器内部生效。可靠投递只覆盖 `B0_NO_EFFECT` 的受理前边界，不扩大业务写入自动重试
权限，也不修改 OpenClaw 源码。详细状态机、故障分类和验收矩阵见
[工作台请求受理前可靠投递详细设计](../架构设计/工作台请求受理前可靠投递详细设计.md)，线上
故障注入证据见[工作台受理前可靠投递验收](../验收记录/工作台受理前可靠投递验收-2026-08-30.md)。
