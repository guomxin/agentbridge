# 业务技能质量与持续沉淀二期

日期：2026-10-03。状态：已实现并部署；自动化回归通过，2026-10-04 补完线上控制台审批、个人发布、真实加载与双用户隔离验收。沿用普通用户创作、个人与共享发布均需管理员审批、Skill 不授予业务权限的产品决定。

## 目标和实施顺序

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 1 生成与治理 | 类型化创作合同、静态诊断、线上/草稿状态、版本和受众差异、用户选择 | 无业务授权可创作；越权不可读；旧草稿可编辑；错误字段可定位 |
| 2 独立评测 | 持久评测任务、无工具模型执行、固定样本、候选/线上/无 Skill 对照、规则评分、审批快照 | 评分答案不进入被测提示；无业务工具；失败不能报通过；报告绑定内容哈希 |
| 3 过程沉淀 | 范围化开关、过程材料、方法/偏好/事实分类、相似候选、持久生成、重试/取消 | 关闭后不保存自动结果；跨用户隔离；不递归生成；不自动发布 |
| 4 运行与复用 | 候选检索、按需参考文件、组合方法检查、版本反馈与效果汇总、标准包适配 | 权限先于检索；资源绑定固定版本；不扩大授权；导入仅私有草稿 |
| 5 联合验收 | 定向/全量测试、Chrome 工作台和控制台验收、发布文档 | 简短人类提示词；区分程序契约通过和实际模型质量 |

## 关键设计

1. 保留当前快速试用及旧 API。增加结构化方法（输入、步骤、异常、验收）、静态诊断和独立评测。静态诊断不冒充语义正确性；旧发布内容不被原地修改。
2. 独立评测只运行文本和合成证据。通过 OpenClaw 的公开 simple completion SDK 调用已配置模型，无工具、无会话历史、无工作区文件、无代理执行循环。业务动作只评估其计划/边界，报告明确不证明真实业务执行。无需为此建立第二套模型密钥。
3. 评测样本与断言冻结；每个样本分别运行候选、线上（如有）和无 Skill 基线，支持重复。断言在服务端执行，不能传给被测模型。未覆盖的语义项保留人工复核状态。审批固定评测报告；不能用模型自报样例替代独立结果。
4. 生成与评测共享 SQLite 持久任务队列。任务由 Workspace 服务工作线程执行，以租约和尝试次数恢复；中心 MCP 只入队。任务状态为 queued/running/succeeded/failed/canceled，租约过期重新领取，完成以 token 校验防止旧 worker 覆盖新结果。幂等结果与草稿保存必须可恢复。
5. 自动沉淀授权按用户及会话范围保存；仅处理获准范围内新完成的交互。用户可关闭、排除会话、取消任务。内容先分类：方法可形成草稿；偏好与事实形成仅自己可见的候选说明，不自动改共享方法。宿主材料不升级为中央已验证证据。
6. 去重使用确定性文本相似度提供候选，不宣称完备语义理解。自动更新仅限同一作者、明确关联的草稿和未变更修订；歧义或并发变化保存为候选供选择，不覆盖用户编辑。
7. 发现先按权限过滤，再对目录排名；保留完整目录入口，避免检索漏召回成为永久隐藏。必读约束继续完整加载，可选参考文件通过固定绑定读取。多步骤复用显式列出方法及输入输出，每一步重新验证可用性；不允许 Skill 文本递归委派或扩大能力。
8. 标准导入导出采用包含 SKILL.md 和 references 的文件映射，校验 YAML 元数据与路径、大小；不执行 scripts，不相信包中权限。内部 manifest 保留中央模式和权限语义。业务来源、用户身份、评测与审批不随包导出。
9. 用户反馈关联已分配的具体版本，记录有效/有误/不适用及纠正。报表分别显示模型评测、用户反馈和加载数量，不能把加载次数作为成功率。

## 界面

Workspace 展示线上版本、当前草稿修订、待审批状态；提供方法诊断、评测样本编辑/启动/状态/对照、后台生成状态/取消重试、范围化自动沉淀、候选分类、标准包导入导出、版本反馈。共享受众使用可见用户选择器，服务端仍验证身份。

控制台列表展示名称和修订；详情展示方法、依赖、范围差异、固定评测报告与未验证项。管理员仍可退回/拒绝；通过条件由服务端检查，不仅依赖前端勾选。已发布版本的恢复仍走新修订与审批。

## 测试约束

验证身份隔离、失效租约、重启恢复、幂等、取消、关闭自动沉淀、固定样本与报告、恶意包路径、资源授权、模型失败和空响应、评分回归。真实模型测试使用合成文字和简短提示，业务权限与真实业务数据保持现有边界。

## 实施记录

- 2026-10-03：确认 Chrome 扩展连接、xinguomao Workspace 与管理控制台现有页面。现有草稿修订 2 和线上 1.0.0 保留。设计采用宿主公开无工具模型调用，避免另配模型凭据或把普通 Agent 会话误当隔离评测。
- 创作工具保留 action/data 兼容入口，将 data 及 proposal 改为可发现的 Pydantic 类型合同；服务端按 action 校验字段。规范化方法附加输入、步骤、异常和验收，已有草稿继续可编辑。
- 独立评测冻结样本、候选与线上快照，断言仅在服务端评分。支持正负触发、包含/排除断言和 1—3 次重复。通过的结果样本可满足对应模式的提交条件；失败报告冻结到申请并阻止批准。没有独立报告的申请保留人工路径，但批准须额外说明验证方法，仍标记未独立验证。此兼容调整避免旧草稿和模型暂不可用时无法人工审核。
- 后台 worker 运行于 Workspace 服务，MCP/控制台不各自启动模型循环。模型调用复用生产宿主配置；独立 SDK 不安装工具、不加载宿主会话。候选/线上/无 Skill 比较是纯文本方法评测，不宣称与全部宿主的真实工具路由行为等价。
- 新增五张表（skill_jobs、skill_auto_scopes、skill_review_quality、skill_feedback、skill_auto_capture），原表不改列。工作台完成事件与 auto_capture 在一个事务内提交；后台处理幂等，启用范围后仅收集新事件。附件和助手创作过程不自动提炼。自动保存和 job 完成原子提交，取消或失效租约不能提交草稿。
- 范围开关独立于总开关，旧用户不自动扩大采集范围。生成分类保留方法/偏好/事实/无需沉淀；后两者只呈现私有候选说明，不实现通用个人记忆系统。相似匹配使用可解释文本相似度，候选可人工采用为新草稿或指定修订，不能称为完整语义去重。
- 大目录宿主上下文最多列 20 项候选，显式提示 discover 回查；中央检索仍先按权限过滤。可选资源按有效绑定取固定快照，必读说明仍完整返回。组合提供最多八步输入输出/版本/依赖预检，执行继续由原有任务与持久计划负责，不新增隐式递归执行器。
- 标准兼容交付为 agentskills.files.v1 JSON 文件映射，内含带 YAML 头的 SKILL.md 和 Markdown references。支持标准标量元数据子集；不支持 ZIP、任意 YAML 标签、scripts 或 assets。导入不带原包权限、身份和历史，须重新审核。这是受限适配器，不宣称完整实现全部可选标准。
- 当前评分器验证明确断言；开放语义仍由人工审核。没有新增未经校准的 LLM 自动裁判，也没有把单次通过转成生产成功率。后续真实业务回放、自动语义评分、跨宿主执行和脚本隔离需要独立合同与证据。

- 联合验收发现首次模型生成偶发无效 JSON，补充一次有上限的格式重生成；每次调用前检查取消、租约与自动范围，连续失败不保存。工作线程生命周期绑定服务运行，避免仅构造应用就启动后台线程。详见[验收记录](../验收记录/业务技能质量与持续沉淀二期-2026-10-03.md)。
