# AgentBridge 受控写模型

> 状态：当前权威说明。具体协议字段以
> [智能体交互协议](./智能体交互协议.md) 为准。

## 1. 目标

AgentBridge 对外暴露工作流级业务能力，例如提交请假、审批补签、创建会议或填写
工作日志。底层按钮、页面脚本和后台 API 都是适配器内部实现，不作为通用原子工具
交给智能体。

受控写必须同时满足：

- 用户身份、目标系统会话和调用 Token 一一绑定；
- 用户提供的敏感字段不进入模型可见上下文；
- 执行前冻结完整业务计划并单独授权；
- 每个提交边界最多执行一次；
- 成功必须由目标系统权威回读证明；
- 结果未知时停止，不自动重试。

## 2. 标准生命周期

1. **识别业务意图**：智能体选择工作流级 prepare 工具，并把用户已经明确提供的值
   作为可编辑预填项。
2. **收集业务字段**：可信字段卡直接把表单值提交给 AgentBridge，模型只得到不透明的
   `interactionId` 或 `inputSubmissionId`。
3. **实时准备**：适配器检查当前登录态、模板、字段、候选项和业务前置条件，生成不可变
   计划；任何实时差异都在此阶段阻断。
4. **独立授权**：可信授权卡向用户展示即将执行的业务摘要。草稿、正式提交、审批、
   撤销和会议创建使用相互独立的权限范围。
5. **单次提交**：commit 工具校验调用者、计划、授权、幂等键和实时目标身份，在最终
   写入边界前消费授权。
6. **权威验证**：适配器从目标系统重新读取已发、待发、待办、会议或日志记录，确认
   数量、稳定 ID 和关键字段。
7. **结果投递**：宿主直接向原私聊返回成功、业务拒绝或结果未知；不会把可信卡 URL、
   密码、Cookie 或完整业务字段重新交给模型。

登录是独立的可信交互。登录完成后，宿主可以恢复原请求，但不得把读取请求和写请求
相互推断或替换。

填写和授权可以在同一可信办理页接续，后台仍保存独立输入、不可变计划与授权事实。
连续页由原任务协调器续办，页面不能执行 commit。全量 25 个有字段动作按固定版本 profile
自动保存私有草稿、只读预检，以具体业务按钮一次记录输入和明确授权；3 个无字段照明动作直接
核对并授权。旧未登记来源保留原字段合同。授权完成先显示“已授权”，只有原提交操作的权威结果才能显示办理成功。
范围和证据见[全业务实施记录](../验收记录/全业务办理界面实施与验收-2026-10-15.md)。

草稿修订和流程版本分开递增，最终决定只接受当前修订及服务端生成的不可变预览。
原任务、业务助手、计划步骤及其不存在的事实在源输入创建时冻结；丢失关联不能退化为
无约束任务。预检检查会话主体、项目解析与重复日志，不创建授权、不写业务系统。
修改会使旧预览失效，多页面冲突保留本地内容并由用户选择。预览有效期为五分钟，
且不超过原输入有效期；批准后草稿不可修改。

最终决定在一个 SQLite 事务内保存字段、已批准授权、交互、任务/计划关联及恢复回执。
原输入的不可变 resume 合同保持不变，由明确的回执关联返回对应授权；字段在授权消费
边界同事务消费。重启和响应丢失恢复原回执与原操作，不重新 prepare，不再次写入。
过期未批准草稿清除输入副本和预览，最终决定保留必要归因，字段和授权继续按原审计规则保存。
会议室候选另存修订绑定的只读快照，绑定时段、房间稳定 ID 与名称；时间变化后旧选择
不再有效，不能静默替换。除具有原日志专门核验合同的日志外，最终决定前还会释放数据库写锁做只读重核，
语义变化产生新预览并要求再次确认，事项身份变化直接拒绝。重核不生成第二份授权。

14 类 OA 只读材料独立于公开读取预算：正文、原字段、已有意见、附件名称及明细行一起绑定材料指纹；缺失框架或超过上限时失败关闭。附件正文与源系统未展开历史不计入完整性承诺。仅原合同的处理意见可修改。

混合待办和补签批次对当前项逐一执行相同最终决定，同时绑定原任务、批次、持久项、目标、顺序与精确版本；成功后页面提供明确“核对下一项”，未知、失败或取消不推进。不能把一次当前项确认解释为批量授权。额外 OA 警告需要新明确决定，后继授权必须验证原任务的准确警告操作链、不可变计划只追加一条提示以及批次精确增量。旧未登记来源和已有授权保持原合同。

## 3. 信任边界

| 边界 | 可以看到 | 不可以看到 |
| --- | --- | --- |
| 智能体 | 工具描述、非敏感摘要、不透明 ID、最终状态 | 密码、Cookie、字段卡完整提交值、授权密文 |
| 交互宿主 | 可信交互元数据、卡片入口、轮询状态 | 下游凭据明文和会话密文 |
| Credential Broker | 临时凭据、预期身份、登录结果 | 普通聊天内容和业务决策 |
| 中心 Worker | 绑定用户的加密会话、适配器计划、目标系统响应 | 其他用户会话和未授权能力 |

每个 Telegram、微信或其他宿主身份都必须映射到独立 AgentBridge Token。Token 只绑定
唯一 `userSubject` 和最小权限集合；每个下游系统的预期与已验证主体按 `(userSubject, systemId)` 独立保存。
不同系统可以使用不同账号或显示名；任一系统的主体不匹配只隔离该系统会话。

## 4. 结果语义

| 状态 | 含义 | 后续动作 |
| --- | --- | --- |
| `succeeded` | 写入完成且权威回读匹配 | 返回稳定业务 ID 和核验摘要 |
| `requires_user_action` | 等待登录、字段输入或授权 | 展示对应可信卡并在完成后恢复 |
| `business_rule_rejected` | 目标系统明确拒绝 | 返回清洗后的业务原因，不重试 |
| `outcome_unknown` | 已越过提交边界但无法确认结果 | 停止；先人工或只读核对 |
| `failed` | 提交边界前的确定性失败 | 修正输入、权限或会话后重新 prepare |

任何网络超时、页面崩溃或下游异常，只要发生在最终点击或提交请求之后，都必须按
`outcome_unknown` 处理。

## 5. 权限与幂等

- 读取、草稿、正式提交、审批、撤销、会议和泰华日志写入分别授权。
- 写权限不会因为部署新能力、完成卡片或登录而自动扩大。
- prepare、授权和 commit 必须绑定同一用户、系统、能力、计划摘要和目标身份。
- 幂等键重复调用返回原操作；不能生成第二份草稿、流程、会议或日志。
- 授权只在最终写入边界前消费；过期、已消费或身份不匹配时失败关闭。
- 持久计划的取消与授权消费共用数据库事务边界；已消费授权的在途提交只能等待核验或对账，不能显示“已取消”。
- 计划字段续办、授权续办和 commit 均复核原执行权限及冻结版本，同用户更换 Token 不会隐式替换原计划授权。
- 提交边界后的传输、解析或回读异常进入 `RESULT_UNKNOWN`；只对权威确认的业务拒绝标记确定失败，不自动补发。

## 6. 新能力准入

每个新工作流至少需要：

1. 明确输入字段、系统计算字段、候选项和必填规则；
2. 明确 prepare、commit 和 verify 的责任边界；
3. 确定提交前失败与提交后结果未知的分界点；
4. 使用工作流专属适配器，不发布任意 URL、任意脚本或通用点击工具；
5. 覆盖权限拒绝、跨用户拒绝、授权过期、幂等重放和业务规则拒绝测试；
6. 在真实系统中完成一次 prepare 验证；真实提交必须获得该具体事项的明确授权；
7. 可撤销流程也不能把撤销当作无副作用的自动清理。

具体实施顺序见 [OA 写能力扩展手册](../系统适配/协同办公系统/写入能力扩展手册.md)。

## 7. 发布验收

- 运行 Python 全量测试、`compileall`、`pip check`；
- 运行 OpenClaw 插件测试和 npm pack 检查；
- 通过正式 HTTPS MCP 执行只读 Release 冒烟；
- 涉及插件时重启 Gateway 并核对深度 RPC 和插件版本；
- 涉及中心包时部署版本化 wheel，核对 systemd 进程、模块来源和工具目录；
- 不使用旧浏览器桥、localhost daemon 或员工个人浏览器 Profile。

发布命令和证据要求见
[开发验证与发布流程](../部署运维/开发验证与发布流程.md)。
