# Pi 宿主接入 Workspace 和首账号 Telegram 私聊

Pi 作为第三个独立宿主接入同一个 Workspace、中央 MCP 和任务系统。产品基线取 OpenClaw 和 NanoBot 在已开放端点提供的功能并集。首轮交付两个账号的 Workspace 和第一账号的 Telegram 私聊。OpenClaw 另有微信私聊，其现有用户在首轮参加回归。Pi 自身的微信接入另设里程碑。首轮候选分别固定 Pi Coding Agent 1.6.0 与 AgentBridge 适配器 0.1.0。[功能对照与分阶段实施方案](../后续规划/第三宿主功能对齐与分阶段实施方案.md) · [多宿主设计](./工作台并列智能体宿主与默认实例设计.md) · [Pi SDK](https://github.com/earendil-works/pi/blob/v1.6.0/packages/coding-agent/docs/sdk.md)

## 账号及使用体验

本机安装与渠道准备的实际结果见[准备记录](../验收记录/第三宿主安装与电报准备-2026-11-25.md)。

| 主体 | Pi Workspace | Pi Telegram |
| --- | --- | --- |
| 第一账号 | 可选为默认宿主，以本人的业务权限使用 | 允许一个经过核验的本人私聊。可从原消息找回任务，在网页完成登录或授权，由原协调者续办并回到原私聊 |
| 第二账号 | 同样可选，使用自己的历史、文件和业务凭据 | 本人 Workspace 隐藏此 Bot 的配对入口和日报收件端。即使在 Telegram 找到公开 Bot，直接配对、发消息、尝试领取文件或历史通知也要被拒绝 |
| 其他主体 | 本次未分配 | 私聊、群组、频道和转发消息均不能取得试点资格 |

建议实例 ID 取 `pi-office`。第一账号由外置配置明确指定中央主体，并与已核验的 Telegram 数字用户 ID 匹配。账号排序、显示名、Bot 所有者或第一个发送消息的人均不能决定业务身份。Web 开放名单与 Telegram 开放名单分开保存，渠道名单缺失时关闭该渠道。新宿主可用后由用户选择默认值，已有派发、卡片、会话及文件继续归原实例。首轮第二账号的 Pi 会话只能交付到本人网页。

## 派发、工具与业务终态

| 层次 | 实现职责 |
| --- | --- |
| Linux 中央与 Workspace | 复用账号、实例目录、入口派发、任务、授权、文件和投递账本。将现有宿主名称分支改为检查登记实例、已核准能力、本人渠道资格和当前绑定。管理台按实例显示连接、版本、能力、用户与停用状态。[Workspace 装配](../../agentbridge/cli/main.py) · [中央工具下发](../../agentbridge/mcp/central.py) |
| 受管 Mac 上的 Pi 适配器 | 以专属运行目录和回环监听接单，中央通过认证的独立隧道连接。先按主体与原请求键持久受理，再启动 Pi SDK。保存实例、端点、会话、载荷摘要和原运行 ID，提供就绪、事件、查原运行和取消。浏览器刷新只断开订阅。取消排队、停止模型生成和取消仍可取消的业务任务分别回报结果。两账号各有受隔离的会话目录、工作目录和个人 MCP 凭据引用。 |
| 模型工具 | 适配器核对当前主体权限及选中技能，显式装入获准读取与准备工具。业务会话关闭默认 shell、本机文件读写以及个人扩展自动发现。附件通过受控入口按主体和有效期读取。临时文件按本次运行清理。技能试用和草稿评测按固定版本取证。 |
| 可信交互与协调 | Pi 的标准 MCP 包装会移除结果顶层私有 `_meta`。受控工具在结果转换前拆出私有信封，并从公开内容、结构化结果、工具详情及错误中筛除私有字段，只向本人已绑定的可信页面或私聊递送信封。Pi 的工具事件、会话文件、压缩摘要和日志只接收公开结果。复用现有 Python 协调器，按受信配置绑定 Pi 实例、实现版本、主体和原任务租约。提交按中央准备、一次性授权、执行、权威核验进行。断线后查询原操作，终态未知时停止重放。[Pi 结果转换源码](https://github.com/earendil-works/pi/blob/v1.6.0/packages/coding-agent/src/extensions/mcp/tools.ts) · [现有协调器](../../integrations/reference-host/reference_host/bound_coordinator.py) |

### Pi 适配器的进程与接口

受管 Mac 的实现由 Pi 专用 Python 适配器和 Node SDK 工作进程组成。Python 侧持有接单账本和到中央的认证连接，进入 L3 后使用与 Pi 实例绑定的协调器。Telegram 消费者单独启停。复用接单、配对、卡片和投递中与 SDK 无关的实现及数据格式。Pi 使用独立宿主运行与收发账本、游标和进程锁。NanoBot 旧接口继续服务原实例，存量账本、旧任务、旧卡及旧消息回执仍属原实例。Pi 的启动、就绪、回执查询和续办均须能在 OpenClaw 与 NanoBot 离线时独立完成。[现有 Workspace 网关客户端](../../agentbridge/workspace/nanobot_gateway.py) · [现有 NanoBot 宿主模块](../../integrations/nanobot-agentbridge/nanobot_agentbridge)

| 边界 | 输入、输出与故障处理 |
| --- | --- |
| Workspace → Pi | `ready` 报告实例、适配器版本和当前可用能力。接单以已认证绑定及原始请求键返回运行 ID。事件游标可断点读取，收据缺失时按原身份查原运行。同键但消息、附件顺序或试用修订有差异时报告冲突。文件续签、准备指令与结果视图均核验原任务归属。 |
| Python 适配器 ↔ Node 工作进程 | 每次运行通过受控标准输入输出交换带运行 ID 的结构化消息。Node 显式创建 Pi 模型、会话管理器和工具集，仅向 Python 请求本次已获准的工具和业务参数。Python 根据启动时绑定的主体、端点、协调权和当前配对复核请求。Node 可接收本次模型请求获准的附件，Bot 密钥、下游凭据和中央协调权只由相应的受信进程持有。 |
| Pi → Workspace 时间线 | 订阅 SDK 的文本增量和公开工具进度。收到 `agent_settled` 后结束本轮生成，区分成功、中止和错误。较早的 `agent_end` 可能早于自动恢复。进程异常退出时按受理账本和中央任务核对。业务办理以中央 Operation 的权威回读为终态，渠道送达另记回执。[Pi 事件语义](https://github.com/earendil-works/pi/blob/v1.6.0/packages/coding-agent/docs/json.md) |

生产启用条件取中央登记的适配器版本、核准等级、本次运行的受信能力、用户权限与当前端点资格的交集。账号开通、默认实例、技能试用来源、文件续取及通知认领等现有分支需逐项接入。管理台应能分别说明模型不可用、中央连接不可用、本人业务需登录和渠道未获准。[实例开通](../../agentbridge/workspace/host_provision.py) · [宿主契约](../../agentbridge/core/host_contract.py) · [端点归属](../../agentbridge/core/endpoint_instances.py)

## 首账号 Telegram 配置

使用 Pi 专用 Bot、钥匙串条目、更新游标、进程锁和收发账本。Bot 密钥只由受管 Mac 上的渠道进程读取。外置配置记录 Bot 公开数字 ID、用户名、钥匙串引用、允许的中央主体及数字发送者。首账号可用已有的、能复核到同一主体的数字身份，或在本人已登录 Workspace 与 Pi 私聊间双向配对。配对证据绑定本次实例、Bot、主体、发送者、端点和有效时段。

中央在展示渠道、签发和确认配对、创建任务、认领通知与实际发送前执行相同的授权判断。渠道进程先核对私聊类型与发送者再派发，撤销或换绑使原排队消息停止投递。普通聊天可以双向展示，每条输入只在发起端运行一次模型。登录、授权、文件和历史卡走各自的专用路径。引用旧消息要追溯原回执。关注和日报只能选择本人当前获准的端点。发送回执不明时保留原记录供对账。

入站以 Bot、私聊和消息 ID 持久去重，连续更新完成处理后再推进游标。进程在接单后或发送中断时，先按原键核对受理及投递记录。隔离测试要分别在“接单后、游标落盘前”和“已发出、回执落盘前”中断进程，前者只能恢复原运行，后者保留待核对的原投递。[既有渠道收件与恢复](../../integrations/nanobot-agentbridge/nanobot_agentbridge/telegram.py)

安装和配置由实施方执行。Pi 使用固定版本的独立安装目录。试点模型用独立授权，凭据与其他宿主分开。Bot 上线前从指定钥匙串引用在作业身份下调用官方 `getMe` 比对公开身份，用 `getWebhookInfo` 检查 webhook 为空，核对本机唯一消费者和中央名单后启动。任何所有权冲突均先查明归属。生产配置、个人 ID 及密钥均保存在仓库外。[既有私聊运维约定](../部署运维/独立电报机器人试点.md) · [Telegram 官方 Bot 管理](https://core.telegram.org/bots/features#botfather)
