# 智能体可信交互协议

> 状态：当前协议基线
>
> 适用版本：AgentBridge 主线、OpenClaw `2026.7.1`、`agentbridge-interactions` `0.4.49`
>
> 目标：让任意智能体宿主在不接触秘密和最终授权能力的前提下，可靠展示、轮询并续办可信交互。

## 一、用途

遗留系统自动化经常需要模型不能代替用户完成的步骤：

- 输入账号、密码、验证码或完成滑块、短信验证；
- 补充业务字段；
- 核对冻结计划并批准一次有副作用的操作。

AgentBridge 把这些步骤统一为 `agentbridge.interaction.v1`。宿主只接收经过脱敏的交互信封和
短期展示入口，不接收秘密值、完整业务字段、Cookie、授权凭据或底层提交参数。

当前交互类型：

| 类型 | 用途 | 用户动作 |
| --- | --- | --- |
| `credential` | 建立或恢复下游登录会话 | 输入凭据、验证码或完成交互式浏览器登录 |
| `business_input` | 补充业务表单字段 | 填写、选择并确认允许的业务字段 |
| `execution_authorization` | 批准冻结计划 | 核对目标、影响和关键字段后批准或拒绝 |

认证挑战、字段提交和执行授权分别保存在服务端独立账本中。统一信封只负责宿主展示和恢复，
不会降低原有一次性消费、用户绑定、会话绑定和审计边界。

## 二、交互信封

标准结构：

```json
{
  "protocolVersion": "agentbridge.interaction.v1",
  "interaction": {
    "id": "opaque-id",
    "type": "business_input",
    "status": "pending",
    "expiresAt": "2026-08-19T10:30:00Z",
    "display": {
      "title": "填写出差申请",
      "summary": "请核对已识别信息并补齐必填项",
      "system": "oa",
      "actionLabel": "填写信息",
      "url": "https://trusted-host/input/opaque-token"
    },
    "binding": {
      "userSubject": "user-reference",
      "system": "oa",
      "capability": "oa.business_trip.submit.prepare",
      "operationId": "operation-reference",
      "taskId": "task-reference"
    }
  },
  "resume": {
    "ready": false,
    "tool": "agentbridge_interaction_resume",
    "arguments": {
      "interaction_id": "opaque-id"
    }
  }
}
```

### 2.1 状态

| 状态 | 含义 | 是否可续办 |
| --- | --- | --- |
| `pending` | 等待用户操作 | 否 |
| `processing` | 服务端正在验证或提交 | 否 |
| `completed` | 用户步骤完成且服务端接受 | 是 |
| `rejected` | 用户拒绝或服务端拒绝 | 否 |
| `cancelled` | 用户或系统取消 | 否 |
| `expired` | 交互已过期 | 否 |
| `failed` | 交互处理失败 | 否 |
| `superseded` | 已被同任务的新交互替代 | 否 |

只有服务端能改变状态。聊天消息、模型文本、客户端按钮标签和宿主本地缓存都不能作为授权事实。

### 2.2 展示字段

`display` 只能包含用户可见且可进入聊天或页面的脱敏信息：

- 标题、摘要、系统名称和动作标签；
- 可信 Origin 下的短期 URL；
- 非敏感目标摘要；
- 对当前终端适用的展示提示。

不得包含：

- 密码、验证码、Cookie、会话 Token；
- 完整业务字段值或隐藏表单字段；
- 执行授权 Token、计划内部哈希或提交接口；
- 浏览器调试端口、VNC 临时密码、CDP 地址；
- 可绕过可信页面直接改变交互状态的参数。

### 2.3 绑定字段

交互至少绑定：

```text
userSubject + system + capability/version + operationId + taskId + TTL
```

需要下游会话时还绑定 `sessionId`，需要冻结计划时还绑定计划哈希、目标标识和授权版本。
跨用户、跨系统、跨会话、跨任务、过期或已消费的交互一律拒绝。

## 三、MCP 投影

AgentBridge 通过 MCP 返回普通结构化结果和可选界面元数据：

- `structuredContent`：只包含脱敏交互信封；
- `_meta.ui.resourceUri`：指向可信交互界面资源；
- 工具注解：声明只读、幂等和破坏性提示；
- 宿主私有元数据：传递 `taskId` 等不会进入模型参数的协调信息。

模型可见工具：

- `agentbridge_interaction_get`：读取一个属于当前用户的交互状态；
- `agentbridge_interaction_resume`：消费一个已经完成的交互并续办原操作；
- 各系统的受治理准备入口，例如 `oa_leave_submit_prepare`。

模型不可见工具：

- 内部 commit 和恢复工具；
- Task Hub 投递和端点管理工具；
- 能直接填写字段、批准计划或改变交互状态的工具。

OpenClaw `2026.7.1` 会丢弃部分顶层 `_meta`。兼容插件从经过验证的结构化结果中恢复必要的
界面元数据，但仍只允许固定协议和固定可信 Origin，不接受模型提供的 URL 或界面资源。

## 四、宿主算法

宿主收到工具结果后按以下顺序处理：

1. 验证 `protocolVersion`；
2. 验证交互类型、状态和 URL Origin；
3. 将交互绑定到当前宿主任务和用户端点；
4. 在所有符合权限和展示能力的用户端显示同一服务端交互；
5. 等待用户完成，不在模型对话中索取字段或批准；
6. 轮询或接收完成通知；
7. 只有 `resume.ready=true` 时调用固定续办工具；
8. 把最终业务结果写入同一任务时间线并停止轮询。

卡片的**展示端**和交互的**续办归属**是两个概念。Workspace 发起的任务可以把同一张卡展示到
Telegram、微信等伴随端，但 Interaction Driver 必须始终按任务的 `activeConversationRef` 恢复
原 Workspace 会话、登记轮询并携带原 `taskId` 续办。异步通知泵不能只把卡片发到伴随端后就
确认投递；即使模型工具结果经过安全脱敏、不再包含完整交互信封，也必须从 Task Hub 通知恢复
轮询。任一端完成字段卡后，下一张授权卡和最终结果仍回到同一任务时间线，多端只负责展示，
不能改变任务所有权。

宿主重启时，恢复查询必须以已认证 `userSubject` 为边界枚举该用户在同一宿主下的活动端点，
而不能只查询 Telegram 或微信配置端点。恢复范围同时包括 `pending/processing` 交互和
`completed + resume.ready=true + resume.completed=false` 的已填未消费交互；后者直接使用原
交互 ID、原任务 ID 和稳定幂等键续办，避免用户填完字段后因 Gateway 重启永久停在中间状态。
恢复扫描发现当前交互已经 `declined/expired/failed/superseded` 时，还必须把同一终态对账回
Task Hub；不能仅跳过恢复，否则网页会长期保留一个实际已经结束的“进行中”任务。

伪代码：

```text
result = call(governed_entry)
interaction = parse_and_validate(result)
publish_to_eligible_endpoints(interaction)

while interaction.status in {pending, processing}:
    interaction = bounded_poll(interaction.id)

if interaction.status == completed and interaction.resume.ready:
    outcome = call(interaction.resume.tool, interaction.resume.arguments)
    publish_authoritative_outcome(outcome)
else:
    publish_terminal_interaction_status(interaction.status)
```

宿主必须设置有界轮询、退避、整体超时和同轮重复调用保护。页面端通过 Task Hub 的 SSE/拉取
读取状态，不应为了投递网页消息而额外唤醒模型。

### 登录后的单项读取恢复

对同一用户、同一任务中明确因 `LOGIN_REQUIRED` 中断的单项读取，中央续办从操作账本恢复
原能力和完整查询参数，复用原操作与认证交互绑定的幂等键；当前 Token 仍需满足原查询的细分
权限。历史写操作的脱敏摘要不能作为可重放输入，组合计划和批量任务保持各自的续办归属。

中央返回 `nextAction.type=original_request_completed` 时，原查询已收敛或原任务已终态。
宿主应读取 `status`、`taskStatus` 和 `error` 区分成功与失败，停止该交互的恢复轮询，不重复执行
读取、不再发送一份结果、不唤醒模型。反馈已经进入中央时间线和同用户消息发件箱。

`retry_original_request` 仍用于没有中央单项读取绑定的兼容情形，不等于中央已经执行业务。
宿主直接重试业务工具时必须携带正式宿主上下文、原任务和适用的协调租约版本，不能只发送任务编号。

## 五、多端展示与单次完成

同一个交互可以在 Workspace、Telegram 和微信同时展示，但服务端状态只有一份：

- 多端可以看到相同标题、摘要、状态和可信入口；
- 任一合格端完成后，其他端同步显示已完成；
- 重复提交、旧页面提交和交叉身份提交会被拒绝；
- 新交互替代旧交互时，旧交互进入 `superseded`，不长期显示“进行中”；
- 交互完成后，原任务继续执行，其他端同步收到后续文本和终态。

多端任务、端点和时间线规则见 [多端智能体任务接续设计](./多端智能体任务接续设计.md)。

## 六、MCP Apps

支持 MCP Apps 的宿主可以直接渲染 `ui://agentbridge/trusted-interaction.html`：

- 界面只能向 AgentBridge 固定可信 Origin 发起请求；
- 认证卡、字段卡和授权卡保持不同页面语义；
- 界面不能通过模型参数获得秘密；
- 宿主关闭界面后仍可通过交互 ID 恢复；
- 不支持 MCP Apps 的宿主使用 HTTPS 可信卡链接或私有宿主适配器。

MCP Apps 是展示方式，不改变服务端授权与账本状态机。

## 七、CLI 与开发验证

CLI 用于开发和故障定位，输出同一信封：

```bash
python -m agentbridge.cli.main --home .agentbridge capability invoke <能力名> \
  --user-subject <用户主体> \
  --json '{}'
```

开发环境可以使用本地浏览器打开可信卡，但不能把 CLI 输出中的控制值粘贴到聊天或测试日志。
Codex 验证真实页面时应使用项目约定的浏览器控制方式；涉及真实业务写入仍必须由用户通过可信
授权卡明确批准。

## 八、OpenClaw 适配

`agentbridge-interactions` 是宿主兼容层，不复制业务逻辑：

- 根据 Telegram、微信或 Workspace 的可信宿主上下文选择身份；
- 按 Token scope 裁剪模型可见工具；
- 将服务端交互投递到合格端点；
- 维持有界轮询、自动续办和完成通知；
- 把文本、卡片、图片和文件写入同一 Task Hub 时间线；
- 防止网页拉取端被误当成聊天直推端；
- 隐藏 commit、任务协调和内部恢复工具。

插件不修改 OpenClaw 核心源码，升级 OpenClaw 后通过版本兼容检查、插件测试和真实宿主验收
确认可继续使用。

## 九、错误语义

宿主应保留 AgentBridge 的明确错误码，不用含糊文本覆盖：

| 错误 | 处理 |
| --- | --- |
| `LOGIN_REQUIRED` | 展示登录卡，完成后自动恢复原任务 |
| `FIELD_INPUT_REQUIRED` | 展示字段卡，不在聊天中收集字段 |
| `AUTHORIZATION_REQUIRED` | 展示授权卡，授权前不得提交 |
| `INTERACTION_EXPIRED` | 标记旧卡过期，按业务规则重新准备 |
| `FORBIDDEN` | 不重试，说明当前身份或权限不足 |
| `CONFLICT` | 重新读取实时状态并要求用户核对 |
| `RESULT_UNKNOWN` | 停止自动重试，进入权威对账 |
| `CAPABILITY_EXECUTION_FAILED` | 返回目标系统可理解的失败原因 |

## 十、验证要求

每次协议或宿主适配变更至少验证：

- 三类交互的创建、展示、完成、拒绝、取消、过期和替代；
- 用户、会话、任务和系统隔离；
- 多端同时展示与单次消费；
- 登录完成后原业务自动续办；
- 同轮重复轮询保护和整体超时；
- 网页拉取端不触发聊天直推或额外模型唤醒；
- OpenClaw 版本、插件版本和工具目录无漂移；
- 日志和模型上下文不出现秘密字段。

写操作的计划冻结、授权和核验规则见 [受控写入模型](./受控写入模型.md)。
