# 业务 Skill 接入与能力提取一期设计

日期：2026-09-24。状态：一期已部署，用户启用与实际业务场景验收待完成。中央目录、配置、宿主加载、首批五个 Skill 和界面已实现；验证与发布事实见对应验收记录。未向用户默认分配，旧业务接口尚未退役。下文保留总体设计，已实现合同以代码和本节实施说明为准。

## 一、目标与主要决定

让已有业务经验形成可版本化、可按用户配置、可按需加载的业务 Skill，并审查现有复杂能力能否拆分简化。用户仍通过自然语言完成工作，不需要理解文件、内部工具或执行计划。

一期决定：

1. Skill 文件在项目中集中维护，随中央服务发布；不复制到每个用户或宿主的磁盘目录。
2. 中央服务管理目录、版本、用户分配和配置；宿主通过 MCP 获取内容，智能体遵循规则、组织调用和生成语义结论。
3. 实际业务访问、权限、可信卡片、持久计划、批量任务、正式提交和权威核验继续由中央服务执行。
4. 一期包含管理控制台按用户勾选 Skill、全局启停、试用标识、依赖提示及变更审计；不因已有底层权限而自动分配 Skill。
5. 先提取五个已有流程；复杂能力按“直接提取、拆分替代、保留执行器”分别处理，不以减少接口数量作为验收目标。
6. Skill 是业务方法，不是授权凭证或通用脚本。第一期不接受任意 Shell、HTTP、浏览器脚本或外部代码包执行。

收益：按需提供业务规则，减少常驻上下文中的无关场景；业务方法可独立评审和回归；同一套方法可服务多个用户和宿主；支持在证据等价的前提下简化高层工具。

不承诺仅增加 Skill 就能提高语义准确率或减少耗时。应以场景选用、结果质量、调用和上下文开销的前后对比验证。

## 三、总体分工

```text
用户自然语言 / 我的业务助手
             |
             v
宿主：确认当前身份 -> 获取 Skill 简介 -> 选择并加载规则
             |
             v
智能体：理解目标、选择既有执行路径、组织参数、分析证据
             |
             v
中央服务：Skill 可用性与业务权限检查
      |                |                  |
 普通只读调用       持久任务计划       原子/批量受控写
      +----------------+------------------+
                       |
                       v
              既有适配器及业务系统
```

Skill 不另建执行器，也不强制每次请求先分类。简单查询继续走原工具；数据库分析继续使用现有只读探索路径；OA 查询结果生成日志使用持久计划；批量审批继续使用既有逐项授权流程。

多来源综合若超出现有计划目录和注册转换，须先补齐执行合同，不允许 Skill 绕开计划限制自行拼接来源并派生写入。

## 四、Skill 提取目录

### 4.1 一期五个交付对象

| 建议标识 | 名称与成果 | 执行路径 | 依赖与交付边界 |
| --- | --- | --- | --- |
| `log-review` | 日志总结与事项复核：主题概览、进展、问题、待办及来源覆盖 | 数据库只读探索 | 同源目录、日志查询/内容分析；自由 SQL 可选。简要总结与详细复核为同一 Skill 的模式 |
| `issue-tracking` | 事项进展追踪：带来源时间线、关联依据、当前证据与缺口 | 数据库只读探索 | 同源目录及正文证据；不新增长期事项台账、自动监控或通知 |
| `similar-cases` | 相似案例检索：问题、措施、明确结果、适用条件与差异 | 数据库只读探索 | 标准查询即可开展；相邻案例与不确定项单列，初始为试用 |
| `oa-work-log` | OA 事项生成工作日志：已办/已发来源、去重草稿、可信核对 | 持久计划 | OA 流程读取；进入填单再检查泰华创建权限，项目检索按实际需要检查；允许只预览 |
| `oa-pending` | OA 待办办理：定位事项、查看依据、填写意见、逐项办理 | 原子或既有批量流程 | 流程读取及所选事项类型的具体审批权限；不自动代拟批准结论，不支持的类型明确拒绝 |

“直接可提取”指有现成业务流程，不表示新加载机制已验收。五个 Skill 逐个通过门槛后启用，不一次性向所有用户开放。

### 4.2 第二批候选

| 候选 | 已有基础 | 需补齐的内容 |
| --- | --- | --- |
| 日志投入统计 | 日志统计、获准自由只读查询 | 登记工时口径、合计对账、未关联项目、周期比较规则；不输出绩效评分 |
| 评论反馈梳理 | 评论与关联日志证据 | 评论关联、回应与落实的判据；评论权限独立检查 |
| 部门知识查询 | 语雀搜索、目录、结构化读取 | 未命中、截断与版本冲突处理；多文档综合执行路径 |
| 会议室办理 | 空闲查询、申请、符合条件的撤销 | 选择与异常处理；限定独立会议室申请，不扩为多写会议全流程 |
| 照明告警分析 | RTU、单灯、真实支路漏电查询与分析 | 分类、时间口径、结论边界及真实场景验收 |
| 照明能耗分析 | 有界用电记录、趋势与排行 | 缺失数据、比较基准、原因判断边界及场景验收 |

登录、分页、授权、恢复、单个搜索和导出不独立包装成用户 Skill。每种 OA 表单先作为待办 Skill 的支持类型；只有形成明显不同的业务方法和交付物才拆分。

## 五、复杂能力的拆分与替代

| 对象 | 一期处理建议 | 保留部分 |
| --- | --- | --- |
| `database.logs.content_analyze` | 优先比较与 `logs.query` 的合同，提取模式提示；证据及权限等价后才讨论入口退役 | 正文获取、分页、分片、覆盖、来源、版本与预算 |
| `database.comments.analyze` | 分离评论取证与反馈/问答/跟进方法；若缺独立读取入口，先设计最小读取合同 | 评论获取、关联日志、独立权限与证据结构 |
| 照明告警和能耗分析 | 解释、报告组织可移入 Skill；是否拆接口由实际重复程度决定 | 确定性聚合、计数、窗口、完整性与预算 |
| OA 事项合并及草稿转换 | 一期保留确定性转换，仅提取使用规则 | 来源绑定、去重、覆盖和写字段来源校验 |
| 批量审批、受控写入、持久计划、登录恢复 | 保留执行器；Skill 负责选用和业务指引 | 状态、锁、事务、幂等、授权、恢复和结果核验 |

替代必须完成：参数与返回结构比较、权限映射、证据等价验证、旧调用者盘点、兼容和回退设计，再决定删除。不能因为新工具更通用，就把原有分析授权自动变成更宽的读取或自由 SQL 权限。

若未来让模型改写计划中的日志正文，应另行设计带来源的模型转换、输出核验和可信字段审阅；不能将模型复述冒充当前注册转换输出。

## 六、文件布局与维护

建议源码根目录：`D:\Codes\CLIExp\bscli\business_skills`。部署时通过包资源访问，Linux 不依赖此开发机路径。

```text
bscli/business_skills/
  __init__.py
  log-review/
    manifest.json
    SKILL.md
    references/
      output-examples.md
  issue-tracking/...
  similar-cases/...
  oa-work-log/...
  oa-pending/...
tests/fixtures/business_skills/...
```

`SKILL.md` 描述适用条件、不适用情况、必需输入、操作步骤、路径选择、交付要求和异常处理；不保存用户名单、真实业务正文、登录信息或执行状态。`references` 保存按需加载的静态规则与示例。

`manifest.json` 建议字段：

| 字段 | 含义 |
| --- | --- |
| `schemaVersion`、`id`、`version`、`name`、`description` | 合同、稳定标识、发布版本、名称和选择摘要 |
| `entrypoint`、`resources`、`required_resources` | 固定主文件及各模式必读资料；发布校验路径、存在性和大小，加载接口不接受文件路径 |
| `selection` | 适用目标、排除范围、交付结果；供模型按语义选择，不作关键词路由 |
| `executionMode` | `read_exploration`、`durable_plan` 或 `controlled_action` |
| `dependencyProfiles` | 按预览、填单、单条、批量等功能声明必需和可选依赖，支持 all/any 组合及同源要求 |
| `settingsSchema` | 允许的参数、默认值、类型、范围及可由谁修改；不开放自由提示词覆盖 |
| `compatibility` | 最低 Skill 协议及所依赖能力/转换合同 |

发布时生成覆盖 manifest、入口和全部资源的内容哈希；同一版本不得对应不同内容。依赖声明使用中央登记的业务权限/数据库能力映射，不由模型自报权限。

规则通过 Git 修改、评审和版本化发布；控制台一期不在线编辑 Markdown、不上传执行包。修改 `pyproject.toml` 包资源配置，并从安装后的 wheel 验证资源齐全。中文项目设计文档仍遵循既有文档目录规范。

## 七、按用户配置与业务权限

### 7.1 三类独立状态

1. 发布内容：某 Skill 的某版本及内容哈希。
2. 全局配置：当前发布版本、启用/试用/停用状态和配置版本。
3. 用户配置：中央用户启用的 Skill、结构化参数、配置版本及变更记录。

建议在中央持久存储中新增全局 Skill 配置、用户 Skill 配置及审计记录，复用现有事务和管理审计方式。数据库授权仍按用户 × 数据源 × 能力求值；Skill 不维护另一份业务权限副本。

可用性为：全局允许、用户明确分配、宿主兼容，并且当前选择的功能依赖满足。未选择数据源时返回“需要选择”，缺依赖时返回具体原因；不把整个 Skill 一律隐藏，也不因可选功能缺权限阻塞基本功能。

Skill 分配不授予业务权限。撤销 Skill 会阻止其新的加载和绑定执行；用户保留的原子业务权限仍可用于普通请求。若要禁止业务操作，必须撤销对应业务权限。Skill 配置不是不可绕过的业务禁用开关，已经进入模型上下文的规则也不能被远程抹除。

### 7.2 参数规则

一期支持默认数据源、输出详细程度和 Skill 特定的预览/填单、单条/批量开关。配置区分管理员允许的功能与普通默认值：用户本次输入可覆盖默认值，不能开启管理员关闭的功能；所有参数仍须通过工具原有合同和权限检查。

不默认“当前用户”对应某数据库人员，不把默认部门当作授权数据边界。数据源、部门和人员在执行时重新核实。

### 7.3 控制台与用户界面

管理员在“用户 → 业务 Skill”中查看勾选、试用状态、允许功能、参数和缺失依赖。保存需变更原因与 `expected_revision`；版本冲突返回冲突，不能覆盖另一管理员修改。审计员只读。复用已有身份、Origin、CSRF 和审计措施。

用户在“我的业务助手”查看已分配内容和不可用原因，可选择助手或直接描述需求；消息渠道主要通过自然语言使用。明确选择只作为 Skill 选择信息，中央仍核实分配。公共已发布规则不包含其他用户配置或私有业务数据。

同一中央用户跨 Workspace、Telegram 等端获得一致配置；各请求继续绑定自己的会话和任务。用户配置变更应无需换 Token 或重启宿主；首次新增协议仍需正常发布兼容插件。

## 八、中央发布接口与宿主加载

以下接口为拟新增名称，并非当前已注册工具：

| 接口 | 合同建议 |
| --- | --- |
| `agentbridge_skill_catalog` | 返回当前认证用户获分配的 Skill 简介、发布版本、配置版本、功能可用性及原因；支持分页和变更校验，不返回其他用户配置 |
| `agentbridge_skill_get` | 按标识/预期版本读取获准入口或白名单资源；每次检查用户分配、全局状态、兼容性及当前依赖，返回有效配置、哈希和任务绑定信息 |

身份来自服务端 Token 解析，模型参数不能指定任意 `user_subject`。管理端使用独立只读目录与配置接口；不借模型公开接口修改用户分配。

宿主在认证业务回合获取或校验简短目录，模型按语义选择并加载规则；没有匹配就走原子能力，不强制所有请求使用 Skill。明确用户选择优先处理；存在实质歧义才请用户澄清。禁止用关键词正则决定是否提供全部通用约束。

一期每个任务绑定一个主要 Skill，共用证据规范作为共享规则；跨 Skill 复合编排另行设计。用户转向独立任务时不沿用旧绑定。独立只读任务的绑定使用现有任务元数据，不为此创建持久计划。

宿主注入中央规则时须标明其来源，不能将业务正文中的指令当作 Skill；来源文本与操作规则分开。发布内容受长度和资源预算限制，引用按白名单按需加载。

缓存建议键包含中央端点、中央用户、Skill 标识/版本/哈希、用户及全局配置版本；权限可用性单独刷新。相同公开文件字节可以复用，但用户配置、可用性和业务数据不得跨用户缓存。每次 Skill 绑定工具调用由宿主私有上下文携带服务端绑定，不能信任模型伪造的 Skill 标识。

无分配、停用、版本缺失、依赖不足和宿主不兼容返回明确状态。中央不可达时不凭离线缓存新开 Skill 任务；普通原子能力保持原有合同，但不得自动绕过已失败 Skill 任务的来源或写入约束。

## 九、版本固定、撤销与恢复

加载时记录任务、用户、Skill 版本、内容哈希、有效参数、配置版本及绑定状态。服务端保留在途任务所需的不可变资源快照；资源只有静态规则，不包含业务证据。保留期限至少覆盖绑定任务生命周期，终结后按既有保留策略清理。

普通内容更新：新任务使用新版本，在途任务仍用原版本；旧版本不再存在时必须使用留存快照，不能静默加载新版替代。协议/能力不兼容则停止并说明。

用户取消分配、全局停用或缩减允许功能：绑定任务在下一工具调用、恢复、进入写准备及授权消费前检查。尚未提交的后续业务步骤停止，相关卡片按现有事务边界失效。提交已发生时仍允许必要的只读对账和终态记录，不重发、不伪装为未提交、不自动撤销业务。

撤销与授权消费存在竞争时，必须按现有写入事务/锁边界决定先后；文档不能用“立即生效”掩盖已发生的副作用。撤销不会撤回用户已收到的内容，也无法抹掉模型记忆。

宿主重启后从中央任务事实恢复绑定；持久计划由现有执行器继续，批量任务由原状态机推进。普通模型只读分析不因此获得新的自动断点恢复保证；原证据失效时重新读取并说明变化。

Skill 回退与业务回退分开：恢复旧规则不回退业务数据；不可恢复的结果未知继续停止和对账。

## 十、场景执行示例

### 10.1 日志事项复核

用户请求一周部门工作复核 → 加载 `log-review` → 选择获准来源并确认部门范围及 DAILY/WEEKLY 口径 → 分页读完并核对长文 → 按来源拆分事项 → 归纳进展/问题/计划/未知 → 输出引用和覆盖限制。

不要求自由 SQL；记录读全不等于语义无遗漏；实际没有读全时不得声称全量。

### 10.2 OA 事项生成日志

用户请求昨天已办与已发生成日志 → 加载 `oa-work-log` → 读取当前计划目录 → 提交带日期约束的来源、合并及草稿转换计划 → 来源完整性校验 → 预览或可信字段卡 → 用户独立授权 → 中央一次提交并权威回读。

登录失效通过原任务续办；缺工时和项目等信息通过合适的可信交互补齐；来源不完整停止派生写入。仅预览时不包含写终点。

### 10.3 多用户使用

甲、乙分配同一复核 Skill，分别使用获准来源 A、B；规则共享但身份、查询和证据隔离。丙已分配但缺查询依赖，界面提示不可执行；丁未分配则不提供该助手，但其原子查询权限保持原状。

| S2 中央目录与用户配置 | 文件加载、安装包资源、版本哈希、管理接口、控制台、审计及任务绑定 | 双用户隔离、配置冲突、动态撤销和打包验证通过；依赖 S1 |

| S4 受控流程接入 | OA 日志与待办 Skill，复用计划、卡片和批量执行器 | 登录续办、预览、精确类型授权、取消、撤销竞争和单次提交核验；真实写入仍须具体授权；依赖 S3 |

## 十二、验收矩阵

| 类别 | 核心检查 |
| --- | --- |
| 文件与发布 | manifest 校验、重复 ID/版本拒绝、全资源哈希、路径越界拒绝、wheel 安装后读取、缺资源失败关闭 |
| 用户配置 | 未分配不能加载；甲乙配置隔离；按源依赖；可选依赖不误阻断；冲突不覆盖；审计包含原因和前后状态 |
| 宿主 | 同义表达和显式选择；普通查询不误加载；跨用户缓存隔离；参考宿主合同一致；规则变更不要求重启才能发现 |
| 撤销与恢复 | 旧缓存、在途任务、旧卡片、提交竞争、进程重启、版本缺失；提交后核验可收尾且不重发 |
| 分析质量 | 日期/组织范围、分页与长文、逐事项覆盖、原文状态、来源引用、案例直接/相邻/不确定分类 |
| 写入 | 只预览零业务写入、来源不完整停止、独立授权、类型权限、取消生效、单次提交、权威回读、未知停止 |
| 替代等价 | 原查询/分析权限不扩大；输出证据和预算不退化；旧宿主兼容；保留回退路径 |

用固定代表性问题比较选用正确性、来源覆盖、状态夸大、人工修正次数、调用数和上下文开销。关键内容质量用独立核对样本，不把同一模型自评当作人工金标准；具体样本规模和阈值在各场景实施前冻结。

## 十三、范围保留与风险

- Skill 的遵循和场景选择仍有模型不确定性；强制规则继续在中央和工具合同执行。
- 不把所有分析模式拆成独立 Skill；控制选择重叠与维护成本。
- 不在一期建设 Skill 市场、任意上传脚本、多 Skill 自动编排、岗位角色系统或另一套执行平台。
- 不承诺自动消除案例相关性问题、多人容量问题或实现生产级隔离。
- 不因提取而删除所有工具内提示：分页、证据状态、错误恢复和安全使用说明仍属于工具合同。业务规则建立单一来源，必要共用规范由打包生成或引用复用，避免手工维护多份。
- 代码更改与 Skill 规则更改都需相应回归；纯用户分配配置走审计，不触发全量重新发布。

### 2026-09-28 加载与选择合同修订

`agentbridge_skill_get` 仅接受助手、模式、数据源和预期版本，不再接受 resource。服务端按绑定版本返回 content 与 loaded_resources；历史版本按原清单包含其参考资料，不混用最新文件。目录提供 selection.use_when、not_for、output；适用的业务总结、追踪、检索或办理先加载方法，纯列表、详情和计数直接查询。判断依据是交付目标，不是关键词或工具数量。

数据库工具保留证据、分页、版本与覆盖信息，业务复核方法移至 Skill；查询权限、写入确认与执行校验仍由中央服务承担。加载失败不得静默跳过方法；原有未分配用户的底层业务授权不因此变化。加载卡展示必读文件数量，加载成功不表示业务完成。本轮改动需要更新宿主工具定义与目录提示；后续仅发布 Skill 内容不需要因此重启宿主。
- 进入工具、恢复和授权消费时检查 Skill；授权消费与 Skill 配置写入共用 SQLite 写事务。撤销后尝试取消待用户任务、关闭旧卡片；已提交或竞争中无法取消的业务保留核验路径。
- 常驻规划策略中的追踪、案例详细方法已提取；工具内共用证据合同和独立调用指引保留，未移除 `database.logs.content_analyze` 或 `database.comments.analyze`。
- 分析工具的取证、预算与权限目前尚未证明完全等价，暂保留入口。后续替代必须先完成合同对照和迁移，不能把本次规则提取记成接口退役。
- 旧版本资源快照保留在中央数据库；按终态任务生命周期清理的自动回收尚未加入，应纳入后续维护预算。现有五个 Skill 为受控固定发布包，不接受用户上传。
