# 用户能力授权与令牌动态管理整体设计

日期：2026-09-23。状态：第一期代码实施与离线回归中；生产部署和真实验收以发布记录为准。

## 1. 目标与已确定决策

把各系统粗粒度 Token Scope 授权，逐步统一为“用户业务能力 + 资源范围”，令牌只承担身份认证和凭证生命周期管理。管理员在控制台调整授权或续期后，下一次调用读取最新配置，继续使用原令牌，不修改 OpenClaw 环境变量，不因管理操作重启 Gateway。

本次讨论确定：

1. 用户按业务能力授权，沿用独立数据库动态授权的方向。
2. 权限只在用户层配置，取消独立令牌授权层；同一用户的所有有效令牌使用同一套用户授权。
3. 令牌到期支持管理员续期，保留 token_id 和原密钥；不要求重新签发。
4. 泄露、丢失、主动密钥轮换或更换所属用户时换发；新客户端可单独签发。
5. 管理权限不能替代业务写操作的逐次确认，继续遵循 prepare → authorize → commit → verify。
6. 不强制一人一个令牌。多端可经宿主共用凭证，也可使用多个独立令牌，分别续期和撤销；令牌数量与权限粒度独立。

本文进一步给出默认方案，包括期限、预设组合、存储与迁移规则。这些属于设计建议，实施时应以本文明确的版本为依据。方案不扩张任何现有账号的真实授权。

## 3. 授权模型

### 3.1 有效权限

一次操作只有同时满足以下条件才允许：

`身份有效 ∧ 用户启用 ∧ 令牌未撤销且未到期 ∧ 用户允许该能力和资源 ∧ 系统策略允许 ∧ 下游权限允许`

身份与 token_id 来自认证上下文，不能接受工具参数中的用户主体作为权限依据。无授权记录、未知能力、资源无法确定、策略读取失败一律拒绝，不回退到旧 Scope 放行。

一个用户授权项同时包含能力和资源条件，不能分别合并能力列表和资源列表后形成交叉授权。操作必须匹配至少一个完整授权项，并满足全部依赖和下游约束。

数据库没有业务系统人员映射，继续以中央用户、source_id 和数据库账号/视图限制作为边界；不能推断“本人”或默认拥有部门范围。

### 3.2 用户授权与令牌生命周期分工

| 对象 | 管理内容 | 修改效果 |
| --- | --- | --- |
| 用户 | 业务能力、对应资源范围、启用/停用 | 对该用户所有令牌生效 |
| 令牌 | 身份绑定、有效期、续期、撤销和换发 | 影响该凭证及使用它的端点 |

用户采用明确授权列表，空列表表示无业务权限。不给令牌保存第二份能力列表，不提供令牌权限上限、复制用户权限或跟随权限开关。新增业务能力默认未授予用户；授予用户后，所有有效令牌即可使用。

令牌到期或撤销不删除用户授权。用户恢复能力后，所有仍有效的令牌可使用该能力；已到期或撤销的令牌仍不可用。到期令牌续期后按用户当时的最新授权执行，不恢复签发时的旧 Scope。

同一用户多个有效令牌在相同资源及下游身份条件下具有相同业务权限，但各自到期、续期和撤销互不影响。撤销共用凭证影响全部使用它的端点；独立凭证可分别撤销。用户、令牌与下游账号绑定分别管理，续期或改权限不能换绑身份。

历史验收采用每用户一个 MCP 令牌、多端经宿主使用该用户身份；代码允许分别配置凭证，本设计不增加用户级唯一令牌约束。浏览器仍只持有自己的登录会话，不分发长期 MCP Bearer。签发新令牌只赋予当前用户身份，不接受独立业务 Scope；对仍提交旧 Scope 的管理客户端明确提示接口已变更，不能静默保存为权限。

另一有效令牌不能仅凭 user_subject 相同接管旧写确认；跨端续办继续遵守既有可信交互协议和原始授权来源绑定。统一用户权限不等于放开任务、文件或确认卡的归属校验。

### 3.3 能力粒度

授权单元是稳定的业务动作，执行能力保留细分接口，一个权限项可以覆盖多个执行步骤。专项梳理已形成[用户业务能力授权目录第一版](./用户业务能力授权目录第一版.md)及[完整映射附件](./用户业务能力授权目录映射.json)，后续实施以该目录为准，不按名称前缀自动匹配。

| 系统 | 第一版粒度 |
| --- | --- |
| OA：30 项 | 流程查询；组织/私人通讯录及导出；证照查询/下载；会议室查询/申请/取消、创建会议；按类型的草稿/提交；14 类审批及撤回 |
| 照明：11 项 | 运行状态与电测、告警、能耗、资产、巡检、维修共 6 类查询；报表导出；备注、工区提交、工区撤回、处置共 4 类写入 |
| 日志系统：4 项 | 本人日志、团队日志、项目检索、创建日志 |
| 语雀：1 项 | 知识内容读取，覆盖书库、目录、搜索和正文 |
| 数据库：8 项 | 保留现有按源 database.* 业务授权，下载归导出，原文按来源权限复核 |

共 54 项业务权限。OA 批量审批按实际事项类型检查，通讯录组按 group_type 分派，照明导出按 12 种 report_type 检查来源查询权限。模板、登录和平台协议不单设业务勾选项，须遵守目录中明确的过滤、归属和原始授权规则。

能力依赖不能隐式扩权：导出同时需要目标数据的读取能力；数据库导出还需要其 query_capability 的授权。下载需核对文件所属用户、来源、有效期与当前权限；不能通过历史文件绕过撤销。

准备、确认、提交属于同一业务写权限的执行阶段，不作为任意拼装的管理员勾选项。登录、会话状态、能力发现是辅助入口：只暴露当前身份必要信息；登录不授予业务能力。缺少业务权限时不能通过登录入口间接执行查询。

权限预设只简化勾选，例如“流程查询”“照明运维查询”。应用时展开为明确列表，不使用未来自动扩展的通配符。新增能力默认未授权；如需纳入既有权限项，必须检查是否改变既有授权含义。

### 3.4 数据范围

第一期必须支持数据库 source_id 精确隔离。其他业务系统默认采用“该绑定下游账号实际可见范围”，不能把它显示成“全公司数据”。

部门、项目、知识库等细分范围逐个适配：只有查询过滤、详情读取、分页、导出和缓存交付都能验证范围时，才在页面开放。暂不支持的范围返回明确错误，不接受保存后假装生效，也不能只靠提示词控制。

资源删除或停用时授权立即不可用；新资源不因重名继承旧授权。已保存的具体资源标识不自动覆盖以后新增的数据源或项目。

## 4. 统一检查与即时生效

新增中央 AuthorizationService（拟定名称），统一提供能力目录过滤、操作授权、结果交付复核及变更影响预览。业务入口只声明所需权限与资源解析器，不再各自维护真假不一致的 Scope 清单。

可信上下文包含 user_subject、token_id、用户授权版本和令牌生命周期版本、授权策略版本、资源标识、request_id。内部工作任务必须携带可追溯的原始授权来源；没有 token_id 的维护任务使用显式服务身份，禁止凭一个 user_subject 绕过检查。

每次新请求读取服务端最新授权。第一期不引入跨请求的授权允许缓存；一次操作中的快照用于比较，不能作为长期通行证。旧的 AccessToken.scopes、会话快照和任务计划中的权限列表不能成为动态放行依据。

| 检查位置 | 行为 |
| --- | --- |
| 目录与计划 | 只列当前有效业务能力；计划提交时重新验证 |
| 工具执行前 | 验证令牌状态、最新权限和资源，覆盖 MCP、CLI、Workspace、任务执行器 |
| 读取结果交付前 | 复核相关授权；相关授权发生变化则拒绝交付该次结果，提示重新查询 |
| 分页、导出、附件下载、历史结果复用 | 每次重新检查，不能把 cursor、report_id 或 operation_id 当权限凭证 |
| 写操作 commit 前 | 检查最新权限及原业务确认，记录检查版本和副作用开始点 |
| 多步/批量任务 | 每个步骤或子项重新检查，失权后停止未开始的部分 |

用户其他无关能力变化，不必终止当前查询。实现以该次操作依赖的授权投影及资源版本判断；已发生相关权限撤销又恢复，也应通过权限版本识别变化，不能仅比较最终列表相等。

令牌续期仅改变生命周期版本，不等于业务权限变化；查询在交付时仍须验证令牌当前有效。用户授权修改使用用户授权 revision，续期和撤销使用该令牌的 edit_revision 防止并发覆盖；不创建令牌权限版本。

“即时生效”的边界是：保存提交后，新授权检查必须看到新状态。已经发往下游的请求不能追回；已经送达用户的数据不能回收。写入一旦跨过副作用开始点，按真实成功/失败/结果未知记录，不能因随后撤权伪装成未执行或自动重试。第一期不承诺跨本地数据库与远端系统的原子撤销。

## 5. 令牌续期与生命周期

### 5.1 状态规则

持久状态为 active/revoked；expired 是 active 且 expires_at 不晚于当前时间的派生状态。用户停用是另外一层阻断。

| 当前情况 | 管理员续期 | 结果 |
| --- | --- | --- |
| 有效且未撤销 | 允许 | 更新到期时间，原密钥继续使用 |
| 已到期但未撤销 | 允许 | 原密钥恢复鉴权，仍受当前权限约束 |
| 已撤销 | 拒绝 | 必须新签发，续期不可复活 |
| 所属用户停用 | 拒绝续期 | 先处理用户状态；启用用户本身不延长令牌期限 |
| 泄露或丢失 | 不以续期处理 | 撤销旧令牌、签发新令牌并替换客户端凭证 |

续期不返回密钥，不修改 token_hash、token_id、所属用户、下游主体或授权配置。密钥仍只在签发时展示一次。持有业务令牌不能调用管理员续期接口。

### 5.2 期限与并发

默认建议提供“从现在起 30 天”“从现在起 90 天”和自定义到期时间，页面展示绝对时间、时区和剩余天数。沿用现有期限上限，要求新到期时间在当前时间后 5 分钟至 90 天内，并且晚于旧到期时间。若选择的期限没有延长旧期限，前端提示并由后端拒绝，避免意外缩短。

服务端存储和比较 UTC，以服务端时钟为准；界面按管理员时区显示。续期接口提交 new_expires_at、expected_revision、reason、request_id。服务端事务内检查状态与版本、写新到期时间、记录审计；重复 request_id 返回原结果，不叠加有效期。续期与撤销竞争时，撤销状态不可被覆盖；旧版本编辑返回 409。

不自动续期，不提供永久有效选项。反复由管理员续期可以长期保留同一密钥，这是降低客户端维护成本的明确取舍；泄露处置仍依赖撤销和换发。控制台展示密钥创建时间及最近续期时间，便于判断是否需要主动轮换。

### 5.3 对 OpenClaw 和任务的影响

原 Bearer 不变，管理员续期不改 .env、不改工具目录，也不触发 Gateway 重启。鉴权过期后若连接已关闭，允许使用原凭证重新建立 MCP 连接，不要求重启进程。需要验证中间件和客户端不存在永久缓存旧 expires_at 或永久停用客户端的行为。

到期提示为“访问凭证已到期，请联系管理员续期”，业务系统登录过期提示重新登录对应系统，权限不足提示缺失能力；三类原因分开处理。对未认证请求保持通用 401，详细到期原因通过受保护的管理视图或可信任务诊断展示，不向未认证调用泄露账号信息。

续期只恢复后续请求的鉴权资格，不自动恢复所有失败任务。读取可由用户重新发起或按已有安全恢复规则继续；写任务需要显式续办、原操作绑定有效、业务确认未失效和最新权限通过。RESULT_UNKNOWN 只核对结果，不能借续期自动重放。

首次部署本次代码是否重启，仍由实际 Gateway 输入变化决定；“管理操作免重启”不等于首次升级免重启。真实密钥换发当前仍需更新配置并加载；凭证热加载不作为本期续期设计的前置条件。

## 6. 管理控制台

“用户与令牌”保留入口，明确分成用户授权区和令牌区。

用户授权区是唯一权限编辑入口，按系统展示业务能力、资源范围及受影响令牌和端点。常规查询、高级访问、导出、业务写入分组。保存前列出新增和撤销；说明所有有效令牌统一生效，到期令牌续期后使用最新用户权限。

令牌列表显示标签、所属用户、当前状态、到期时间、最近使用、创建时间及已知端点绑定。详情链接到用户权限的只读视图，并说明凭证失效或资源停用等限制；不显示独立令牌权限配置。

令牌操作分为“续期”“撤销”“签发新令牌”和“换发此令牌”。换发明确撤销目标旧凭证；新增凭证不自动撤销同用户其他令牌。续期弹窗展示旧/新到期时间与“原客户端无需重新配置”，要求原因。已撤销令牌隐藏续期操作但后端仍强制拒绝。

管理员可修改，审计员只读；业务用户和模型工具不能管理授权。沿用管理员登录、Origin、CSRF、初始密码修改要求。保存使用乐观并发版本，成功回显本次事务结果；冲突提示刷新并对比，不静默覆盖。

页面可显示 7 天内到期和已到期筛选，阈值只是展示默认值，不启动后台自动续期或外部通知。所有编辑均记录操作人、原因、前后值和版本，不记录密钥。

## 7. 数据与接口设计

以下为新增逻辑模型，具体表名可在实施中统一，但权威数据源与事务边界必须保持。

| 模型 | 核心内容 |
| --- | --- |
| 权限目录 | permission_id、系统、名称、风险分组、执行能力映射、依赖、支持的资源类型、目录版本 |
| 用户授权集 | user_subject、明确授权条目、revision、更新时间 |
| 令牌生命周期 | 现有字段，加 edit_revision、lifecycle_revision、last_renewed_at |
| 授权审计 | actor、target、action、reason、前后状态、版本、request_id、时间 |
| 迁移记录 | 映射版本、输入摘要、逐令牌差异、迁移批次、切换状态 |

授权条目采用结构化资源选择器，例如 `{permission_id, resource_type, resource_ids}`。无范围限制要显式表示“绑定账号可见范围”，空资源列表表示不授权，二者不能混淆。新授权和令牌生命周期放在统一访问治理事务存储中；优先扩展当前身份存储，避免对同一授权长期双写。

数据库现有授权表、管理接口和执行检查继续作为唯一权威源。本期不复制、不双写、不迁移数据库授权数据。统一用户授权表只管理 OA、照明、日志系统和语雀。

| 拟定管理接口 | 用途 |
| --- | --- |
| GET /api/access/permissions | 业务权限及资源能力目录 |
| GET、PUT /api/access/users/{subject}/grants | 读取、替换用户授权集 |
| GET /api/access/tokens/{token_id}/effective | 只读展示用户当前权限、该凭证有效性及限制原因，不产生独立授权配置 |
| POST /api/access/tokens/{token_id}/renew | 管理员续期 |
| POST /api/access/preview | 不落库的变更影响预览 |

写接口统一要求 expected_revision、reason、request_id；拒绝未知字段和未知权限。预览结果不构成授权，保存必须重新验证依赖和资源状态。保留既有签发和撤销入口，接入同一并发和审计规则。

权限变更和权威审计同事务提交，审计写失败则变更失败；如向既有管理审计另行投递，使用事务内事件记录保证可补投，不把跨库双写当作原子操作。

业务拒绝区分 USER_CAPABILITY_DENIED、RESOURCE_SCOPE_DENIED、AUTHORIZATION_CHANGED；配置读取故障返回 AUTHORIZATION_UNAVAILABLE。管理接口区分 TOKEN_REVOKED、TOKEN_EXPIRED（展示状态）、REVISION_CONFLICT 和期限参数错误。对外错误保留最小必要信息。

## 8. 迁移：原令牌继续使用，权限不扩大

### 8.1 先生成对照清单

穷举工具、执行能力、写目录、计划、导出、下载及历史结果入口，生成“旧检查 → 新权限项 → 资源解析 → 依赖”清单。缺映射的入口不进入切换；新入口没有映射时默认拒绝。旧 Scope 只作为迁移输入，不能成为迁移后的旁路。

读取实际用户、令牌和按源数据库授权。历史已退役 Scope 不参与授权恢复。报告不包含 token_hash 或密钥。

### 8.2 合并到用户授权，处理历史差异

以下为首次迁移的历史流程；正式用户迁移已完成。现行版本不再提供 Scope 兼容授权或在线迁移预选，未配置用户按零业务权限处理。

先按旧有效 Scope 和实际入口检查展开每个令牌的权限集合及资源范围；收集该用户全部未撤销令牌，包括已到期但可以续期的令牌。不能假定当前线上一定只有一个有效令牌。

单个有效令牌、或多个未撤销令牌映射权限完全一致时，可将其明确权限迁入用户授权。用户没有有效令牌时，不自动从过期凭证恢复普通系统权限，先生成迁移待处理清单，由管理员确定用户目标授权。

若同用户令牌存在不同权限，统一用户授权不可能同时保持所有旧令牌的权限差异。迁移必须报告每个令牌的新增/减少项，暂缓该用户的切换，不自动取并集扩大受限令牌，也不自动取交集剥夺原权限。管理员明确选择统一用户授权，并决定撤销哪些旧凭证、哪些继续承载统一权限后，再记录决策并切换。选择扩大属于显式授权变更，不能记为等价迁移。

已到期但未撤销令牌也参与差异预览：它们续期后将获得最新用户权限。不能仅忽略旧过期凭证，让它们以后续期时意外扩大权限。已撤销令牌只保留历史，不成为授权来源，也不得恢复。

数据库继续按现有用户/source_id/能力机制管理，不进入新用户授权表，也不生成令牌能力快照。令牌续期后，数据库调用仍以原动态授权为准。

旧粗 Scope 包含的导出能力，等价迁移时进入对应用户明确权限，并标记来源。不能借“新默认关闭导出”偷偷撤掉既有授权；管理员可另行明确收紧。

导出依赖等新约束若无法在不扩权前提下保持旧行为，报告差异，暂缓该用户切换；禁止为补依赖自动授予旧时不可执行的能力。比较以实际动作、资源范围和下游身份为准，不能只比较权限数量。

### 8.3 切换与回退

先影子比对，新服务计算决策但旧服务仍执行；差异检查覆盖每个现有令牌及过期可续期凭证；差异必须等价或已有管理员明确处置记录。切换前短暂冻结授权编辑，迁移在一致快照上执行，按用户原子切换，切换后该用户只认新源；未切换用户仍完整使用旧路径，禁止新旧检查混用或失败后回退。保留映射版本、备份和迁移审计；迁移可重跑但不得覆盖已经由管理员修改的新授权。

旧 scopes_json 作为历史元数据保留。过渡期兼容读取可以给旧客户端显示信息，但执行不得再因旧宽 Scope 拒绝已获新授权的细项，也不能因旧宽 Scope 放行已撤销的细项。

细粒度配置生效后，旧版本可能无法表达收紧后的权限，禁止直接回退成更宽 Scope。必要时关闭受影响业务入口，使用兼容新授权检查的修复版本；只有证明权限等价的快照才可回退。已发生的撤销与收紧不能被旧备份抹掉。

## 11. 本期边界与遗留风险

本期目标包括：OA、照明、日志系统、语雀共 46 项用户能力授权，独立令牌生命周期管理、管理员续期、必要的执行链统一、控制台、审计和迁移验收；数据库原有 8 项授权仅做兼容回归。

后续独立事项：若出现明确需求再评估客户端差异权限；密钥换发热加载、企业角色继承/组织策略、未具备后端校验能力的部门与项目范围、外部到期通知。它们不阻塞管理员续期和第一期业务能力授权。

保留的事实边界：续期无法改善已泄露密钥的安全性；撤权无法追回已交付数据或撤销已提交的下游请求；下游账号过宽的权限需要下游治理；Gateway 免重启必须通过真实客户端验证，不能仅靠服务端单测宣布完成。
