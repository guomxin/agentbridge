# OpenClaw 的 AgentBridge 交互适配器

`agentbridge-interactions` 把中心 AgentBridge 的远程 MCP、可信交互和 Task Hub 接入
OpenClaw。它是宿主兼容层，不包含协同办公、泰华、语雀或照明系统的业务实现，也不修改
OpenClaw 核心源码。

当前版本：`0.4.119`

本版补齐 Telegram 私聊业务卡：闭集业务入口、逐项批次进度、授权与业务核验状态区分；完整 OA 查询提供可信 Mini App 单选/多选入口。
选择使用中央持久冻结的原来源及原 Telegram 端点，经宿主私有 L3、协调租约和原 prepare 执行；不把 Workspace grant 或模型 callback 当作身份。
入口仅在签发时身份、精确调用和私聊路由持续一致时投递，URL 不进入模型目录或结果；切换身份、会话结束/重置、发送期间改绑均拒绝迟到卡片。
共用页支持移动触点、键盘视口及返回恢复，结果未知不重放。官方公开 outbound 没有 edit 接口，历史消息键盘不承诺原位移除；旧 URL 仍按中央终态拒绝执行。

本版增加有界事件唤醒、最长 20 秒状态等待、跨任务并发和原会话精确准备，减少固定轮询与重复目录读取。
目录缓存按身份和版本隔离，权限、材料及最终授权持续实时核验；未知结果不重放。
受管配置须显式启用 `hooks.allowConversationAccess=true`，原生事件可观测性以实际执行器发出为准。
通用工具覆盖与生产模型保持原配置；普通 RPC 继续一次连接，同一已受理 run 的最终历史沿原连接核验。

本版支持 Workspace 结构化草稿短试用：固定草稿、修订、模式和材料，宿主确认绑定后才发送。
试用仅允许对应的 test/test_result，禁止业务和本机工具；保存状态由中心回执核实。没有业务权限的已认证用户也可发现创作工具。
候选排序沿用明确名称或 ID 优先、不适用说明不计正向分数的规则；仍须检查适用范围和权限。

组合任务规划检查在任务协调之前；独立填写不能绕过本轮来源约束。
新增未提交任务取消入口，自动区分普通卡片和持久计划，不撤销已提交的业务流程。

多个或全部 OA 待办使用 `oa_workflow_pending_batch_prepare` 建立通用持久批次；“上面的”事项传入已读取的精确 ID，
当前某类事项使用类型/关键词筛选。每项在对应可信界面填写、核对并明确确认，再由中央提交和回读；成功后由用户进入下一项。旧未标记字段卡和额外警告沿用原确认要求。
默认上限 20，可显式设置到 100；超限或来源不完整时不启动。现有 `oa:write:approval` 足够，不新增权限范围。

可信卡片的只读状态查询遇到可重试网络错误时，在原有等待期限内退避重试；不会重放业务提交。
宿主运行状态日志保留清洗后的传输错误码，用于区分证书、连接和响应故障。

单项只读查询被登录打断时，中央服务按同任务的操作账本恢复原能力及完整参数，并先持久化结果消息、
再结束任务；Gateway 重启不再依赖内存中的查询描述。宿主收到中央续办完成回执后停止轮询，
不再重复查询或用心跳唤醒模型。组合计划和写操作仍使用原有计划或授权续办路径。

原生工具代理在 OpenClaw 裁剪结果前捕获可信卡片，交给同用户协调器后才返回清洗结果。
不将完整业务列表重新复制进 `details`，不将可信入口暴露给模型。TG、微信与 Workspace
的交互通知均可恢复接续；发起端不能仅凭 `origin_handled` 标记就忽略未接管的交互。
元数据恢复或卡片投递失败保留重试，已经发出续办请求但丢失响应时保留防重复执行状态。

同一用户消息可以先读取候选对象，再进入审批、填报、撤销等写操作。所有受治理的业务
`*_prepare` 入口都会建立独立任务，不复用已经由前置读取结束的任务；该写任务随后贯穿字段卡、
授权卡、提交和权威回读。登录入口仍绑定原读取任务，组合任务仍由持久计划统一协调。

兼容基线：OpenClaw `2026.7.1`
完整身份设计见 [智能体宿主多用户身份路由](../../docs/架构设计/智能体宿主多用户身份路由.md)。

## 一、职责边界

插件负责：

- 根据 Telegram、微信和 Agent Workspace 的可信宿主上下文选择 AgentBridge 身份；
- 为不同用户使用不同的环境变量 Token；
- 按 Token scope 裁剪模型可见工具；
- 把认证卡、字段卡和授权卡展示到合格端点；
- 有界轮询交互状态并在完成后续办；
- 同步任务文本、状态、图片和文件；
- 在登录完成后安全恢复允许自动重放的只读请求；
- 保持网页拉取端、Telegram 和微信各自正确的投递方式。

Telegram 回答文本在 `message_sent` 确认发送成功后同步，覆盖普通回复和
`message(action=send)` 工具发送。只接受已绑定且唯一的目标渠道/账号/会话路由，
失败发送和插件自身通知不重复发布；使用平台消息 ID 去重。微信专用卡片处理不变。

插件不负责：

- 保存或解释用户密码、验证码、Cookie 和业务字段；
- 实现目标系统流程、表单填充或提交逻辑；
- 让模型直接调用内部 commit、续办和 Task Hub 工具；
- 绕过 AgentBridge Token scope；
- 为 OpenClaw 修补网络代理、通道实现或核心源码。

## 二、模型工具面

中心 MCP 同时发布业务工具与宿主私有控制工具；受治理智能体工具由插件按身份权限动态裁剪：

- 读取工具；
- 受治理的 `prepare` 或登录入口；
- 一个本地身份状态工具。

内部 commit、可信交互续办、任务协调、端点管理和文件投递工具保持宿主私有。即使工具在模型
目录中可见，中央服务仍按当前用户 Token scope 逐次授权。

插件工具被限制性工具配置过滤时，需要显式加入：

```sh
openclaw config set tools.alsoAllow '["agentbridge-interactions"]' --strict-json
```

不要使用 `group:plugins` 扩大全部插件权限。若 `tools.alsoAllow` 已有其他条目，应合并而不是覆盖。

## 三、安装

在仓库根目录安装已核验的本地插件：

```sh
openclaw plugins install --link ./integrations/openclaw-agentbridge
openclaw plugins enable agentbridge-interactions
openclaw plugins inspect agentbridge-interactions --runtime --json
```

正式宿主的 `NODE_EXTRA_CA_CERTS`、配置路径、状态目录与身份环境变量由审核后的 Mac profile 和 launchd 提供。保留现有工具授权列表，配置 Token 只引用环境变量，不在命令行明文填写。

修改插件后通过 `scripts/agentbridge-native host restart --kind gateway` 配合 `--profile` 与 `--authorization` 管理，不另用 OpenClaw 自带安装器建立第二套服务。验收当前进程的插件注册版本、RPC 和 `/readyz`，超时先检查进程与 pending，不能盲目重复重启。完整步骤见[原生维护](../../docs/部署运维/苹果系统原生维护.md)。

## 四、单用户与多用户配置

### 4.1 单用户兼容模式

旧的单用户安装可以让插件复用全局 `mcp.servers.agentbridge` 地址和环境变量授权头。

```sh
openclaw config set "mcp.servers.agentbridge.url" https://10.10.50.213:8790/mcp
openclaw config set "mcp.servers.agentbridge.timeout" 150
```

### 4.2 多用户模式

多用户部署不得共用一个全局 Bearer。配置一个 `mcpUrl` 和多条 `identityBindings`，每条绑定包含：

- 聊天通道；
- 发送者或网页身份；
- AgentBridge `userSubject`；
- 保存 Token 的环境变量名 `tokenEnv`；
- 允许卡片 Origin。

插件只把 `mcpUrl` 当作地址，根据可信发送者选择授权头；Token 值不写入配置、日志或模型上下文。
启用多用户绑定后应删除带共享 Bearer 的全局 MCP 服务配置，避免形成第二个共享身份工具面。

同一私聊或 Workspace 会话一旦绑定身份就不能切换。未知身份只能看到
`agentbridge_identity_status`，不能调用业务工具。

## 五、可信卡片投递

### 5.1 Telegram

HTTPS 可信卡优先显示 Telegram Web App 按钮。为兼容不信任用户安装内部 CA 的 Android
WebView，同一消息还可以显示“浏览器打开”入口。两个按钮都使用相同短期 URL，URL 只存在于
宿主展示元数据中，不进入模型结果。

### 5.2 微信

微信恢复活动时，已经延期的跨端聊天消息归档投递记录，不逐条补发历史；原始消息仍保留在 Workspace 时间线。新入站消息去重后才唤醒待处理通知，投递领取遵守重试与活动延迟时间。已结束任务的延期状态提醒归档；进行中的任务、可信卡、文件和计划结果仍可恢复。微信回复仅在带平台消息 ID 的 `message_sent` 确认成功后同步到时间线，忽略适配器无 ID 的重复成功回调。

腾讯微信适配器支持文本和媒体投递，但没有统一的卡片渲染器。插件把动作标签和短期 HTTPS
链接追加到宿主生成的出站文本；链接仍不进入模型。微信通道不可用时只报告通道错误，不得把
结果误投到 Telegram 或其他用户。

### 5.3 Agent Workspace

Workspace 是拉取式 Task Hub 客户端，通过 SSE 和历史接口获取有序文本、状态、卡片、图片和
文件。插件不得把 Workspace 当成聊天通道直推，也不得因为网页拉取失败额外唤醒模型。

同一可信交互可以在多个合格端展示，但服务端只能完成一次。完成后其他端同步终态，旧卡不会
长期停留在“等待用户”。主调用链与伴随端通知共享同一个续办占位；父任务进入终态后，插件会
终止该任务的残留轮询并清除恢复记录。中心端不会给终态任务重新签发协调租约，因此迟到通知
只会被确认并忽略，不会重复进入业务系统，也不会再产生虚假的 `RESUME_FAILED`。

## 六、完成后的续办

可信页面完成后：

1. 插件先读取服务端交互终态；
2. 若产生下一张可信卡，直接投递到原端点和其他合格端点；
3. 若业务已经结束，使用宿主固定文本投递成功、拒绝、过期或失败；
4. 需要模型继续理解结果时，使用不含秘密的私有唤醒事件；
5. 禁止同一轮重复调用 `agentbridge_interaction_get`。

### 6.1 登录后自动恢复

登录成功时，以下只读请求可以按白名单重放一次：

- 协同办公的已知流程集合读取；
- 泰华个人/团队日志和项目搜索；
- 语雀知识库、目录、搜索和选中文档读取；
- 照明系统的已注册只读查询。

只保留允许的过滤条件、日期和分页值，丢弃旧幂等键。重放仍使用原身份 MCP 客户端，结果回到
原任务和原通道。

草稿、审批、正式提交、会议、撤销和其他写工具绝不自动重放。字段卡和授权卡完成后也不能推断
成“重新登录后自动提交”。

## 七、跨端任务与时间线

插件在调用业务工具前把宿主请求绑定到中央 `AgentTask`：

- 网页、Telegram 和微信使用同一用户主体时可以继续同一任务；
- 文本、卡片和文件按服务端序号写入同一时间线；
- 相对表达“刚才、上一个、继续上面的任务”由受控任务引用解析；
- 多个候选任务时要求用户选择，不能猜测；
- 撤销是独立任务，通过业务对象关联原提交任务，不复用原提交卡片；
- 同一轮重复工具调用和重复卡片投递由幂等键与投递记录抑制。

网页刷新后从中央时间线恢复，不依赖浏览器内存。历史文件到期后保留“已过期”卡片，并可通过
新的准备操作重新生成下载入口。

## 八、文件交付

证书扫描件等文件由 AgentBridge 准备后绑定当前任务：

- 多文件使用一次批量准备调用；
- 每个文件独立投递，一个失败不阻断后续文件；
- Telegram/微信媒体发送失败时回退到同一短期下载链接；
- Workspace 展示文件名、大小、状态、到期时间和重新生成入口；
- 二进制不进入模型文本上下文；
- 插件不在 AgentBridge 授权过期后自行保留文件。

通道代理和重试由 OpenClaw 配置负责，插件不修改网络和代理设置。

## 九、超时与结果对账

协同办公提交可能包含浏览器准备、CAP4 多阶段发送和权威回读，MCP 超时应至少为 150 秒。

MCP 请求尚未获得响应时，插件只对以下工具执行两次短时传输恢复，等待间隔为 0.5 秒和 2 秒：

- 标记为幂等的只读工具；
- 对模型开放、尚未执行业务提交的 `prepare` 工具。

`prepare` 重试始终复用由工具调用生成的稳定 `idempotency_key`。底层连接错误码会保留在宿主
日志中，恢复成功只记一条诊断，不向用户重复播报失败。内部 `commit`、提交后的权威回读、
`MCP_TIMEOUT` 和 `RESULT_UNKNOWN` 均不进入该重试路径。

宿主超时不等于下游接受或拒绝。任何已经越过提交边界的超时必须：

1. 查询 AgentBridge 操作账本；
2. 查询下游已发、待办或详情等权威集合；
3. 能确认时返回明确结果；
4. 不能确认时返回 `RESULT_UNKNOWN`；
5. 在未对账前不自动重试。

## 十、诊断命令

私聊中：

- `/agentbridge status`：查看不含秘密的身份和运行诊断；
- `/agentbridge pending`：重新显示当前未过期可信交互。

`openclaw agent --deliver` 可以执行工具和发送模型文本，但它绕过正常入站回复路径，因此该命令
只出现文本不能证明卡片渲染失败。卡片验收应使用目标私聊的真实入站消息，或在同一私聊执行
`/agentbridge pending`。

`oa_session_status` 只检查会话，不创建认证卡。`SESSION_CHECK_UNAVAILABLE` 表示保留会话并稍后
重试，不能要求用户重新输入密码。要测试登录卡，应明确请求登录，使模型调用 `oa_session_login`。

宿主耗时通过现有身份认证的 `agentbridge_host_runtime_snapshot` 异步合批记录：

- OpenClaw `2026.7.1` 的 `model_call_started/ended` 在执行器实际发出事件时记录供应方调用耗时和可用的 TTFB；未发出时记为不可用，不能记作零次或伪造 TTFT。隔离实测的 Codex 执行器会发出工具及回合事件，但未发出这两个模型事件。
  没有首 token 钩子，TTFB 不等同于 TTFT。`llm_output` 只提取存在的用量，不把缺失写成零。
- 提示构建、整个工具调用、MCP 完整请求和每次传输分别计时，嵌套阶段不能相加当作总耗时。
  自己测量的 duration 使用单调时钟；宿主原生模型 duration 明确标为墙钟。
- `io.agentbridge/timing` 仅携带可信 request/run/task/tool-call 关联。Workspace 的 `turnRef`
  是 request 标识，不能当作持久 dispatch UUID；同一 run 绑定原始 request，不被新回合覆盖。
  延迟工具工厂没有 `runId` 时，工具计时也使用同一精确调用绑定；绑定冲突时不继承工厂的回合标识。
- 事件只接受有界标识、计数、状态及固定阶段，不读取提示、参数、回复正文、密钥或卡片 URL。
  每身份队列最多 256 个，单批最多 32 个，每秒至多安排一次合批；队列满或上报失败只丢诊断，
  不阻塞业务、重试提交或改变授权、材料、租约和核验状态。

通知领取使用最长 20 秒的异步长轮询，服务端在决定事务提交后唤醒，跨进程每两秒核对持久
outbox。每个等待端点只预留一个队列槽；身份数超过 32 时自动使用最长两秒恢复轮询，避免
空闲连接占满容量。旧服务或传输失败也回到恢复轮询，不反复发送不支持的等待参数。
没有 companion 通知端点时，原交互的 `interaction_get` 也立即进入同一事务后唤醒长轮询；
等待窗口受剩余卡片期限限制，取消或到期不产生额外提交，旧服务仍回退原状态查询。

领取与续办分开：全局最多 32 个已领取/预留通知，默认 4 个跨任务 worker，同一 task 全局
串行，没有 task 的时间线按端点串行。实际处理后才 ack；重复 delivery 不重复排队，已有
resume claim、原协调租约、fencing 版本及稳定幂等键仍决定唯一执行。已完成的决定直接进入
原租约续办，不为执行重新签发展示 URL。`notificationLongPoll=false` 可回退为恢复轮询；
`notificationConcurrency=1` 可单独关闭跨任务并发，允许配置范围为 1—8。

领取租期为 300 秒，覆盖排队和慢续办，满队列暂停领取。超过领取租期的重复投递仍由本地
delivery 去重和中央业务账本保护；进程崩溃后的原交互恢复、业务租约和权威结果核验保留。
租期只影响通知恢复时机，不授予或扩张业务提交权限。

查询结果中已明确选择的 OA 事项通过 `agentbridge.task.wake` 进入原任务准备：Gateway 先兑换
原 Workspace 一次性绑定 grant，再由原宿主获取租约、调用 host-private prepare。该通道只接
task/command/session/endpoint 标识，不接 capability 或业务参数；任务及目标来源由 Central
冻结验证。接口立即返回受理状态，准备与材料读取在有界后台队列执行，所得卡片进入原协调器
状态长轮询。runtime snapshot 中同身份的 pendingCommands 仅用于丢失唤醒后的恢复。

业务助手目录按实际 MCP transport 捕获的身份凭据、端点、目录及权限版本隔离缓存，重复读取
合并，最长 60 秒；版本改变、过期或失败不使用旧目录替代新读。执行 Skill 加载、绑定、资源、
材料和授权继续实时检查。原子 ensure 返回精确且剩余至少 300 秒的 600 秒租约时省一次续租；
业务响应的 taskObservation 仅在 task、全部 operation/interaction 引用、状态和版本精确匹配
时省一次 observe。缺失、短租约或不完整回执均保留原调用。

`toolScope=all` 保持生产通用 agent 的全部业务工具；独立 OA agent 或隔离同题测试可显式选择
`oa_pending` 静态目录。专用 OA agent 可显式开启 `boundSkillToolGuard=true`：加载 OA 待办助手后，
将原 run 限制在对应 single/batch、固定资料/反馈及只读发现/组合预检入口，包含宿主 builtin
工具检查。通用 agent 默认关闭此附加 guard，以保留同一轮的独立任务与原 PLAN_REQUIRED
计划恢复；中央原任务绑定、权限、材料和授权校验不受影响。OpenClaw 2026.7.1 的已核对 hooks
不能动态删改同 run 后续模型工具 schema；本实现不声称做到动态 schema 裁剪。目录缓存可用
`skillCatalogCache=false` 独立回退。生产主 agent 不因隔离模型对照切换 scope 或模型。

2026.7.1 的延迟工具工厂可能由另一注册实例执行，并且不提供 `runId`。插件在同一宿主
owner 内共享精确的 tool-call/session/run 关联，以及 Skill 和样例约束；关联同时核对 MCP
地址、捕获的凭据摘要、身份绑定和 endpoint，客户端及权限画像仍各自读取实时服务。
加载 Skill 必须有该工具调用的可信回合关联，不借用会话最近的入站或 Workspace dispatch。
调用冲突、换身份/凭据、已结束回合均失败关闭；无约束的旧协议原始读取仍可执行。
活跃 Skill/样例限制不按时间静默删除，容量满拒绝新加载；`agent_end` 按精确 session/run
清理，重置会话清理该会话，防止迟到回调复活已结束绑定。工具关联另有五分钟及一千项上限，
丢失关联不会放开已存在的专用范围或样例限制。局部协调器停止可保留其他实例的共享关联，
整 Gateway 停止清理协调状态；Skill/样例约束由精确回合或会话清理，进程退出释放 owner 内存。
